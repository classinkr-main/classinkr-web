# 챗봇 상단 퍼널 개선 설계 (발견·오픈·첫질문)

- 작성일: 2026-06-22
- 상태: 설계 합의 → 구현 계획 대기
- 범위: 챗봇 사용 퍼널의 **상단 2구간(발견·오픈)과 첫질문 전환**. 만족·재사용(C)·상담전환(D)은 로드맵.

## 1. 배경과 문제

공개 사이트의 `FloatingChatbot`은 스트리밍 답변, 동적 시작질문, 후속 추천, 출처, 피드백, 복사, 상담 브리지(채널톡 핸드오프), unresolved 넛지까지 이미 갖췄다. 즉 **질문이 시작된 이후 구간은 탄탄**하다.

약한 곳은 **퍼널 최상단**이다:

- 버튼이 우하단에서 펄스만 할 뿐, 먼저 말을 걸지 않는다(선제 노출 없음).
- 페이지 맥락과 무관하게 전역 고정 시작질문만 노출된다.
- 페이지 CTA·콘텐츠에서 챗봇으로 들어오는 통로가 없다.

목표: **더 많은 방문자가 챗봇을 열고 첫 질문을 보내게** 한다(발견 → 오픈 → 첫질문). 그리고 그 변화를 **숫자로 측정**한다.

## 2. 범위

### 이번 범위 (In scope)
1. 선제 말풍선(미니멀 텍스트 칩) — 보수적 트리거, 세션당 1회.
2. 페이지 맥락 컨피그 — 핵심 페이지별 말풍선·시작질문 카피, 기본값 폴백.
3. 견적·가격 가드레일 — 챗봇은 최종가 단정 금지, 상담 연결로 라우팅.
4. 프로그램적 오픈 — CTA·말풍선이 챗봇을 프리필과 함께 여는 공통 메커니즘.
5. 계측 — 퍼널 이벤트 로깅.

### 이번 범위 밖 (Out of scope — 로드맵)
- **C(만족·재사용)**: 세션 기억·재방문 경험, 답변 품질 추가 손질.
- **D(상담·리드 전환)**: 핸드오프 조건 확대, 리드 캡처, 시연/견적 예약 흐름.
- 단, 견적→상담 라우팅은 §6 가드레일로 이번에 일부 선반영한다.

## 3. 합의된 결정 (Decisions)

| # | 결정 | 선택 |
|---|------|------|
| D1 | 우선 구간 | 상단 퍼널 A+B(발견·오픈·첫질문) |
| D2 | 선제 노출 강도 | 은은한 맥락 말풍선 |
| D3 | 말풍선 모양 | 미니멀 텍스트 칩(가장 은은) |
| D4 | 맥락 정밀도 | 핵심 페이지 개별 카피 + 기본값 폴백 |

## 4. 선제 말풍선

### 모양 (D3)
- 흰 배경 칩 한 줄 + 점 액센트(브랜드그린 `#084734`) + `×` 닫기.
- 우하단 버튼 위쪽에 등장. 그린은 액센트로만, 면은 뉴트럴 흰색. 보더 `1px solid rgba(0,0,0,0.08)`.
- 모션: 은은한 페이드 + 살짝 상승. `prefers-reduced-motion` 존중.

### 트리거 (D5)
- **사이트 누적 관여 체류 시간 ≥ 120초** 가 되는 순간, 현재 보고 있는 eligible 페이지에서 노출.
- 누적 체류는 세션 내 페이지 이동을 가로질러 합산하고, 탭이 숨겨지면(`visibilitychange`) 누적을 멈춘다. 상태는 `sessionStorage`.
- 2분 도달 시점에 비-eligible 페이지(예: hidden 페이지)에 있으면, eligible 페이지로 이동한 첫 순간 노출.

### 빈도·억제
- **세션당 최대 1회.**
- `×`로 닫으면 그 세션 끝까지 다시 뜨지 않는다.
- 사용자가 이미 챗봇을 연 적이 있으면 뜨지 않는다.
- 모든 상태(`shown`/`dismissed`/`openedBefore`/`dwellMs`)는 `sessionStorage` 키로 관리.

### 클릭 동작
- 말풍선 클릭 → 챗봇 열림 + 입력창에 **해당 페이지의 리드 질문을 프리필**(편집 가능, 자동 전송 안 함 — 취향상 비공격적). 열림 소스 `teaser`로 계측.

## 5. 페이지 맥락 컨피그 (D4)

- 신규 `lib/chatbot/page-context.ts`.
- 형태: 라우트 패턴 → `{ teaser: string; starters: string[]; intent?: "demo" | "support" }`.
- 매칭: 가장 구체적인 패턴 우선, 없으면 `default`.
- 초기 시드 키(노출 ON 페이지만):
  - `/` (홈) — 도입·운영 일반.
  - `/product/*` — 전자칠판·녹화·EDB·LMS 등 제품 맥락.
  - `/contact` — 상담 전 사전 정리.
  - `/docs/*` — "이 문서 관련 더 물어보기".
  - `default` — 기존 welcome·starterQuestions 폴백.
- `/pricing`은 D6에 따라 노출하지 않으므로 컨피그 키를 두지 않는다.
- **시작질문 일원화**: 이 컨피그의 `starters`를 기존 `/api/chatbot/recommended-questions` 동적 결과와 병합(페이지 맥락 우선 N개 + 동적 보충). 현재의 전역 고정 시작질문을 페이지화한다.

## 6. 견적·가격 가드레일 (D7) ⚠️

- 챗봇은 **가격 구성·영향 요인만** 설명하고 **최종 견적/구체 숫자는 제시하지 않는다.**
- 가격 구성 설명에서 **OPS는 항목으로 넣지 않는다**(보드 내장이므로 개별 강점으로만 언급). 구성 항목은 **카메라/스탠드·벽걸이, 소프트웨어 연동, 온보딩 범위** 중심.
- 가격/견적 질문의 다음 행동은 **"상담 연결로 맞춤 견적"** — 기존 `ConsultationBridge`/handoff(`intent: "demo"`)를 재사용한다.
- `lib/classin-positioning.ts`의 `answerPrinciples` 가격 원칙을 위 규칙에 맞게 개정(OPS를 견적 항목 목록에서 제거, "최종가 단정 금지" 명문화).
- 회귀 테스트로 "최종가/구체 숫자 단정 금지"와 "상담 라우팅"을 고정.

## 7. 프로그램적 오픈 (D8/D9)

- 가벼운 전역 오픈 메커니즘. 전면 `ChatbotProvider` 리팩터는 하지 않는다.
- 신규 유틸 `lib/chatbot/open-chatbot.ts`: `openChatbot({ prefill?, intent?, source })` → `window` 커스텀 이벤트 `classin:chatbot-open` 디스패치.
- `FloatingChatbot`이 이 이벤트를 구독해 창을 열고 프리필을 적용. 말풍선 클릭도 같은 경로를 쓴다.
- 시범 도입: 제품/요금 안내 영역의 보조 CTA 1~2곳을 `openChatbot(...)`으로 연결(전면 교체 아님).

## 8. 계측 (D9)

- `lib/analytics.ts`의 `EventNames` 유니온에 추가:
  - `chatbot_teaser_shown`
  - `chatbot_teaser_clicked`
  - `chatbot_teaser_dismissed`
  - `chatbot_opened` — param `source = "button" | "teaser" | "cta"`
  - `chatbot_first_question`
- 기존 `trackEvent()` → `/api/track/event` → `client_events` 적재 경로 재사용. 내부 적재는 분석 동의가 있을 때만 발화(기존 프라이버시 정책 유지).
- 이로써 발견 → 오픈 → 첫질문 퍼널을 어드민에서 수치로 확인할 수 있다.

## 9. 코드 변경 계획

- `components/ui/FloatingChatbot.tsx`
  - 이미 1,200줄 이상으로 큰 파일이다. 말풍선·트리거·오픈 로직을 인라인으로 더 붓지 않고 분리한다:
    - `useChatbotTeaser`(또는 `useSiteDwellTeaser`) 훅 — 누적 체류·세션 억제·노출 판정.
    - `ChatbotTeaser` 컴포넌트 — 칩 UI.
    - 커스텀 이벤트 `classin:chatbot-open` 구독 + 프리필 적용.
  - 페이지 맥락(`page-context.ts`)에서 말풍선/시작질문을 읽어 적용.
  - 오픈·말풍선·첫질문 시 계측 이벤트 발화.
- `lib/chatbot/page-context.ts` (신규) — 라우트 컨피그 + 매처.
- `lib/chatbot/open-chatbot.ts` (신규) — 전역 오픈 유틸.
- `lib/classin-positioning.ts` — `answerPrinciples` 가격 원칙 개정(OPS 제외, 최종가 금지), 필요 시 시작질문 구조 정리.
- `lib/analytics.ts` — `EventNames` 추가.
- `lib/chatbot/service.ts` — 가격 답변/CTA의 상담 라우팅 정책 정합(필요 범위에서).
- 보조 CTA 1~2곳(제품/요금 안내 컴포넌트) — `openChatbot(...)` 연결.

## 10. 테스트·검증

- 품질 게이트: `npx eslint app components lib --max-warnings=0` + `npm run build`.
- 단위 테스트(`tests/chatbot/`):
  - 말풍선 트리거: 누적 체류 < 120초면 미노출, ≥ 120초 + eligible + 미억제면 노출, 닫으면 재노출 안 함, 이미 오픈했으면 미노출.
  - 페이지 컨피그 매칭: 구체 패턴 우선, 미매칭 시 default.
  - 가격 가드레일 회귀: 최종가/구체 숫자 단정 금지, OPS 미항목화, 상담 라우팅 유지.

## 11. 열린 항목 (구현 중 확정할 카피·수치)

- 페이지별 말풍선·시작질문 최종 문구(따뜻한 상담원 톤, 이모지 없음, 깊이별 길이 — 기존 챗봇 답변 스타일 기준 준수).
- 누적 체류 트리거의 "관여 시간" 정의를 단순 경과(세션 시작 이후)로 둘지, 탭 가시성 기준 활성 시간으로 둘지 — 기본은 활성 시간 합산.
- 프로그램적 오픈을 시범 연결할 CTA 위치 1~2곳 확정.
