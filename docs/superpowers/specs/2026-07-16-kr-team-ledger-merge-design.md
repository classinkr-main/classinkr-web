# KR Team × 매출 장부 통합 설계

- 날짜: 2026-07-16
- 상태: 설계 승인됨 (목업 Phase A 진행 중)
- 대상: `/admin/branch` (KR Team, `BranchDashboardClient` 399줄) + `/admin/branch/ledger` (매출 장부, `SalesLedgerWorkbench` 6,114줄 + `components/admin/branch/ledger/*` 분리 섹션)

## 배경 / 문제

사이드바에 "KR Team"과 "매출 장부(MVP)"가 나란히 있다. 두 화면은 같은 데이터(매출시트 DSH/REV/KPI 미러 + 장부 초안)를 다루는 형제 화면이다:

- **KR Team** = 소비 뷰. 개요·파이프라인·히트맵·AI 인사이트 4탭, 팀/기간 필터.
- **매출 장부** = 입력·검수 뷰. DSH/REV/KPI 3렌즈, 매트릭스 인라인 편집·TSV 붙여넣기·초안 큐·주간 마감.

같은 도메인이 진입점 2개로 갈라져 사이드바가 혼란스럽고, 겹치는 섹션(회계 로드맵 vs DSH 누적 차트, KPI 아코디언 vs KPI 렌즈)이 두 곳에서 따로 자란다.

## 확정 결정

1. **통합 깊이 = 탭 통합**: 사이드바 1개 항목, `/admin/branch` 공유 레이아웃(헤더+탭바)에 라우트 기반 탭.
2. **스코프 = 겹침 정리 포함**: 단순 IA 묶기가 아니라 중복 섹션을 한 자리로 합친다.
3. **우선순위 규칙**: 비주얼 디자인은 KR Team 우선 / 정보 구조는 매출시트(1.DSH → 2.REV → 3.KPI) 기준 / 기타 탭(히트맵·AI 등)은 KR Team 것 유지.
4. **REV 탭 = 뷰 전환**: [파이프라인(테이블) | 칸반 | 검수 매트릭스] 3지선다 뷰 스위치. 팀·기간·원천 필터 공유. 인라인 편집·TSV·초안 큐·주간 마감은 검수 뷰에서만.
5. **신규 합성 화면은 HTML 목업 먼저**: 기존에 없던 조합(개요+DSH 흡수, REV 뷰 스위치 셸, KPI 통합)은 정적 HTML 목업으로 승인받은 뒤 구현.

## 통합 IA

| 탭 | 라우트 | 내용 | 성격 |
|---|---|---|---|
| 개요 (DSH) | `/admin/branch` | KR Team 개요(KPI 그리드·히어로 게이지·딜믹스·회계 로드맵·다가오는 딜·캠페인·HW) + 장부 DSH 렌즈의 누적 흐름·주차 차트 흡수 | 합성 → 목업 |
| REV | `/admin/branch/rev` | 뷰 스위치 [파이프라인ㅣ칸반ㅣ검수 매트릭스]. 검수 뷰에만 편집 기능 일체 | 합성 셸 → 목업 (뷰 내용물은 기존 재사용) |
| KPI | `/admin/branch/kpi` | 장부 KPI 렌즈(활동 병목·담당자) + KR Team KPI 아코디언 통합 | 합성 → 목업 |
| 히트맵 | `/admin/branch/heatmap` | KR Team 그대로 | 라우트 이동만 |
| AI 인사이트 | `/admin/branch/insights` | KR Team 그대로 (+ 데이터품질 패널·CRM 대사) | 라우트 이동만 |

- 사이드바: `admin-nav.ts`에서 매출 장부 항목 삭제, KR Team 1개만. MVP 배지는 사이드바에서 제거(검수 뷰 내부 표기 여부는 목업에서 결정).
- 구 URL 호환: `/admin/branch/ledger` → `/admin/branch/rev?view=matrix` 리다이렉트.
- 필터 상태(팀·기간·월·원천)는 URL 쿼리로 승격 — 탭 전환에도 유지되고 딥링크 가능.
- 역할(roles)은 현행 유지: 두 화면 모두 `STAFF_ADMIN + BRANCH`였으므로 통합 후에도 동일.
- 데이터 경로·API 변경 없음 (이 작업은 프론트 IA 통합).

## 진행 순서

- **Phase A — 목업**: 탭 전환되는 정적 HTML 1장. 합성 3개 탭(개요·REV·KPI) 중심, KR Team 디자인 토큰(#FAFAF8/#111110/#615D59/#084734, 보더 rgba(0,0,0,0.08)) 사용. → 사용자 검토·수정.
- **Phase B — 구현**: 목업 확정 후 writing-plans로 구현 계획 수립. 공유 레이아웃 + 기존 컴포넌트 재배치, 합성 뷰는 확정 목업대로.

## 리스크 / 주의

- `SalesLedgerWorkbench`(6,114줄)는 라우트 분리로 코드 스플리팅되지만, 내부 state가 거대해 REV 탭 이식 시 필터 공유 배선을 신중히. (구현 단계 이슈 — 목업엔 영향 없음)
- 검수 매트릭스의 확도 색 규약(확정=빨강 계열 토큰, 고확도=파랑)은 `CONFIDENCE_TOKENS` 캐논 유지.
- 겹침 정리로 없어지는 섹션(파이프라인 탭의 KPI 아코디언 등)은 KPI 탭으로 이동이지 삭제가 아님.
