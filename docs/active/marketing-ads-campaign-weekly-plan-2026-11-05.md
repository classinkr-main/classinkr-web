## 0. 한 줄 요약

"지금 무슨 광고가 돌고 있고, 이번 주·지난주 성적이 어떤가"에 답하는 화면이 없다. 운영 중 캠페인 표는 맨 아래 데이터 층에 있고,
캠페인 성과는 네 곳에 흩어져 리드 기준이 세 가지·기간 토글이 두 개다. 주간 보고서는 직전 한 주만, Meta만 보여 주고 지난 주를 넘겨 볼 수 없다.

허브에 **"광고" 탭**을 하나 만들어 ① **운영 중 광고**(채널 통합, 이번 주 성적) ② **캠페인 분석**(한 표·한 기간·드릴다운) ③ **주간 분석**(월~일 주 넘기기 · 8주 추이 · 캠페인×주)을 모은다.
기간 토글에 **"주(월~일)"** 모드를 더해 허브 전체가 같은 주를 보게 한다. 리드 단위 콜·소재 월별 이력은 지금처럼 Compass에 두고 딥링크한다.

## 1. 현황 진단 (코드·데이터 근거)

### 1.1 광고 데이터 원천

| 원천 | 단위 | 지표 | 적재 | 지금 |
| --- | --- | --- | --- | --- |
| `meta_insights_daily` | 캠페인 × 일 | 광고비(USD)·노출·도달·클릭·CTR·CPC·CPM·리드(Meta 집계) | 매일 크론, 최근 3일 재적재 | 가동. **상태·광고세트·소재 없음** |
| `google_ads_daily` | 캠페인 × 일 | 광고비(KRW)·노출·클릭·전환 | 매일 크론, 최근 7일 | 11/3 환경변수 설정 → 행이 쌓이기 시작. **상태 없음** |
| `naver_ads_daily` | 캠페인 × 일 | 광고비(KRW, VAT 별도)·노출·클릭·전환 | 매일 크론 | 자격증명 미설정(활성화 대기) |
| Compass `compass_ads_v`·`compass_adsets_v` | Meta 소재·광고세트 × 일 | 광고비(USD)·리드·클릭·노출·소재 썸네일 | Compass 앱이 적재, 읽기 전용 | 브리지가 살아 있을 때. 상태 없음 |
| Meta Graph 라이브(`/api/admin/meta/campaigns`) | 캠페인 | 상태·effective_status·예산·기간 + 선택 기간 인사이트 | 요청마다(45초 메모) | **상위 50개, 페이지 넘김 없음**. 광고세트·소재 호출 없음 |
| 채널 예산·행사 광고비 | 채널·행사 | KRW 수기 금액 | 수기 | **날짜 없음**(누적) |

- "운영 중" 판정은 Meta 라이브 호출의 `effective_status === ACTIVE` 하나뿐이다(`lib/marketing/meta-campaign-view.ts`). Google·네이버는 상태를 가져오지 않는다.
- 리드(`public.leads`)에는 광고·광고세트·캠페인 **id 컬럼이 없다** — Meta 리드는 `utm_campaign/term/content`에 **이름**만 남는다. 캠페인별 연락·전환은 이름 매칭으로만 셀 수 있다.
- 캠페인별 연락·전환 결과는 화면에 없다 — perf 퍼널의 연락·전환은 계정 전체 합이다.

### 1.2 화면이 흩어져 있다

| 위치 | 보여 주는 것 | 리드 기준 | 기간 |
| --- | --- | --- | --- |
| 한눈에 › Top 3 | 우산 캠페인 3개 | Meta 리포트 리드(연결 캠페인) | 허브 기간 |
| 상세 › 캠페인 | 우산 캠페인 스코어보드 + Meta 라이브 차트 | 스코어보드 = Meta 리포트(스냅샷) / 차트 = Meta 라이브 | **두 토글**(허브 기간 · Meta date_preset) |
| 상세 › 소재 | 소재·광고세트 CPL | Compass(Meta 리포트) | 허브 기간 |
| 데이터 › Meta 캠페인 | 운영 중/멈춤 표 + 재개·중지 | Meta 라이브 | Meta date_preset |
| 데이터 › Google Ads | 계정 구조·계획(정적) + API 실적 자리 | — | — |

"돌고 있는 광고"를 보려면 데이터 층 맨 아래까지 내려가야 하고, 같은 캠페인의 리드가 위치마다 다르게 보인다(각 카드 각주가 이유를 밝히지만 한 화면에서 비교할 수 없다).

### 1.3 주간 분석의 한계

- 주간 보고서(`lib/marketing/weekly-report*.ts`)는 **직전 완료 월~일 한 주**만 만든다. 월 09:20 크론이 `marketing_insights`에 매주 저장하지만 **지난 주를 고르는 API·화면이 없다**(최신 1건만 읽음).
- 범위는 Meta + CRM이다 — Google·네이버 광고비, 홈페이지 문의는 빠진다. 위치는 데이터 층 맨 끝(+ 헤더 버튼).
- perf API는 `7d·30d·90d·이번 달·분기`의 굴러가는 창만 받는다. **특정 월~일 주를 요청할 수 없고, 여러 주 추이(예: 8주)도 없다.**
- WeCom 주간 리드 다이제스트(목 13:00)는 같은 월~일 주로 전 소스 리드를 보내지만 광고비가 없고 다시 볼 곳이 없다.

### 1.4 Compass와의 경계(유지)

Compass `/dashboard`(Meta 파이프라인)·`/ads`(캠페인·소재 월별 집행 이력)·`/leads`(콜·케어)는 다시 만들지 않는다.
어드민이 맡을 것은 **채널 통합(Meta USD · Google·네이버 KRW를 나란히)**, **전 소스 리드와 CRM 결과(연락·전환)**, **월~일 주 단위 운영 리듬**이다.

## 2. 목표와 원칙

**목표**: 마케팅 담당자가 월요일 아침 한 화면에서 ① 지금 돌고 있는 광고와 이번 주 성적 ② 캠페인별 비교 ③ 지난 몇 주의 흐름을 본다.

1. **한 탭, 한 기간** — 광고 관련 성과는 "광고" 탭에 모으고, 그 탭 안에서는 기간 토글 하나만 쓴다(Meta date_preset 토글 제거).
2. **주는 월~일(KST)** — 기존 주간 보고서·WeCom 다이제스트와 같은 경계. 진행 중인 주는 "진행 중(월~오늘)"으로 표시하고 완료 주와 섞어 비교하지 않는다.
3. **리드 기준을 열로 가른다** — "플랫폼이 센 리드(Meta·Google 보고)"와 "우리 DB 리드(연락·전환까지)"를 같은 표의 다른 열 묶음으로 둔다. 한 숫자로 합치지 않는다.
4. **정직 규칙 계승** — USD·KRW 분리, 채널을 가로지르는 ROAS·ROI 없음, null ≠ 0, 원천이 끊기면 그 칸만 "확인 필요/미집계", 운영 중 판정 기준을 화면에 밝힌다.
5. **쓰기는 데이터 층에서만** — 재개·중지 같은 쓰기는 지금처럼 데이터 › Meta 캠페인에 두고, 광고 탭은 링크한다.

## 3. 제안 — "광고" 탭

탭: **한눈에 · 광고 · 상세 · 데이터 · 메시지**. 광고 탭 섹션: **운영 중 · 캠페인 · 주간**. 상세에는 퍼널·채널 · 행사 · 메시지 성과가 남는다.

### 3.1 운영 중 광고

```
기간 [7일 | 30일 | 이번 달 | 주(월~일) ◀ 11/2~11/8 진행 중 ▶]                      (탭 공통 토글)
┌ 운영 중 광고 ─────────────────────────────────────────────────────────────┐
│ 운영 중 4개  Meta 3 · Google 1 · 네이버 연동 대기    이번 주 광고비 $412 · ₩186,000 │
│ 이번 주 광고 리드 38 (지난주 같은 요일까지 31)   CPL $10.8   연락 61% · 전환 2      │
├──────┬──────────────────┬──────┬───────┬────────┬──────────┬──────────────┬─────┤
│ 채널 │ 캠페인 (우산)     │ 상태 │ 시작   │ 이번 주 │ 플랫폼 리드│ 우리 DB 리드  │ 추이 │
│      │                  │      │       │ 광고비  │ · CPL     │ 연락 · 전환   │ 7일  │
│ Meta │ 겨울특강_리드폼   │ 집행 │ 10/14 │ $188   │ 19 · $9.9 │ 17 · 59% · 1  │ ▁▃▅ │
│ ▸ 광고세트·소재 펼치기(Compass, USD) — 소재 썸네일·CPL Top 3, "Compass에서 이력"        │
│ Google│ 브랜드 검색      │ 노출 │ 10/02 │ ₩86,000│ 전환 4    │ 홈페이지 문의 6│ ▂▂▃ │
└──────┴──────────────────┴──────┴───────┴────────┴──────────┴──────────────┴─────┘
  멈췄지만 이번 주 지출 있음 2개 · $96 · 리드 7  ▸ 펼치기          재개·중지 → 데이터 › Meta 캠페인
```

- **행** = 지금 운영 중인 플랫폼 캠페인(채널 통합). 우산 캠페인에 연결돼 있으면 이름 옆에 우산 이름.
- **운영 중 판정**: Meta = `effective_status ACTIVE`(라이브). Google·네이버 = 상태를 아직 안 가져오므로 **"어제 노출 있음"**을 대리 지표로 쓰고 상태 칸에 "노출"로 표시(§5 P1에서 상태 조회로 교체).
- **이번 주 열**: 선택한 주(기본 = 진행 중인 주, 월~오늘)의 광고비·플랫폼 리드·CPL과 **지난주 같은 요일까지** 대비. 통화는 행의 채널 통화 그대로.
- **우리 DB 리드 열**: 그 캠페인 이름으로 들어온 리드 수 · 연락률 · 전환(이름 매칭 — 열 머리에 "이름 기준" 표시). Google은 캠페인 귀속이 없어 같은 주 "홈페이지 문의(구글 유입)"만 보조로 둔다.
- **이상 신호**: 기존 `lib/marketing/anomaly.ts`(CPL 급등·리드 0·과속 집행)를 행 끝 점 하나 + 툴팁으로.
- **펼치기**: Meta 행은 광고세트·소재 Top 3(Compass, USD, 썸네일) + "Compass에서 이력 보기". 기존 `CreativeCplCard`·`AdsetPerfCard` 집계를 캠페인 필터로 재사용.
- **멈춘 캠페인 접힘**: 기존 정직 규칙 그대로 — 멈췄어도 기간 안에 쓴 돈·리드를 접힘 머리말에 합계로 밝힌다.

### 3.2 캠페인 분석

- **한 표**: 우산 캠페인을 묶음 행, 그 아래 연결된 플랫폼 캠페인(Meta·Google·네이버)을 자식 행으로. 우산이 없는 플랫폼 캠페인은 "연결 안 됨" 묶음.
- **열 묶음**: 집행(광고비·노출·클릭·CTR) | 플랫폼 리드(리드·CPL) | 우리 DB(리드·연락률·전환) | 진행(페이싱·기간) | 이상.
- **필터**: 운영 중만 / 전체 · 채널 · 우산 캠페인. 정렬: 광고비·리드·CPL·전환.
- **기간**: 탭 공통 토글(주 모드 포함). 상세의 "Meta date_preset" 토글은 없앤다 — Meta 라이브 차트는 같은 기간으로 매핑하거나 스냅샷(`meta_insights_daily`)으로 그린다.
- **드릴다운**: 캠페인 → 광고세트 → 소재(Compass). 소재 월별 이력은 Compass `/ads`로 링크.
- **CRM 결과**: 캠페인별 연락·전환은 지금 이름 매칭(`aggregateAdCreativePerf` 확장 — 연락 수 추가). §5 P2에서 리드에 광고 id를 저장해 정확도를 올린다.
- ROAS·전환당 비용은 두지 않는다(계약 금액 롤업은 대시보드 설계 백로그 그대로).

### 3.3 주간 분석 (월~일)

```
◀  10/26(월) ~ 11/1(일)  ▶   [진행 중 주로]                  확정 · 11/2 09:20 저장본 · 복사 · Markdown
┌ 이 주 요약 ─────────────────────────────────────────────────────────┐
│ 광고비 Meta $1,204 (−8%) · Google ₩412,000 · 네이버 —   광고 리드 92 (+12%) │
│ 전 소스 문의 131 · CPL $13.1 (−18%) · 연락 64% · 전환 5                     │
│ 요일 리듬(월~일) ▃▅▆▅▃▂▁   지금 처리할 일 3 · 캠페인 Top 3                   │
└─────────────────────────────────────────────────────────────────────┘
┌ 8주 추이 (완료 주만) ───────────────────────────────────────────────┐
│            9/7  9/14 9/21 9/28 10/5 10/12 10/19 10/26                       │
│ Meta $     ...                                                    ▁▃▅▆      │
│ Google ₩   ...                                                              │
│ 광고 리드   ...                                                             │
│ 전 소스 문의 ...                                                            │
│ CPL $      ...                                                              │
│ 연락률·전환 ...                                                             │
└─────────────────────────────────────────────────────────────────────┘
┌ 캠페인 × 주 (리드, 완료 8주) ─ 숫자 + 옅은 막대 ──────────────────────┐
```

- **주 넘기기**: ◀ ▶ 로 완료 주를 오가고, "진행 중 주로" 버튼. 진행 중인 주는 "진행 중(월~오늘)" 배지 + 비교는 "지난주 같은 요일까지".
- **이 주 요약**: 기존 주간 보고서 내용(KPI·퍼널·요일 리듬·처리할 일·캠페인 Top)을 그대로 쓰되 범위를 넓힌다 — Google·네이버 광고비(KRW 별도), 홈페이지 문의, 전 소스 문의. 저장본이 있으면 저장본, 없으면 다시 계산하고 "다시 계산"이라고 밝힌다.
- **8주 추이**: 행 = 지표, 열 = 완료 8주. 행 끝에 스파크라인. 표로 보기 기본, 차트는 지표 하나를 고르면 그 줄만.
- **캠페인 × 주**: 행 = 캠페인(운영 중 + 최근 8주에 지출 있던 것), 열 = 8주, 값 = 우리 DB 리드(셀 배경은 같은 행 안의 상대 크기로 옅게). 광고비로 바꿔 보기 토글.
- **데이터 › 주간 보고서** 섹션은 이 화면으로 옮기고 옛 딥링크(`?tab=data#weekly`)는 `?tab=ads#weekly`로 착지시킨다. 헤더의 "주간 보고서" 버튼도 이 섹션을 연다.

### 3.4 한눈에·다른 화면과의 연결

- 한눈에 판정 줄에 "운영 중 광고 N개" 칩 → 광고 › 운영 중.
- 한눈에 Top 3 캠페인 "전체 보기" → 광고 › 캠페인.
- Overview "지금" 띠의 "오늘 문의" 소스 분해와 광고 탭의 리드 숫자는 같은 정의(전 소스·이름 매칭 축을 섞지 않음)를 쓴다.

## 4. API·데이터 계획

| 작업 | 내용 | 위치 |
| --- | --- | --- |
| 주 기간 | `PerfPeriodKey`에 `week` 추가, `?period=week&week=YYYY-MM-DD(월요일)`. since=월·until=일(진행 중이면 오늘), prev = 직전 월~일(진행 중이면 같은 요일까지). 캐시 키에 week 포함. `assembleMarketingPerf`의 `today` 고정 경로를 재사용 | `lib/marketing/perf.ts`, `perf-assemble.ts`, `app/api/admin/marketing/perf/route.ts` |
| 주 헬퍼 | `lib/marketing/week.ts` — KST 월요일 계산·주 목록·일→주 버킷(순수, 테스트). 기존 `resolveLastCompletedMarketingWeek`도 여기로 | 신규 |
| 주간 추이 | `GET /api/admin/marketing/weekly-trend?weeks=8` — `meta_insights_daily`·`google_ads_daily`·`naver_ads_daily`·leads를 주로 버킷. 원천별 상태(미설정·실패) 동봉. 5분 캐시 | 신규 |
| 캠페인×주 | 같은 라우트의 `byCampaign`(캠페인 × 8주 리드·광고비) | 신규 |
| 주간 보고서 | `?week=` 지원 + 저장본 목록(`marketing_insights` scope `weekly_report` 최근 N). 보고서 v4: Google·네이버 광고비(KRW), 홈페이지·전 소스 문의 추가 | `weekly-report*.ts`, `lib/repositories/marketing-insights.ts` |
| 운영 중 보드 | `GET /api/admin/marketing/running?week=` — Meta 라이브(페이지 넘김 추가) + 일별 테이블의 이번 주·지난주 같은 요일까지 + 우산 연결 + 리드 이름 매칭(연락·전환) | 신규, `lib/meta/marketing.ts` |
| 소재 드릴다운 | `/api/admin/compass/ads·adsets`에 `campaign=` 필터 | 기존 라우트 확장 |

데이터 보강(결정 후, §6 D4·D5):

- **P1** Google·네이버 캠페인 상태 조회(GAQL `campaign.status` · 네이버 응답의 `status` 보존) → "노출" 대리 지표를 실제 상태로 교체.
- **P1** Meta Graph `/campaigns` 페이지 넘김(지금 상위 50개).
- **P2** 리드에 Meta `campaign_id·adset_id·ad_id` 저장(리드폼 웹훅 페이로드에 이미 있음 — 마이그레이션 1건, 앞으로 들어오는 리드부터). 캠페인별 연락·전환을 이름이 아닌 id로 센다.

## 5. 실행 순서

| 단계 | 내용 | 분량 | 파트 |
| --- | --- | --- | --- |
| W0 | 광고 탭 껍데기 + 상세 › 캠페인·소재 이동, 데이터 › Meta 운영 중 표를 읽기 전용으로 운영 중 섹션에, 탭 안 기간 토글 하나(Meta date_preset 제거), 레거시 딥링크 매핑 | 1일 | 그로스·CRM |
| W1 | 주 기간(`period=week`) + 주 넘기기 UI(허브 공통 토글), 주간 보고서 `?week=`·저장본 목록, 주간 섹션 이동 | 2일 | 그로스·CRM |
| W2 | weekly-trend API + 8주 추이 표·스파크라인 + 캠페인×주 | 2~3일 | 그로스·CRM |
| W3 | 운영 중 보드(채널 통합·이번 주·지난주 같은 요일 대비·이름 매칭 연락·전환·펼치기 소재) | 2~3일 | 그로스·CRM |
| W4 | 데이터 보강 P1(상태 조회·페이지 넘김) → P2(리드 광고 id 저장, 마이그레이션) | 결정 후 | 그로스·CRM + 플랫폼(마이그레이션) |

파일 소유권: `components/admin/campaigns/**`·`lib/marketing/**`·광고 라우트는 그로스·CRM, 마이그레이션은 플랫폼 파트([플레이북](playbook/README.md)).

## 7. 완료 기준

- 월요일 아침 한 화면(광고 탭)에서 운영 중 광고·직전 주 요약·8주 추이를 스크롤 두 번 안에 본다(1440).
- 같은 주·같은 캠페인의 숫자가 광고 탭·주간 보고서·WeCom 주간 다이제스트에서 같다(리드는 같은 정의, 광고비는 같은 원천).
- 진행 중인 주는 완료 주와 같은 줄에서 비교하지 않는다. 원천이 끊긴 칸은 "확인 필요"이지 0이 아니다.
- USD·KRW를 합한 숫자가 화면 어디에도 없다.
- 옛 딥링크(`?tab=detail#campaigns`·`#creatives`, `?tab=data#weekly`)가 새 위치로 착지한다.
- 기본 품질 게이트 + `npx vitest run tests/campaigns tests/marketing`.
