## 기존 버전 진단

기존 브랜드 PT(21장)는 **"우리가 무엇을 만드는가"** 순서로 짜인 기능 소개 덱이다. 비전 → 연혁 → 원칙 3가지(환경·콘텐츠·데이터 표준화) → 하드웨어 → 칠판·도구 → 클라우드 → 녹화 → LMS → API → 세 사람 → 파트너 사진 → 감사.

| 살릴 것 | 바꿀 것 |
| --- | --- |
| **BEFORE/AFTER 실제 교실 사진**(가림 · 케이블 · 파편화) — 불편함을 가장 빨리 공감시키는 장 | 기능이 13장 연속 나열됨 → 청중이 "그래서 우리 학원에 뭐가 좋은데?"를 끝까지 들고 있음 |
| **세 가지 표준화(환경 · 콘텐츠 · 데이터)** — 생태계를 설명하는 뼈대로 그대로 씀 | 돈 이야기가 없음. 세 사람 장의 "피드백 작성 시간 70% 감소"는 출처가 없음 |
| **녹화 자동화 Before/After 흐름도**(로컬 녹화 → 수동 업로드 → 누락 vs 수업 종료 → 자동 녹화 → 다시보기) | "기술로 교육을 변혁" · "폭발적 성장" 톤이 강해 변화가 크게 느껴짐 |
| **국내 파트너 교실 사진**(과사람 · 정율사관 · 예림 · 이미숙국어) — "평범한 교실에 칠판만 바뀌었다"는 증거로 재배치 | 장마다 디자인 계열이 다름(검정 · 베이지 · 흰 바탕 초록 바 · 컬러 카드) → 한 톤으로 통일 |
| 회사 규모 · 한국 지역별 핵심 고객사 | 연혁 수치 일부가 회사 팩트 정본과 다름(아래 [고칠 사실](#기존-덱에서-고칠-사실)) |

**한 줄 차이**: 기존 덱은 "클래스인은 이런 걸 만듭니다", 새 덱은 **"원장님 학원에서 이게 이렇게 사라지고, 이만큼 남습니다"**.

## 한 문장 스토리

> 원장님 학원의 수업은 이미 좋습니다. 그동안 손이 갔던 건 수업 밖, 가리고 꼬이고 흩어지는 것들이었습니다.
> 클래스인은 수업 방식을 바꾸지 않고, 환경 · 콘텐츠 · 데이터를 한 플랫폼에서 하나로 맞춥니다.
> 이미 많은 학원이 칠판 하나 바꾸는 것으로 시작했습니다.
> 이어지면 강사의 시간과 떠날 뻔한 학생이 돌아오고, 그건 우리 학원 숫자로 계산됩니다.

## 설계 원칙

1. **존중으로 시작**: "수업은 이미 좋다, 불편은 필연적이었다." 원장님 탓이 아니라는 데서 출발한다(기존 BEFORE 장의 '필연적' 카피를 살림).
2. **불편 → 해소를 짝지음**: 1막 BEFORE 사진의 불편 세 가지가 2막 세 가지 표준화와 하나씩 짝을 이루고, 2막 끝 AFTER 사진에서 같은 구도로 닫힌다.
3. **'그대로' 표시**: 바뀌지 않는 것(판서 방식 · 교재 · 교실 · 시간표 · 결제/출결 프로그램)에 같은 표시를 붙이고 4막에서 모은다.
4. **복선과 회수**: 1막 끝 "이 사이를 잇는 데 매달 얼마? ?" → 5막 계산으로 채움.
5. **약속하지 않고 계산하게 함**: 절감·재등록을 보장하지 않는다. 가정값은 화면에 밝히고 계산기에 우리 학원 숫자를 넣게 한다. 가격은 말하지 않는다(포지셔닝 §6).

## 결정이 필요한 것

1. **청중과 자리**: 원장 대상 세미나인지, 영업 미팅·쇼룸용인지. AI 강의평가 세미나와 같은 자리라면 19장 AI 스위치를 짧게 둔다.
2. **분량**: 기본 24장 · 약 20분. 영업용이면 14장 안팎 압축본.
3. **고객사 노출**: 지역별 고객사 이름과 파트너 교실 사진을 공개 발표에 써도 되는지.
4. **21장 예시 가정값**: 반복 업무 시간·시간당 비용에 쓸 사내 실측값이나 고객 사례가 있는지.
5. **기존 장 중 꼭 살려야 할 것**: 이 안에서 빠진 장(독립된 API 장, 연속 프레젠테이션 손동작 장)을 따로 살릴지.
