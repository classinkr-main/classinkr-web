# 캠페인·마케팅 어드민 — 디벨롭 & 정리 분석 (레퍼런스 대조)

- 상태: **분석·가안** (코드 변경 없음, 적용 미착수). 업로드 레퍼런스 목업을 우리 현실에 대조해 "무엇을 정리하고 무엇을 디벨롭할지" 정리한 문서.
- 대상: `/admin/campaigns` + 흩어진 마케팅/그로스 라우트 전반
- 관련 파트: 마케팅/그로스/CRM (`growth-crm`)

## 0. 레퍼런스 성격 (먼저 짚을 것)

업로드된 자료는 "Marketing Campaign Suite" 인터랙티브 목업이다.

- **비주얼은 참고 대상 아님.** Modernist 디자인 시스템(플랫 레드 #ec3013 · Archivo · 0 radius · 2px 룰)으로, 우리 [DESIGN.md](DESIGN.md)(그린 #084734 액센트 · 뉴트럴 넓은 면 · 둥근 에디토리얼)와 정면 충돌한다. **채택하는 것은 정보구조(IA)와 기능 범위뿐**, 스타일은 우리 시스템을 유지한다.
- **데이터는 전부 더미.** 목업 안 7개 캠페인·6개 채널·프로젝트·ROAS 412% 등은 하드코딩. 우리 실측(§2)과 다르므로 숫자는 무시하고 "화면 구성이 제안하는 관점"만 읽는다.
- **핵심 제안 = 단일 마케팅 워크스페이스.** 좌측 사이드바 7개 섹션 + 상단 검색 + `새 메시지`/`새 캠페인` 글로벌 버튼 + 캠페인 상세 모달 + 메시지 작성 모달.

## 2. 현재 상태 (실측, 2026-07-23)

### 2.1 IA — 단일 워크스페이스 아님, 라우트 분산
마케팅/그로스 표면이 여러 top-level 라우트로 흩어져 있다: `/admin/campaigns`, `/admin/crm`(자체 하위탭), `/admin/events`, `/admin/lead-magnets`, `/admin/analytics`, `/admin/traffic`, `/admin/calendar`, `/admin/branch`. 유일한 통합 사례: 구 `/admin/marketing`(메시지 허브)가 `campaigns?tab=email` 탭으로 흡수됨(현재 redirect 스텁).

### 2.2 `/admin/campaigns` — 4개 탭
| id | 라벨 | 내용 | 데이터 |
|----|------|------|--------|
| summary | 요약 | ChannelHubCards, MetaLiveSummary, KPI 6종, InsightsBanner, TimelineRow, MiniFunnel, GoalProgressPanel, 5종 차트, TopPerformersTable | 실데이터(단, 경제지표는 수기 입력 event-metrics 기반) |
| events | 행사 | 리스트/갤러리 토글, 검색/필터/정렬, EventDetailModal, MetricsEditor | `public_events`(Supabase) + `event-metrics.json`(파일) |
| meta | Meta 광고 | MetaCampaignPanel(계정·캠페인 표·재생/정지 쓰기), MetaPerformanceCharts | **Meta Graph API 라이브** |
| email | 메시지 | MarketingHub(구 /admin/marketing 전체) | 이메일 대량=라이브, SMS/카카오=테스트만 |

### 2.3 데이터 real vs 미구현
| 항목 | 판정 |
|------|------|
| Meta 광고(`/api/admin/meta/*`) | ✅ Graph API 라이브(읽기+상태쓰기), Instagram도 |
| 이메일 대량 발송 | ✅ 라이브(Resend, `email_campaigns` 기록, 오픈 픽셀) |
| **SMS/카카오 대량 발송** | ⚠️ **미구현** — solapi 클라이언트·로깅은 실재하나 UI/API는 1건 테스트 발송만. UI에 "대량 발송 백엔드 준비 중" 명시 |
| 구독자·리드 | ✅ 라이브(Supabase 강제/시트 스파인) |
| **자동화(automation)** | ⚠️ **엔진 라이브·UI 언마운트** — `lib/automation-engine.ts` + 일 1회 크론 + on-submit 트리거 + 풀 CRUD API 전부 실재. 그러나 campaigns→메시지→자동화 탭은 "설계 진행 중" **플레이스홀더**만 렌더. 규칙/템플릿 UI 컴포넌트 6개가 **어디서도 import 안 됨(죽은 UI)** |
| 캠페인 트렌드/채널효율/ROI/목표 | ⚠️ 실데이터지만 **수기 입력 event-metrics** 기반. 채널별 리드는 광고비 비례 **추정**(UI에 caveat 명시) |
| **통합 캠페인 개체** | ❌ **없음** — 크로스채널 `campaigns` 테이블 없음. "캠페인"은 오늘 (a)이메일 발송=`email_campaigns`(이메일만) (b)Meta 광고캠페인(API, 로컬 미저장) (c)`public_events`뿐 |
| 클릭 추적 | ❌ 이메일은 **오픈만** 추적(클릭 없음). SMS/카카오는 sent/failed 상태만 |
| event-metrics 저장 | ⚠️ `data/event-metrics.json` 파일(Supabase 마이그 전) |

## 4. 정리(Reorganize) 권고 — 구조·IA, 낮은 리스크

레퍼런스가 일깨우는 가장 값싼 개선은 "새 기능"이 아니라 **이미 만든 것을 제자리에 놓는 것**이다.

- **R1. 죽어있는 자동화 UI 마운트/정리.** ✅ **해소(2026-08-18 확인).** 6개 컴포넌트 전원이
  `tabs/AutomationTab.tsx`에 연결돼 메시지 탭 자동화 자리에 라이브로 마운트돼 있다.
  단 SendCenter 리팩터로 구세대 컴포저 4개(`EmailComposer`·`ChannelStatusStrip`·
  `AiCampaignComposer`·`LeadSegmentView`)가 새 고아가 됐고, 같은 날 삭제했다(import 0건 확인).
- **R2. 메시지 탭 정직화 일관성 유지.** SMS/카카오 "대량 발송 준비 중" 게이트는 이미 정직하게 라벨돼 있음 — 레퍼런스처럼 "발송 목록+오픈/클릭률" 통합 테이블을 추가할 때도 미구현 채널을 실제처럼 보이게 만들지 말 것.
- **R3. campaigns 탭 라벨·범위 정합.** 레퍼런스의 "캠페인 관리 / 광고 관리 / 메시지 발송" 3분할 관점으로 현재 4탭(요약/행사/Meta/메시지)의 명칭·경계를 재검토(예: `meta`→"광고", 통합 캠페인 목록 도입 시 `summary`와 역할 분리).
- **R4. 흩어진 라우트의 "마케팅 워크스페이스" 관점 부여.** 물리적 통합(대공사)까진 아니어도, 사이드바 마케팅 그룹(campaigns/blog/lead-magnets/events/analytics/traffic)이 하나의 워크스페이스로 읽히도록 그룹 헤더·상호 딥링크 정리.

## 5. 디벨롭(Develop) 권고 — 신규·확장, 중간~큰 리스크

- **D1. 크로스채널 "캠페인" 1급 개체 (★ 근본).** 오늘 "캠페인"은 이메일/Meta/행사로 파편화. 레퍼런스의 통합 캠페인 목록을 실현하려면 `campaigns` 테이블(채널·기간·예산·상태·담당자·목표)이 필요. 이게 있어야 §1-②(통합 목록)·⑥(프로젝트)·⑦(예산리포트)이 전부 성립. **가장 큰 레버이자 가장 큰 공사.**
- **D2. 예산·성과(ROAS) 크로스채널 리포트.** 레퍼런스 §7의 채널별 배정/집행/잔여/전환/ROAS 표. 부분 재료는 있음(Meta 라이브 스펜드 + 수기 event-metrics 광고비). 단, **매출이 "입력 기준"이라 진짜 ROAS는 장부 연동 전까진 불완전** — 이 한계를 UI에 유지하며 "집행/전환"부터 신뢰 구축.
- **D3. 프로젝트(캠페인 묶음).** §1-⑥. D1 이후에 얹는 상위 그룹(프로젝트=캠페인+광고+행사 묶음·공유예산·소진%). 우리 CRM/branch에 이미 "프로젝트/딜 묶음" 사고가 있어 접목 여지 있음.
- **D4. 메시지 통합 발송 목록 + 클릭 추적.** §1-④. 이메일 오픈만 있는 현 상태에 클릭 추적 추가 + 채널 통합 리스트. **단 SMS/카카오 대량 발송(백엔드)이 선행**돼야 "발송" 목록이 의미 있음.
- **D5. 광고 관리 확장(선택).** Meta 외 매체는 API 통합 비용이 큼 — 당장은 "수기 채널 + Meta 라이브" 유지가 현실적. 레퍼런스의 소재 카드(노출/클릭/CTR/소진 바) UI는 Meta 데이터로 먼저 차용 가능.
