## 0. 용어 정리 — "매출시트 탭"은 입력 표면이 아니다

현재 어드민에는 이름이 비슷한 두 화면이 있고, 이 혼동 자체가 입력 동선의 첫 번째 비용이다.

| 화면 | 경로 | 역할 |
| --- | --- | --- |
| 매출시트 | `/admin/crm/deals/rev-sheet` | REV 원장 **읽기 전용** 검수·매칭 상태 표면 (금액 입력 없음) |
| 매출 장부 | `/admin/branch/ledger` | 수치 **입력·검수·마감** 작업면 (이 기획의 대상) |

금액을 타이핑할 수 있는 곳은 매출 장부 하나다. 매출시트에서 검수하다 입력이 필요해지면 사이드바로
나가 매출 장부를 다시 찾아 들어가야 한다.

→ **P2-10**(아래)에서 매출시트 행에 "장부에서 입력 ↗" 딥링크(해당 고객·월로 바로 진입)를 붙여
이 왕복을 없앤다. 두 화면의 역할 분리(CRM-1 결정)는 그대로 둔다.

입력 UX는 이미 여러 라운드를 거쳤다. 아래는 **구현되어 있으므로 이 기획의 항목이 아니다.**

  방향키 이동, Esc 취소, Ctrl+D 위 값 복사, E/H/C 확도 전환, 단축키 치트시트 상시 노출

- 엑셀 TSV 붙여넣기 + 적용 전 프리뷰 다이얼로그(잠금·무변경·비숫자 분류, 최대 600칸)

- 주차(W1~W5) 분해 입력 그리드 + 주차별 확도 기록, 월 합계 자동 계산

- 확정/장부반영 셀 잠금과 저장 전 사전 검사, 낙관적 잠금 충돌 안내
- 체크 큐 일괄 체크·일괄 적용 버튼(2026-09-14), 적용 되돌리기(entries 상쇄)
- 담당자 datalist 추천, 담당자 핀("내 딜" 스코프), 행 밀도 저장
- 서버 저장 실패 시 로컬 임시 초안 폴백과 그 사실의 명시적 표시

## 2. 진단 — 그런데도 입력이 느린 이유

단축키가 모자라서가 아니라 **저장 경로의 구조** 때문이다. 근거는 코드다.

### 2.1 셀 1건 = 네트워크 왕복 1건, 배치 경로 없음

초안 API는 단건 전용이다(`POST /api/admin/branch/ledger-drafts`, `PATCH .../[id]`). 그래서:

- 붙여넣기 커밋은 셀 수만큼 요청을 동시에 던진다 — 최대 600건 동시
  ([SalesLedgerWorkbench.tsx:2027](../../components/admin/branch/SalesLedgerWorkbench.tsx))
- 일괄 체크·일괄 적용은 `for` 루프로 **건당 1 PATCH를 순차** 전송
  ([useLedgerDraftQueue.ts:500, :536](../../components/admin/branch/ledger/useLedgerDraftQueue.ts))

100건을 입력하고 반영하면 대략 `100(생성) + 100(체크) + 100(적용) = 300 왕복`이고, 뒤 200건은
순차라 사용자가 진행 막대를 보며 기다린다. 버튼을 모아준 것은 클릭 수만 줄였을 뿐 대기 시간은 그대로다.

### 2.2 장부에 반영되기까지 3단

입력 → 체크 → 적용. 2단 게이트는 감사 추적을 위한 정본 규약이고 폐기 대상이 아니다. 다만 **입력자와
체크자가 같은 사람인 일상 입력**에서도 큐로 이동해 같은 건을 다시 훑게 만든다. 매트릭스에서 30칸을
친 사람은 그 30칸을 큐에서 한 번 더 본다.

### 2.3 고객명이 자유 텍스트

담당자는 오탈자가 집계를 조용히 쪼갠다는 이유로 datalist 추천이 붙어 있는데
([InputRailSection.tsx:218](../../components/admin/branch/ledger/InputRailSection.tsx)),
**정작 집계 키인 고객/계정명은 추천 없는 자유 입력**이다(같은 파일 `:201`). 신규 행을 만들 때마다
표기 흔들림(`OO학원` / `OO 학원` / `OO어학원`)이 새 행을 만들고, 그 행은 매칭 인박스로 흘러간다.

### 2.4 신규 고객은 매트릭스에서 시작할 수 없다

매트릭스는 이미 존재하는 시트 행만 편집한다. 새 고객은 레일 폼으로 전환해 고객·담당·팀·상품군·월·
금액·확도를 채워야 한다. 붙여넣기도 **보이는 행 순서에 위치로 투영**할 뿐 고객명으로 매칭하지 않아
([buildMatrixPastePlan](../../components/admin/branch/ledger/rev-matrix-logic.ts)), 시트에서 복사한
블록의 행 순서가 화면 정렬과 다르면 엉뚱한 행에 값이 들어간다(프리뷰가 막아주지만 다시 해야 한다).

### 2.5 커밋 직후 실행 취소가 없다

되돌리기는 **적용된** 초안의 entries 상쇄에만 있다. 방금 잘못 친 셀은 체크 큐에서 그 건을 찾아
취소·삭제해야 한다. 빠른 입력 중 한 번의 오타가 흐름을 끊는다.

### 2.6 모바일에서는 입력할 수 없다

매트릭스 스크롤 영역은 `hidden … md:block`이고
([SalesLedgerWorkbench.tsx:3483](../../components/admin/branch/SalesLedgerWorkbench.tsx)),
모바일은 읽기 전용 [RevMobileList](../../components/admin/branch/ledger/RevMobileList.tsx)를 본다.
빠른 작업 레일 자체는 모바일에서도 뜨지만, 행을 고르고 월·금액을 직접 다시 채워야 한다.

### 2.7 감액은 입력 경로 밖

API가 `amount <= 0`을 거부한다
([route.ts:128](../../app/api/admin/branch/ledger-drafts/route.ts)). 감액은 "적용 되돌리기 → 재적용"
2단계다. 설계 의도(감사 추적)는 옳지만, 실무에서 잦은 하향 조정이 가장 긴 동선을 탄다.

구현하며 확정된 세부 규약:

- 배치 응답은 요청 shape가 유효하면 항상 200이고, 항목별 `status`(400/404/409/503/500)와
  `summary{total,succeeded,failed}`로 부분 실패를 드러낸다. 클라이언트는 청크 요청 자체가 실패한
  경우에만 단건과 같은 로컬 폴백 규약을 타고, 항목 실패는 로컬 폴백·큐 강등 없이 그 항목만 실패로 남긴다.
- 자가 체크 재편집 시 클라이언트는 `{...내용, status:"checked"}`를 보내고, 서버가 DB 트리거(checked
  행 내용 변경 금지)를 피해 한 요청 안에서 잠금 해제→갱신→재체크를 처리한다. `checked_by`가 다른
  사람이면 아무것도 바꾸지 않는다 — 검수자의 체크를 조용히 무효화하지 않기 위해서다.
- 붙여넣기 커밋은 셀 커밋과 같은 입력 빌더를 쓰므로 셀당 초안 1건·재편집은 갱신·자가 체크 규약이
  두 경로에서 동일하다.
- 알려진 한계: 큐 카드의 "편집" 버튼은 여전히 checked 초안을 열지 않는다(자가 체크 초안도 동일).
  자가 체크 초안의 수정은 매트릭스 같은 셀에서 다시 치는 경로로 하고, 큐에서 고치려면 체크를 해제한다.
  이 제약을 풀지는 P1-6(실행 취소)과 함께 다음 라운드에서 본다.

### P0-1. 초안 배치 API

- `POST /api/admin/branch/ledger-drafts/batch` — 최대 200건 생성/갱신
- `PATCH /api/admin/branch/ledger-drafts/batch` — 최대 200건 상태 전이(`checked`) 및 `action=apply`
- 응답은 **건별 결과 배열**. 부분 성공을 전체 성공으로 숨기지 않는다(운영 장애 안전 규칙).
- 건별로 기존 계약을 그대로 유지: 60초 중복 방어, `expectedUpdatedAt` 낙관적 잠금, 양수 금액 검증,
  `applied`로의 직접 PATCH 금지.
- 클라이언트는 붙여넣기 커밋과 일괄 체크·적용을 이 경로로 바꾸고, 단건 경로는 남겨 둔다(폴백).

효과: 2.1의 300왕복 → 3왕복. 붙여넣기 동시 600요청 폭주도 함께 사라진다.

### P0-2. 자가 체크 — 3단을 2단으로

매트릭스 셀 커밋에 한해 저장 시 `status: "checked"`로 올리고, 큐 카드에 **"자가 체크" 배지**와
입력자 이름을 남긴다. 적용은 지금처럼 명시적 액션으로 유지한다.

- 2단 게이트를 없애는 것이 아니라 **체크 시점을 입력 시점으로 당기는 것**이다. 감사 추적(누가 언제
  입력·체크·적용했는지)은 그대로 남는다.
- 서버 변경이 필요하다: 지금 생성은 `status: "draft"`를 하드코딩한다
  ([branch-sales-ledger-drafts.ts:358](../../lib/repositories/branch-sales-ledger-drafts.ts)).
  생성 입력에 `status`를 받아 `checked`면 `checked_by`/`checked_at`을 작성자로 함께 찍는다 —
  기존 체크 전이가 쓰는 필드 그대로다. 자가 체크 배지는 `created_by === checked_by`로 파생하므로
  새 컬럼을 만들지 않는다.
- 레일 폼 입력(신규 행·정정)은 기존 3단을 유지한다 — 시트에 없는 행을 만드는 동작이라 검수 가치가 다르다.
- 설정 토글(사람별)로 둘지, 매트릭스 기본값으로 둘지는 **D1**에서 결정한다.

### P0-3. 고객/계정 자동완성

- 후보: 현재 REV 행 고객명 + CRM 계정명. 정규화 키는 기존
  [normalizedAccountKey](../../lib/branch/account-key.ts)를 그대로 쓴다(새 정규화 규칙을 만들지 않는다).
- 자유 입력은 계속 허용하되, **정규화 키가 기존 행과 같은데 표기만 다르면** 저장 전에 인라인 경고
  ("기존 행 `OO학원`과 같은 계정으로 보입니다 — 그 행에 입력할까요?")와 원클릭 전환을 제공한다.
- 담당자 datalist와 같은 문법(추천만, 차단 없음)을 유지한다.

### P1-4. 매트릭스 인라인 신규 행

- 매트릭스 맨 아래 `+ 새 행` 한 줄. 고객 자동완성 1칸 → 월 셀로 Tab → 금액 입력 → Enter.
- 담당·팀·상품군은 현재 필터/담당자 핀에서 추론하고, 추론값은 행에 칩으로 보여 수정 가능하게 둔다.
- 저장은 기존 `new-row` 초안 계약을 그대로 사용한다(새 저장 경로 없음).

### P1-5. 붙여넣기 이름 매칭

- 첫 열이 숫자가 아니면 **고객명 열**로 인식해 정규화 키로 행을 매칭한다(위치 투영은 폴백).
- 미매칭 이름은 프리뷰에서 "새 행으로 생성" 체크박스로 분류 — 승인한 것만 `new-row` 초안이 된다.
- 주차 칸 앵커 붙여넣기 허용(현재는 월 셀만 대상).

### P1-6. 실행 취소 토스트

- 커밋 성공 토스트에 5초짜리 "실행 취소". 누르면 방금 만든 초안을 `cancelled`로 전이(삭제 아님 —
  감사 추적 보존, 2026-09-10 #8 결정과 동일).
- 기존 [pushMatrixToast](../../components/admin/branch/SalesLedgerWorkbench.tsx) 배선을 재사용한다.

### P2-7. 모바일 입력 진입

- 모바일 행 카드의 월 금액을 탭하면 레일 "입력/수정"이 **행·월·기존 금액·확도까지 프리필**된 상태로 열린다.
- 매트릭스 그리드 자체의 모바일 이식은 하지 않는다(64px 셀 밀도는 모바일 장르가 아니다).

### P2-8. 키보드 보강 (최소)

- `/` — 검색창 포커스
- `Shift+방향키` — 셀 범위 선택, 선택 범위에 `E/H/C` 일괄 확도 적용(배치 API 1회 호출)
- `Ctrl+Z` — P1-6의 실행 취소와 같은 동작을 키로

### P2-9. 감액 1액션화

API 계약(양수 전용)은 **바꾸지 않는다.** 대신 셀 컨텍스트에 "감액" 액션을 두고, 내부적으로
"되돌리기 → 새 금액 재적용"을 배치 API 한 번으로 묶어 사용자에게는 한 동작으로 보이게 한다.
(음수 허용으로 갈지는 **D3**.)

### P2-10. 매출시트 → 장부 딥링크

매출시트 행에 "장부에서 입력 ↗" — `lens=rev` + 고객 검색어 + 해당 월로 진입. §0의 왕복을 없앤다.

## 5. 2단계 — 어드민이 시트를 대체

1단계가 끝나면 "빠르게 칠 수 있는" 상태가 되지만, 그것만으로 시트를 끌 수는 없다. 시트에만 있고
어드민에 없는 것이 남아 있기 때문이다.

### 5.1 이미 깔려 있는 기반

- 버전드 DB 임포트: `branch_rev_lines`, `branch_rev_period_entries`, `sales_ledger_active_sources`
  ([마이그레이션과 목록은 로드맵 §10](sales-ledger-productization-roadmap-2026-06-30.md))
- 액티브 임포트가 있으면 시트를 다시 읽지 않는 읽기 경로
  ([sales-ledger-rev-import.ts](../../lib/repositories/sales-ledger-rev-import.ts))
- 주차 마감 스냅샷과 차분(`/api/admin/branch/ledger/weekly-close`)
- 적용 되돌리기(entries 상쇄)와 수기 장부 갭 계측
  ([computeManualLedgerGap](../../lib/admin-crm-revenue-sheet.ts))

### 5.2 전환 조건 체크리스트 (전부 충족해야 시트 입력 중단)

| # | 조건 | 현재 | 필요한 일 |
| --- | --- | --- | --- |
| C1 | REV 행 **속성** 편집 | 초안은 고객·담당·팀·월·금액·확도·메모만 쓴다 | 상태·지역·과금유형(시트 J열)·계약금액·첫결제일·중요도까지 편집 가능한 초안 종류 추가 |
| C2 | 감액·해지 표현 | 양수 전용 + `INACTIVE_STATUS_PATTERN` 문자열이 시트에서만 온다 | 감액·해지·드랍을 어드민 1급 동작으로 정의 (D3와 함께) |
| C3 | DB 원장 **직접 쓰기** | `captureRevDbImport`는 *시트 미러를 스냅샷*한다 | 시트 입력이 멈추면 새 행이 올라올 곳이 없다 — 초안 적용이 `branch_rev_lines`/`period_entries`에 직접 쓰는 경로 필요 |
| C4 | 원천 스위치 | 액티브 임포트 → DB 미러 → 라이브 시트 순 폴백 | 시트 동기화를 끄고 되돌아가지 않게 하는 명시적 스위치 + 운영 확인 절차 |
| C5 | 시트 독자 | 본사·타팀이 시트를 읽는다면 끊기면 안 된다 | 읽기 전용 역방향 export 필요 여부 확인 (**D5**) |
| C6 | 대조 증거 | Compass 대조 배지 패턴 존재 | 전환 기간 동안 "시트 합계 == 어드민 합계" 일일 대조를 표면에 고정 |

### 5.3 전환 순서

1. **2-1 속성 편집**(C1) — 시트를 계속 돌리면서 어드민에서 같은 값을 고칠 수 있게 한다. 이 기간의
   정본은 여전히 시트이고, 어드민 수정은 초안으로 남는다.
2. **2-2 감액·해지 정규화**(C2) — 하향 조정과 해지가 어드민 안에서 끝난다.
3. **2-3 DB 직접 쓰기**(C3) — 초안 적용의 목적지를 시트 미러 위 덧쓰기에서 DB 원장 자체로 옮긴다.
   여기부터 되돌리기 비용이 커지므로 마이그레이션 런북과 계약 테스트를 함께 만든다.
4. **2-4 원천 전환**(C4~C6) — 한 회계월을 **병행 입력**으로 돌려 C6 대조가 0 차이로 닫히는 것을 확인한
   뒤에만 시트 입력을 중단한다. 차이가 남으면 전환하지 않는다.

```bash
npx vitest run --dir tests/branch

```

추가할 테스트:

- 배치 API 부분 실패 — 일부 409/400이 섞여도 성공분이 반영되고 실패분이 건별로 보고되는지
- 자가 체크 상태 전이 — 매트릭스 커밋은 `checked`, 레일 커밋은 `draft`로 남는지
- 고객 자동완성 — 표기가 다른 동일 정규화 키에서 경고가 뜨는지(`account-key-parity` 인접)
- 붙여넣기 이름 매칭 — 행 순서가 화면 정렬과 달라도 이름으로 정확히 투영되는지
- 실행 취소 — `cancelled` 전이이고 하드 삭제가 아닌지

기존 회귀 보호(건드리면 반드시 재실행): `ledger-cell-dedup`, `ledger-cell-relock`,
`ledger-draft-optimistic-lock`, `ledger-week-cell-lock`, `draft-bulk-plan`, `rail-lock-precheck`,
`matrix-confidence-shortcuts`.

운영 mutation(동기화·마감·대량 임포트)은 승인된 계정·환경 없이 브라우저에서 실행하지 않는다.

## 8. UI·UX 디벨롭 — 입력 후 확도 선택기와 뷰 모드별 입력 편의 (2026-09-20 감사)

운영자 지적: "입력 후 (확정·예정·일반) 선택이 작고 불편하다", "각 입력 창(뷰 모드)을 더 잘 쓰게 하자".
읽기 전용 코드 감사 결과를 요약한다(수치는 Tailwind 클래스에서 역산).

### 8.1 측정 — 같은 개념이 6곳에서 6가지 크기

| 위치 | 버튼 높이 | 비고 |
| --- | --- | --- |
| REV 매트릭스 월·주 셀 편집 팝오버 (`RevMatrixEditPopover`) | **≈14px** | `text-[10px] px-1.5 py-0.5`, 셀 바로 아래 고정 — 가장 많이 쓰는 곳이 가장 작다. WCAG 2.5.8 최소 타깃(24px)의 58% |
| 붙여넣기 프리뷰 일괄 확도 | ≈21px | 마우스만 |
| 주차 그리드 rail 변형 seg | 32×24px | 라벨 1글자 축약("예/고/확") |
| 입력 레일 확도 블록 | 32px | 금액 입력보다 **앞**에 놓여 "금액 치고 확도 고른다"는 순서와 반대 |
| 콕핏 편집기 | 36px | |
| 주차 그리드 cockpit 변형 | 40px | rail 변형과 열 순서(금액↔확도)가 서로 반대 |

대조군: 편집 input 24px, 딜행 28px, 레일 저장 버튼 36px, 큐 일괄 버튼 `min-h-11 md:min-h-7`(앱 전역 13개 파일이 쓰는 반응형 관행) — 확도 버튼만 이 관행 밖이다.

### 8.2 진단

- **작다**: 매트릭스 팝오버는 최소 타깃 미달이고, 셀 폭(64px)보다 넓어 오른쪽 이웃 셀을 35~60px 침범하며, 아래 1~2행을 가린다(뷰포트·이웃 충돌 회피 없음).
- **골라도 안 보인다**: 편집 중 확도를 바꿔도 input은 무색(팝오버 버튼 배경만 변함). 커밋 후 pending 셀은 어떤 확도든 **항상 같은 앰버**(점·글자·밑줄 모두 `#A8741A`/`#7A520F` 고정). 토스트는 화면 하단 중앙이라 셀에서 멀고 확도를 말하지 않는다 → "확정을 골랐는데 초록을 볼 수 없다".
- **이름이 다르다**: 코드 SSOT는 예정/**고확도**/확정, 운영자 어휘는 예정/**일반**/확정. 라벨 변경 지점은 `ledger/shared.tsx`의 `DRAFT_CONFIDENCE_OPTIONS` 3문자열과 `confidence-tokens.ts`의 `label` 뿐 — **결정 D6**로 올린다(아래).

## 9. 하지 않기로 한 것

- **2단 게이트 폐기** — 자가 체크는 체크 시점을 당길 뿐이다. 적용은 항상 명시적 액션으로 남긴다.
- **전용 입력 라우트(콕핏 부활)** — 2026-07-19 재평가에서 채택하지 않기로 한 결정을 유지한다.
  URL·필터·큐 상태 이원화 비용이 이득보다 크다.
- **매트릭스 그리드의 모바일 이식** — D4 (a).
- **새 저장 경로** — 모든 입력은 계속 초안 계약 하나로만 들어간다. 배치 API는 같은 계약의 묶음 전송이지
  두 번째 저장 경로가 아니다.
