## 1. 제품 한 줄 정의

문서 허브는 `문서를 찾는 곳`이 아니라 `문서를 만들고, 보내고, 확인하고, 정리하는 운영 허브`다.

핵심 목표는 다음 세 가지다.

- 만들기는 빠르게 시작된다.
- 발송은 같은 절차로 반복된다.
- 보기는 상태와 다음 행동이 바로 읽힌다.

## 2. 핵심 원칙

### 2-1. 행동 기준으로 설계한다

- 문서 종류보다 `지금 해야 할 행동`을 먼저 보여준다.
- 사용자는 `견적서/계약서/영수증`을 먼저 찾는 것이 아니라 `새로 만들기 / 보내기 / 확인하기`를 먼저 한다.

### 2-2. 문서와 발송을 분리한다

- `문서 상태`와 `발송 상태`는 같은 값이 아니다.
- 문서는 원본과 버전을 말하고, 발송은 외부 전달본의 생명주기를 말한다.

### 2-3. 최신본과 발송본을 분리한다

- 최신 문서가 반드시 고객에게 나간 버전은 아니다.
- 발송 시점에 버전을 고정하고, 이후 수정은 새 버전으로만 누적한다.

### 2-4. 출력은 별도 결과물로 본다

- `링크 열기`와 `PDF 출력`, `인쇄용 보기`는 같은 버튼이 아니다.
- 출력은 최종 정리본, 발송은 전달본, 보기는 검토본으로 구분한다.

### 2-5. 정리는 사람이 분류하는 것이 아니라 상태가 분류한다

- 폴더를 먼저 만들지 않는다.
- `작성 중 / 발송 준비 / 열람 확인 / 응답 대기 / 만료 임박 / 완료 / 보관` 같은 운영 상태가 먼저다.

## 3. 전역 문서 허브 레이아웃

### 3-1. 화면 역할

전역 문서 허브는 전체 거래의 문서를 한 곳에서 다루는 운영 화면이다.

이 화면에서 해야 하는 일:

- 새 문서 만들기
- 문서 발송
- 버전과 열람 상태 확인
- 만료와 재발송 관리
- 출력용 PDF 접근

### 3-2. 데스크톱 레이아웃

```text
[Page Header]
  제목 / 짧은 설명 / live-demo 배지 / 새 문서 / 빠른 발송 / 새로고침

[Mode Tabs]
  만들기 | 발송하기 | 보기·정리

[Filter Bar]
  전체 | 견적서 | 계약서 | 영수증 | 작성 중 | 발송됨 | 열람됨 | 만료 임박 | 완료

[Main Grid]
  Left: 문서 리스트 / 큐
  Center: 선택 문서 상세 / 미리보기
  Right: 상태 요약 / 다음 액션 / 발송 이력 / 출력 상태
```

### 3-3. 각 영역의 역할

- 헤더는 현재 허브가 무엇을 하는 곳인지 설명한다.
- 모드 탭은 작업의 중심을 바꾼다.
- 필터 바는 문서의 성격과 상태를 빠르게 좁힌다.
- 좌측 리스트는 문서 큐다.
- 중앙 패널은 선택 문서의 상세와 버전 미리보기다.
- 우측 패널은 다음 행동과 운영 리스크다.

### 3-4. 모바일 레이아웃

- 상단에 제목과 `새 문서` CTA를 둔다.
- 모드 탭은 가로 스크롤 칩으로 축약한다.
- 필터는 두 줄 이하의 칩 그룹으로 접는다.
- 리스트가 먼저 나오고, 상세는 아래 아코디언 또는 바텀 시트로 연다.
- 우측 패널의 내용은 상세 패널 하단 탭으로 합친다.

## 4. 거래 상세 내 문서 탭 역할

### 4-1. 역할 정의

거래 상세의 문서 탭은 전역 허브의 축소판이다.

이 탭의 목적은 다음과 같다.

- 이 거래에 연결된 문서만 본다.
- 이 거래에서 바로 만들 수 있는 문서 작업을 제공한다.
- 문서 생성 이후의 다음 단계로 자연스럽게 이어준다.

### 4-2. 이 탭에서 보여줄 것

- 이 거래의 견적서 목록
- 이 거래의 계약서 목록
- 이 거래의 영수증 기록
- 각 문서의 최신 버전과 이전 버전
- 버전 고정 링크
- PDF 다운로드
- `shared` 또는 공개 상태 배지
- 재발송 / 복사 / 출력 / 열람 확인 액션

### 4-3. 이 탭에서 하지 않을 것

- 전체 거래를 가로지르는 전역 큐 역할은 하지 않는다.
- 문서 종류별 메뉴를 또 늘리지 않는다.
- 발송 정책과 보안 정책을 거래마다 제각각 흩뜨리지 않는다.

### 4-4. 이 탭의 핵심 문장

`거래 상세 문서 탭은 전역 문서 허브의 축소형이며, 이 거래에서 필요한 문서를 만들고 보내고 확인하는 가장 짧은 길이다.`

## 5. 모드별 화면 블록

### 5-1. 만들기 모드

목적:

- 새 문서를 가장 빨리 시작한다.
- 이전 문서를 복제해 초안을 빠르게 만든다.
- 거래 맥락을 잃지 않는다.

권장 화면 블록:

- `Start Card`
  - 새 문서 시작 CTA
  - 문서 종류 선택
  - 거래 선택
  - 최근 거래에서 이어서 만들기
- `Template Picker`
  - 표준 견적
  - 계약서 초안
  - 영수증 발행
  - 최근 문서 복제
- `Draft Form`
  - 제목
  - 거래
  - 고객
  - 발행일
  - 유효일
  - 내부 메모
- `Item Builder`
  - 품목 행
  - 수량
  - 단가
  - 합계
  - 비가격 행
- `Save Strip`
  - 임시 저장
  - 버전 생성
  - 미리보기

만들기 모드 핵심 원칙:

- 새 문서를 만들 때도 나중 발송을 고려해 버전 구조를 미리 깐다.
- 사용자는 초안 작성 중에도 현재 어떤 거래에 속하는지 잃지 않아야 한다.

### 5-2. 발송하기 모드

목적:

- 같은 절차로 반복 발송한다.
- 문서 버전, 수신자, 채널, 보안 옵션을 한 번에 정리한다.
- 재발송과 새 발송을 구분한다.

권장 화면 블록:

- `Send Queue`
  - 오늘 보낼 문서
  - 열람 후 응답 없는 문서
  - 만료 임박 문서
  - 실패 재시도 문서
- `Recipient Card`
  - 수신자
  - 참조자
  - 연락처
  - 이메일
- `Version Lock Card`
  - 발송할 버전 선택
  - 최신본과의 차이
  - 발송본 고정 안내
- `Channel Card`
  - 링크
  - PDF
  - 카카오톡
  - 이메일
- `Security Card`
  - 만료일
  - 비밀번호 사용
  - 다운로드 허용
  - 출력 허용
- `Confirm Bar`
  - 발송 전 최종 요약
  - 테스트 발송 여부
  - 실제 발송 CTA

발송하기 모드 핵심 원칙:

- 발송 버튼은 언제나 같은 위치에 있다.
- 발송 전에는 반드시 `누구에게 / 어떤 버전 / 어떤 채널 / 어떤 보안`이 보인다.
- 재발송은 새 작업처럼 보이지 않게, 이전 전달본에서 이어서 처리한다.

### 5-3. 보기·정리 모드

목적:

- 문서를 빨리 찾는다.
- 상태별로 자동 정리된 느낌을 준다.
- 운영자는 무엇이 막혔는지 즉시 본다.

권장 화면 블록:

- `Smart Filters`
  - 작성 중
  - 발송 준비
  - 발송됨
  - 열람됨
  - 응답 대기
  - 만료 임박
  - 완료
  - 보관
- `Document Table or Card List`
  - 한 줄 요약
  - 상태 배지
  - 다음 액션
  - 마지막 발송
  - 마지막 열람
- `Detail Panel`
  - 선택 문서 상세
  - 버전 이력
  - 발송 이력
  - 출력 상태
  - 빠른 액션
- `Bulk Actions`
  - 링크 복사
  - PDF 열기
  - 재발송
  - 만료 연장
  - 보관 처리

보기·정리 모드 핵심 원칙:

- 정리는 사람이 일일이 폴더를 만드는 것이 아니라 상태와 이력으로 자동 분류되는 느낌이어야 한다.
- 문서가 많아질수록 `다음 액션`이 더 중요해진다.

## 9. 문서 상태와 발송 상태 분리 규칙

### 9-1. 문서 상태

- `draft`
- `ready`
- `review`
- `final`
- `archived`

### 9-2. 발송 상태

- `draft`
- `ready`
- `sent`
- `opened`
- `expired`
- `revoked`
- `failed`

### 9-3. 분리 이유

- 문서가 준비됐다고 해서 반드시 발송된 것은 아니다.
- 발송됐다고 해서 문서 자체가 최종본인 것도 아니다.
- 열람됨과 승인됨도 같은 상태가 아니다.

### 9-4. 화면 표현 규칙

- 문서 row에는 두 상태를 동시에 보여준다.
- 상세 패널에서는 문서 상태와 발송 이력을 나눠서 보여준다.
- 경고는 발송 상태에서만 띄우고, 초안 경고는 문서 상태에서 띄운다.

## 10. 출력, PDF, 링크 원칙

### 10-1. 링크

- 링크는 고객 열람용이다.
- 링크는 버전 고정이어야 한다.
- 링크 복사는 가장 자주 쓰는 기본 행동이다.

### 10-2. PDF

- PDF는 발행 시점 스냅샷이다.
- PDF는 다운로드와 외부 첨부에 모두 쓰일 수 있다.
- 고객이 저장하거나 내부가 아카이빙할 때 동일 버전을 보도록 한다.

### 10-3. 출력

- 출력은 인쇄용 레이아웃이 따로 필요하다.
- 출력 허용 여부는 문서와 전달본에서 모두 확인해야 한다.
- 출력이 필요 없는 링크는 출력 버튼을 강하게 보이지 않게 한다.

### 10-4. 보기 기준

- `보기`는 검토용
- `발송`은 전달용
- `출력`은 정리용

## 11. 모바일 압축 원칙

- 상단 CTA는 `새 문서` 하나를 유지한다.
- 모드 탭은 가로 스크롤 칩으로 바꾼다.
- 필터는 상태 우선으로 접는다.
- 리스트가 우선이고, 상세는 바텀 시트로 연다.
- 발송 모달은 풀스크린 시트를 기본으로 한다.
- row 액션은 `상세 / 복사 / 발송` 세 개까지만 노출하고 나머지는 더보기로 넣는다.
- 버전 이력은 아코디언으로 접는다.
- 출력 카드와 발송 카드는 한 화면에 다 보이려 하지 말고 순차 노출한다.

## 12. v1 우선순위

### P0

- 전역 문서 허브 레이아웃 정리
- `만들기 / 발송하기 / 보기·정리` 모드 추가
- 문서 row 구조 정리
- 상세 패널 구조 정리
- 공통 발송 모달 필드 확정

### P1

- 거래 상세 문서 탭을 전역 허브와 같은 규칙으로 압축
- 문서 상태와 발송 상태 분리 표시
- PDF / 링크 / 출력 액션 통일

### P2

- 스마트 큐 저장
- bulk action
- 만료 임박 큐
- 재발송 히스토리 노출

## 13. 화면 문구 초안

- `최신본과 발송본을 분리해서 봅니다.`
- `이 문서의 다음 행동은 무엇인가요?`

## 14. 구현 메모

- 이 문서는 전역 허브와 거래 상세 탭이 같은 언어를 쓰게 하려는 기준서다.
- 실제 구현은 기존 문서 허브 화면을 중심으로 시작하고, 거래 상세 문서는 동일한 정보 구조를 축약 재사용하는 방향이 적합하다.
