# 챗봇 증상형 CS 질문 트리아지 — 가이드·Figma CS 기반 4회 루프와 페르소나 상호 평가 5회 루프 기록

기준일: 2026-11-06 · 담당 파트: 챗봇/CS([플레이북 05](./playbook/05-chatbot.md))

## 문제

공개 챗봇이 짧은 증상형 질문을 처리하지 못했다.

| 질문 | 변경 전 답 |
|---|---|
| 기관 등록 안됨 / 기관 인증이 안 돼요 | 로그인·비밀번호 재설정 안내(오답) |
| 녹화 안됨 / 업데이트가 안 돼요 / 설치가 안 돼요 / 미러링이 안 돼요 | 로그인·비밀번호 재설정 안내(오답) |
| 에러나요 | "무엇을 도와드릴까요?" |
| 오류가 떠요 / 버그 있어요 | 범용 fallback(신뢰도 0.15) |
| 다시보기가 안 떠요 | 웹 라이브 생성 방법(사용법 가이드) |

원인은 세 가지였다.

1. `LOGIN_TROUBLE_RE`에 `안 돼|안됨`이 들어 있어 대상과 상관없이 "안 돼"가 들어간 질문을 모두 로그인 문제로 분류했다.
2. 공개 문제 해결 문서(로그인·카메라/마이크·앱 업데이트·PC 설치·끊김·녹화·녹화본·다시보기·숙제, 2026-10-29 공개)가 있었지만 챗봇이 증상 질문을 그 섹션으로 잇는 경로가 없었다. Figma 사용법 가이드가 증상 질문까지 가로채기도 했다.
3. 대상이 없는 오류 질문은 되묻는 경로가 범용 문구뿐이었다.

## 바꾼 것

- `lib/chatbot/symptom-triage.ts`(신규): 대상 + 증상 패턴으로 증상 주제 66개를 고르고, **공개 문서 섹션의 단계(steps/body)를 그대로 뽑아** 답한다. 문서를 고치면 챗봇 답도 같이 바뀐다. 근거는 공개 문서(Figma CS 안내 화면 모음과 공식 도움말을 다시 쓴 것)만 쓰고, 내부 트러블슈팅 지식(`docs/active/cs-troubleshooting`)은 쓰지 않는다.
  - 대상 없는 오류("에러나요", "안 돼요", "선생님 안녕하세요 오류가 자꾸 나요")는 오류 문구·화면·기기를 되묻고 자주 있는 6가지 응급 조치를 함께 보여 준다(`clarifying_question`).
  - "끊김 없는 수업 가능해요?", "무료 체험판 있나요?"처럼 기능·가능 여부를 묻는 질문은 증상으로 보지 않는다.
  - 문의 안내에는 아이디·연락처·시리얼 같은 식별 정보를 채팅으로 적으라는 항목을 넣지 않는다.
- `lib/chatbot/service.ts`: Figma 가이드 직답 앞에서 트리아지를 먼저 본다. 단, 사람이 확인한 Figma **알려진 의도**(늦게 가입한 학생 다시보기, 웹 라이브 채팅 등)는 그 가이드를 먼저 쓴다(로컬 녹화 파일 찾기처럼 증상 문서가 더 구체적인 주제는 예외). 트리아지 답은 결정형 최종본이라 stream/non-stream 모두 Gemini 재작성 없이 나간다.
  - 트리아지·바로 답·"이미 다 해 봤다" 상담 연결·지난 대화 되묻기·말투 계층은 **공개 위젯 전용**이다. 내부 CS 코파일럿(`includeInternalDocs: true`)은 이 단계를 건너뛰고 내부 문서 검색(`match_docs_ai_chunks`의 `include_internal`)까지 간다(계약 6, `tests/channel-talk/include-internal-docs.test.ts`).
- `LOGIN_TROUBLE_RE`에서 `안 돼|안됨` 단독 매칭을 뺐다. `계정 인증·삭제·탈퇴`도 로그인으로 보지 않는다.
- 하드웨어 판별의 `보드`가 '대시보드'에 걸리던 버그를 고쳤다("관리자 대시보드에 인증하라는 메시지가 떠요"가 전자칠판 스펙 답으로 새던 원인).
- Figma 큐레이션 가이드 `recording-download-share`에 "녹화본 다운로드" 류 키워드를 더했다("녹화본 다운로드 방법 알려줘"가 도입 전 FAQ로 새던 원인).

## 페르소나 상호 평가 루프

10명의 페르소나(여 5·남 5, 성격·말투·디지털 숙련도가 다름)가 회차마다 6문항씩 냈다(15회차까지 900문항). 6회차부터는 2시간마다 같은 순서로 반복한다(`scripts/chatbot-persona-loop/README.md`). 질문과 정답 키(intent·must·must_not)는 저장소를 읽지 않은 별도 작성자가 만들었다. 심사는 서로의 결과를 보지 않는 두 심사관이 같은 기준표로 따로 했다.

- 기준표: C1 의도 적중·C2 정확성·C3 실행 가능성·C4 페르소나 적합·C5 안전·정책·C6 간결·형식, 각 0~2점.
- 통과 조건: C1·C2·C5가 모두 2점, 합계 10점 이상, must를 모두 충족하고 must_not을 하나도 어기지 않음.
- 두 심사관 판정이 엇갈린 행만 서로의 근거를 보고 다시 판정했다. 아래 통과 수는 두 심사관이 모두 통과로 본 문항만 센다.
- 회차 k에서는 새 질문 k와, 그 직전 수정이 반영된 질문 k−1을 함께 채점했다.

|---|---|---|---|

- 새 질문 점수가 낮은 이유: 수정 전 답을 그대로 채점했고, 회차마다 질문 주제가 새로 바뀌었다.
- 수정 후 재채점 점수: 29 → 30 → 45 → 45 → 37 → 43 → 54 → 56 → 56 → 58 → 59 → 56 → 54 → 58 → 59/60이었다.
- 마지막 회차 재채점 뒤 고친 것은 다시 채점하지 않았다(지난 문의 오인, 강제 상담 연결, 핫스팟 판단 순서, 코스 넘기기 경로, 영어 요약 문구).

루프에서 고친 것:

- 일반 폴백("상황을 한 문장만 더…")이나 엉뚱한 문서로 새던 질문에 맞는 주제를 더했다. 주제는 `lib/chatbot/symptom-topics-field.ts`에 있고, 모두 공개 문서 섹션에서 단계를 가져온다.
- 공개 안내에 없는 사실은 "공개 안내에 없다"고 밝히고 상담으로 넘긴다. 예: 해상도 상한, 링크 유효 기간, 리전 선택, 계정 통합, 재응시.
  - 반대로 문서에 있는 내용을 "없다"고 하던 답도 바로잡았다. 예: 계정 삭제 경로, 1인 강사 Pro, 스마트 담임 교사, 숙제 관리.
- 결제·세금계산서·할인·체험·쇼룸·계정 삭제·시험 정답 요청은 정해 둔 문장으로 바로 답한다(`buildServiceQuickAnswer`).
- 말투 처리:
  - 화난 사람에게는 상담 연결을 먼저 내민다. 이미 다 해 봤다는 사람에게는 같은 조치를 다시 주지 않는다.
  - 지난 대화를 전제로 한 질문에는 지난 대화를 볼 수 없다고 먼저 밝힌다.
  - 들뜬 느낌표는 화난 신호로 보지 않는다.
- 한 번에 두 가지를 물으면 둘째 주제의 첫 단계까지 붙인다.
- 근거 없는 문장을 지웠다. 예: 전자칠판 카메라·마이크 내장, 다시보기 횟수 계산, 기록 보존 단정, 1:1 전담 전환 지원, 다른 기관 소속 단정, 최소 인터넷 속도.
- 6회차: 결제 사칭 문자, 해지 후 재결제, 보안 점검(암호화·IP 제한·SSO·802.1X), 만 14세 미만 동의, 지점 계정·계산서, 로고 사용, 소개 혜택, 체험 데이터 삭제처럼 공개 문서로 끝까지 풀 수 없는 질문은 `lib/chatbot/quick-answers-field.ts`의 정해 둔 답으로 바로 받는다. 가상 배경, 한글(HWP) 파일, 칠판 청소, 무상 A/S 기간, 해외 접속, 웹 라이브 공개 수업, 닉네임, 왕관 권한, [대량 작업]처럼 문서에 있는 사실은 그대로 답한다.
- 질문 주도(`lib/chatbot/follow-up.ts`): 답 끝에 확인 질문 하나를 붙인다. 뜻이 갈리는 말은 어떻게 이해했는지 밝히고, 증상 주제가 정해 둔 질문이나 쓰는 기기를 묻고, 영업 상담에서는 규모·교실 수·수업 방식·지금 쓰는 도구·도입 시기 가운데 모르는 것 하나를 묻는다. 화난·반복 문의와 영어 질문에는 붙이지 않는다.
- 7회차: 문서에 있는데 "없다"고 하던 답(화면 수명 5만 시간, 65인치 S65, HDMI Touch, 보조 카메라, 통계 이력, 아이디 전환 불가)을 바로잡고, 문서에 없는 메뉴 이름([새 과제 추가] 등)과 결제 조건 표현을 뺐다. 답의 첫 문장이 이미 공감·사과하면 말투 계층이 첫마디를 또 붙이지 않고, 따옴표로 옮긴 남의 말은 지난 문의로 읽지 않는다. 정해 둔 답 끝에는 영업용 되묻기를 붙이지 않는다(요금 문의만 예외).
- 8회차: 새 질문 전반에 영향을 주던 공통 원인 셋을 고쳤다. 보안 공격 거절 패턴이 'rce'·'sqli'를 단어 일부로 잡아 "video source" 같은 정상 질문을 거절하던 것, 비교 질문 패턴이 "차별 아니에요"를 비교로 읽던 것, 제품 이름(classin)이 Figma 가이드의 강한 키워드로 쳐져 앱 업데이트 순서가 엉뚱한 질문에 붙던 것이다. 학생의 늦은 제출 질문이 강사용 숙제 안내로 새던 경로도 막았다.
- 9회차: 새 질문을 엉뚱한 답으로 보내던 공통 원인을 고쳤다.
  - '걱정'이 들어가면 도입 걱정 영업 문구가 나가던 것('반대편 벽'의 '반대'를 강사 반발로 읽음), 학원이 여는 설명회·행사 질문에 클래스인 행사 안내가 나가던 것, '영어로만 뜬다'를 영어 상담 요청으로 읽던 것, '학생의 채팅 기록'을 챗봇과의 대화로 읽던 것이다.
  - 질문 주도 계층의 A/S 패턴이 'classin' 속 'as'를 고장 신호로 잡아, ClassIn이라고 쓴 질문마다 영업 되묻기가 빠지던 것을 고쳤다. 같은 패턴 때문에 가격 비교 질문에 보증 답이 나가던 것도 바로잡았다.
  - 검색 답 끝의 범주별 일반 되묻기("오류 화면·브라우저를 알려 주세요", "90일 도입 순서로…")는 결제 증빙 안내만 남기고 뺐다. 끝 질문은 질문 주도 계층이 고른다.
  - 불안 첫마디는 당황(어떡하죠·급해요)과 걱정을 나누고, 미안해하며 걱정하는 말에는 사과를 덜어 주는 첫마디를 쓴다. "어떻게 해야 하나요"만으로는 불안으로 보지 않는다.
  - 답에 섞여 있던 내부 작성 지침 문장("기본 기능처럼 단정하면 안 됩니다")을 고객에게 하는 말로 바꿨다.
- 10회차: 제품 질문이 챗봇 자기소개나 영업 문구로 새던 범용 원인을 더 고쳤다.
  - 챗봇을 부르는 말 패턴이 '너무'의 '너', '없으니 제'의 '니', '로봇'의 '봇'에도 걸리던 것을 낱말 단위로 고쳤다. '아까·방금·기억'은 제품 낱말이 없을 때만 챗봇과의 대화로 보고, "이 챗봇 안내대로 했는데…"처럼 지난 답을 인용한 제품 질문은 제품 문제로 본다.
  - '바꾸면'만으로 도입 걱정 문구가 나가던 것, 행사를 지나가며 말한 질문에 행사 안내가 나가던 것(일정·신청을 물을 때만 쓴다)을 고쳤다. 영어로 "you told me"라고 지난 대화를 말하면 볼 수 없다고 먼저 밝힌다.
  - 분류가 안 된 짧은 질문에는 "도입·운영·계정·결제 중 어디냐" 대신 묻는 사람에 맞는 예(학생·학부모: 수업 입장·다시보기·숙제, 학원: 강사 등록·녹화 설정·저장 공간)를 들어 하나만 묻는다.
  - 심사관이 짚은 문서 사실을 반영했다. 활동마다 게시 대상(구성원)을 골라 일부 학생에게만 낼 수 있고, 전자칠판에는 수업 녹화와 별도로 로컬 녹화가 있으며, 같은 화면을 오래 띄우면 잔상이 남을 수 있다.
- 11회차: 말투와 주제를 잘못 읽던 범용 원인을 고쳤다.
  - 따옴표로 옮긴 말('Good job!')의 느낌표는 세지 않고, 'ㅎㅎ·good job'은 긍정 신호로 본다. "안 맞으면 어떡하죠"처럼 아직 일어나지 않은 일의 걱정은 당황이 아니라 걱정 첫마디를 쓰고, 답이 "놀랐겠어요"로 시작하면 첫마디를 또 붙이지 않는다.
  - "챗봇 답변에 ~라고 돼 있어서"처럼 지난 답을 인용한 제품 질문은 챗봇 자기소개가 아니라 제품 질문으로 본다.
  - 오래된 정해 둔 답이 새 질문을 가로채던 경로를 좁혔다. 예: '네트워크 상태 불량' 표시 → 알림 빨간 점, 숙제 사진 → SNS 캡처, 결제 명의 → 닉네임, 화면 키보드 → 앱 언어, '보안 패치' → 내부 단가표 거절.
  - 심사관이 짚은 문서 사실을 반영했다. 학생으로 등록된 수업은 시작 10분 전에 앱 알림이 오고, 숙제는 다시 내면 마지막 제출본만 남는다. 온보딩 때 관리자·강사 교육을 기본 2회 하고, 소프트웨어 플랜 이름은 Standard·Plus·Enterprise다. API를 켜면 코스·수업·구성원을 자체 시스템에서 만들어야 한다.
- 12회차: 반복 문의와 지난 채팅 인용을 가려 읽게 했다.
  - "오늘만 네 번째"처럼 횟수만 센 말은 같은 일이 되풀이된다는 뜻으로 본다. 문의·연락을 함께 말할 때만 "여러 번 문의하시게 해 드려" 사과와 즉시 상담 연결을 쓴다. "지난번 이 채팅에서", "어제 이 챗봇이", "저번에 여기서"는 챗봇과의 지난 대화로 읽는다.
  - 카드 명세서의 낯선 결제를 학원비 결제 기능 문의로 막지 않는다. 긴 질문 속 '이거'에 "'그거'가 뭐냐"고 되묻지 않고, 이미 칠판을 쓰는 학원의 걱정에 도입 영업 문구를 붙이지 않는다.
  - 오래된 정해 둔 답이 새 질문을 가로채던 경로를 좁혔다. 예: 'jobs'의 obs → OBS 가상 카메라, 선생님이 올린 단톡방 캡처 → 학생 SNS 답, 리스 → 연간 결제 답, 실수로 수업 종료 → 화장실 답.
  - 심사관이 짚은 문서 사실을 반영했다. 6.0.9 실시간 자막 번역은 관리자가 [부가가치 서비스]에서 켜고 수업을 만들 때 켠다. 관리자가 [수업 모니터링]으로 교실에 들어가도 교사·학생에게 알림이 가지 않는다. 학생을 잡는 카메라는 S1이다. 영수증에 찍히는 이름의 기준은 공개 안내에 없다. 전자칠판에서 수업에 들어가는 자리는 칠판 기준으로 따로 안내돼 있지 않다.
- 13회차: 오래된 정해 둔 답이 낱말 하나로 새 질문을 가로채던 경로 26곳을 좁혔다.
  - 예: '지우다'만으로 칠판 청소 답(회사 노트북 기록 지우기, 손날에 판서가 지워짐), '열면'의 '열'로 칠판 발열 답, '이름'만으로 숙제 사진 개인정보 답, 'jobs'·'total cost'·'presenter view' 같은 영어 낱말로 엉뚱한 답이 나가던 것.
  - 이미 상담원 대기 중이라고 항의하는 질문에는 말투 계층이 "지금 바로 연결해 드릴게요"를 또 붙이지 않는다.
  - 재답변이 54/60으로 내려간 원인은 지난 회차 답이 문서에 있는 내용을 "공개 안내에 없다"고 한 것이다. [종합 성적]은 여러 활동의 평균, 판서 화면은 두 손가락으로 위아래로 옮김, 다섯 손가락 작은 제어 화면은 멀리 있는 버튼용, 구성원 초대 뒤 [교사로 설정], PC 설치 문서의 최소·권장 사양(인텔·AMD), PC 설치 때 [언어 선택]을 반영했다. 정해 둔 답을 쓸 때는 "없다"고 쓰기 전에 문서를 다른 낱말로도 찾는다.
  - 새로 확인해 넣은 문서 사실: 보드 자체 시스템 Android 11(메모리 4GB, 저장 32GB), 해외에서도 VPN 없이 대부분 접속, 마이크가 꺼진 채 녹화하면 소리가 남지 않음, 손바닥처럼 넓은 면으로 문지르면 지워짐, [다른 코스에서 가져오기]·[작업 복사], 인증 서류(학원은 사업자등록증·설립 운영등록증명서, 신분증 앞면은 개인 강사).
- 14회차: 정해 둔 답의 사실을 쓰기 전에 따로 확인했다.
  - 13회차 답 60개를 독립 사실 확인 담당이 공개 문서와 대조해, "공개 안내에 없다"고 했지만 문서에 있던 12곳을 고쳤다. 예: PC 로그인 화면의 [구글 계정으로 로그인하기]·[스캔해 로그인], 코스 복사 때 학생 명단·지난 성적은 넘어가지 않을 수 있음, 웹 라이브에는 녹화 화면이 그대로 나감, 담당 매니저·카카오톡 채널 같은 다른 상담 경로. 재답변이 54에서 58/60으로 올랐다.
  - 칠판 OPS 사양을 사용자 확인대로 고쳤다. OPS는 S110을 포함해 Windows, 16GB 메모리, 256GB SSD이고, 모델마다 다른 건 CPU다.
  - 말투 판단: "헌 걸 버리기는 아깝고요"처럼 물건을 아끼는 말은 화로 읽지 않는다. "아까 너가 앱 데이터 지우라해서"처럼 챗봇이 시킨 대로 했다는 말은 챗봇 자기소개가 아니라 제품 질문으로 본다.
  - 오래된 정해 둔 답 19곳이 새 질문을 가로채 조건을 좁혔다. 예: 태블릿 미러링 → 태블릿 구매, 칠판 청소 → 물이 들어간 사고, 칠판 시계 → 쉬는 시간 잠금·NTP, 지점 계정 → 가맹 본부.
  - 기준표에 생성 캡처 가이드(`lib/cs-figma-guides.ts`가 내보내는 unlisted 문서, 사내 전용 제외)도 근거라고 적었다. 두 심사관이 이 범위를 다르게 봐서 이견이 생겼다.
  - 새로 확인해 넣은 문서 사실: 클래스인은 오프라인(대면) 출석 체크를 지원하지 않음, 트로피 순위, 대형 화면 제어 메뉴의 [터치 잠금]·[화면 끄기], 액체가 들어가면 전원을 끄고 플러그를 뽑은 뒤 A/S, 수업 리소스 보호 잠금, 학습 자료로 열람 여부 확인, 학생 원비 수납은 처리하지 않음, 리눅스 설치 파일, 다이내믹 아일랜드로 수업 입장.
- 15회차: 정해 둔 답이 기대한 대로 나가는지 보는 점검을 엄격하게 바꿨다.
  - 첫 문단만 비교하던 점검은 "두 가지 답드릴게요." 같은 흔한 첫 줄 때문에 다른 답이 나가도 통과로 봤다. 그래서 b14-P02-3(미응시 학생과 정답률)이 반 평균 답에 가로채인 것을 놓쳤다. 먼저 맞는 정해 둔 답의 id와 둘째 문단을 함께 보는 `scripts/chatbot-persona-loop/route-check.mjs`를 더했고, 11~15회차 블록은 모두 60/60이다.
  - 오래된 정해 둔 답 19곳이 새 질문을 가로채 조건을 좁혔다. 'multitasking' 안의 lti로 LTI 답이 나가던 것은 낱말 경계로 고쳤다. "깜빡하고 안 줄이면"의 깜빡을 화면 깜빡임으로 읽던 것도 고쳤다.
  - 새로 확인해 넣은 문서 사실: 하위 계정 권한은 기관 관리·스토리지·학습 관리·관리자 기능·재무 센터 묶음으로 나뉨, 설정한 수업 시간이 다 되면 모두 교실에서 나가짐, 설치 당일 점검 순서, 웹 라이브 시청자 채팅은 교실 학생에게 안 보이고 녹화에 남지 않음, 조교는 수업에서 강사와 같은 권한, 학생 학습 보고서의 말한 시간(Speaking), 교실 [브라우저]·[다방향 브라우저], 50점 적외선 터치.
- 회귀 테스트: `data/chatbot-persona-eval-set.json`(900문항), `tests/chatbot/persona-eval-set.test.ts`, `tests/chatbot/follow-up.test.ts`, `tests/chatbot/conversation-tone.test.ts`. 오프라인 결정 경로에서 일반 폴백이 0건인지 보고, 근거 없는 문장·식별 정보 요구가 다시 생기지 않는지도 본다. 지난 대화 전제·영어·반복 항의·두 가지 질문 처리도 확인한다.

심사관이 지적했지만 남겨 둔 것:

- 챗봇 데이터 활용 문장("반복 질문을 찾고 FAQ를 보강")은 공개 문서에 근거가 없다는 지적을 받았다. 사이트의 답변 정책이라 "어떤 데이터로 답하나요" 답에는 그대로 둔다. 대신 "입력한 내용이 저장되나요, 학원 정보를 넣어도 되나요"에는 저장 여부를 단정하지 않고 개인정보처리방침과 입력 자제를 안내하는 답(`input_privacy`)을 따로 둔다.
- 운영에서 Gemini가 다시 쓰는 검색형 초안은 오프라인으로만 채점했다. 그래서 운영 답의 질은 이 표와 다를 수 있다.

## 남은 것

- 운영 DB의 실제 챗봇 질문 로그로 같은 루프를 한 번 더 돌리는 것이 다음 단계다. 이 세션에서는 운영 DB에 접속하지 않았다(`npm run check:alpha-db` 미실행 — 챗봇 DB/RPC 계약은 바꾸지 않았다).
- 대화 이력(직전 질문)을 보고 "에러나요"의 대상을 추정하는 것은 하지 않았다. 지금은 대상 없는 오류를 항상 되묻는다.
- 화면에 중국어가 보이는 문제, 결제창 멈춤처럼 공개 문서가 없는 증상은 트리아지 대상이 아니다. 공개 문서가 생기면 주제를 더한다.
