# 매출 장부 · 견적 문서 · 사이드바 간소화 기획 (2026-11-20 홈페이지 회의)

상태: 기획 — 구현 전. 1차 결정(D1 · D2 · D4 · D8)은 2026-11-20에 닫혔다(§5). 확도 색(D6)은 디자인 시안을 보고 정한다.
범위: `/admin/branch/ledger`(매출 장부), `/admin/quotes`(견적·문서), 어드민 사이드바·로그인 착지
근거: 2026-11-20 홈페이지 회의 녹취(약 44분)와 같은 날 코드 조사. 녹취는 자동 전사라 일부가 뭉개져 있어, 해석이 들어간 항목은 "(해석)"으로 표시했다.

## 1. 한 줄 요약

매니저가 당장 쓰는 화면은 **매출 장부와 견적 문서 둘뿐**이다. 12월 1일부터 매출 시트를 잠그고 장부를 원본으로 쓰려면, 장부는 "기존 시트와 90% 같은 모양"이어야 하고, 나머지 화면은 관리자 외에는 사이드바에서 치운다.

## 2. 회의에서 정한 것

### 2.1 공통 원칙

- 새 기능을 더하지 않는다. **12월 1일 기준 매출 시트에서 되던 것이 장부에서 그대로 되면 합격**이다.
- 불편했어도 지금까지 쓴 시트 모양이 팀에게 가장 직관적이다. 첫 화면과 입력에서 위화감이 없어야 한다.
- 기능은 지우지 않고 숨긴다. 고도화하면서 하나씩 다시 꺼낸다.

### 2.5 이번 범위 밖 (다른 사람이 별도로 진행)

- **총판 미수금 · 정산 정리**(환율 고정, 네오CRM 수금 대조, 합산 입금 분해, 미수 대장 잔액): 의사결정자가 직접 독립 모듈(별도 저장소)로 만들고, 완성되면 붙인다. 이 저장소 작업자는 매출 시트에 집중한다.
- **10월 C방식 물량 목록**: CRM과 하드웨어 시트를 맞춰 "금액 · 입력 누락" 목록을 뽑아 전달하기로 했다(일회성 추출, 화면 작업 아님).
- 은행 보안 프로그램 팝업 문의는 이 저장소와 무관하다.

회의 중 화면에서 본 문제 두 가지는 화면 개편보다 먼저다.

- 시트 구조를 최근에 바꾼 뒤로 **동기화 결과가 시트와 맞지 않는다**(하드웨어 매출이 빠진 것처럼 보임).
- 장부가 **아예 뜨지 않는 순간**이 있었다(배포가 끊긴 것으로 추정). 원인은 확인되지 않았다.

## 4. 작업 묶음

순서는 W0 → W1 → W4 → W5a → W3 → W5b다. W2는 다른 브랜치에서 진행 중이라 확인 목록만 둔다. W1 · W4는 서로 다른 파일이라 나란히 진행할 수 있다. 각 묶음의 "지시"는 작업 세션에 그대로 넘길 수 있게 적었다. 화면 모양은 디자인 시안 4장(1 장부 · 2 확도 색 · 3 견적 · 4 사이드바와 탭)을 본 뒤 확정한다.

### W0. 장부 데이터 복구 (가장 먼저, 12월 1일 전환의 전제)

담당: 그로스/CRM 파트([Classin KR Team 스킬](../../.codex/skills/classin-kr-team/SKILL.md))

지시:

1. 장부가 뜨지 않던 원인을 찾는다. 배포 상태, `SyncHealthBannerServer`가 띄운 경고, `/api/admin/branch/sync`의 최근 실행 결과를 본다.
2. 최근 바뀐 '2. REV' 시트 구조와 동기화 파서(`lib/branch/sync/`)가 어디서 어긋나는지 찾는다. 하드웨어 행이 빠지는지 따로 본다.
3. 시트와 장부를 담당자별 · 월별 합계로 대조해 차이를 0으로 만든다. 차이가 남으면 건별 목록으로 남긴다.
4. 운영 동기화 실행은 승인된 관리자 계정으로만 한다(지침 맵 §6).

끝난 기준: 담당자 2명 이상이 자기 담당 11월 · 12월 합계가 시트와 같다고 확인한다.

담당: 어드민 코어 파트 ([02-admin-core.md](playbook/02-admin-core.md))
결정: D1 · D2 닫힘

**전체 사이드바를 보는 사람**은 `SUPER_ADMIN` 역할과, 따로 지정한 계정(현재 1명: 준혁)이다. 그 밖의 모든 계정은 **간소 사이드바**다.

지시:

1. `components/admin/admin-nav-access.ts`의 기본값 판정(`resolveDefaultNavPreference`)에 "전체 / 간소" 구분을 더한다. 간소 사이드바는 `/admin/branch/ledger`와 `/admin/quotes`만 상시, 나머지는 기본 숨김이다. 전체 사이드바는 지금 그대로다.
2. **지정 계정은 역할을 올리지 않는다.** `SUPER_ADMIN`으로 바꾸면 API 권한까지 열린다. 사람별 표시 설정으로 "전체 사이드바"를 켠다. `admin_profiles.nav_preset` 컬럼과 값 `super`가 이미 있어 마이그레이션 없이 쓸 수 있다 — 다만 이 컬럼은 지금 "레거시, 화면을 가르지 말 것"으로 적혀 있으므로, 다시 쓰기로 했다는 사실과 쓰는 값을 주석과 문서에 남긴다. 설정 › 회원에서 최고 관리자가 켜고 끈다.
3. 숨김은 **메뉴와 눈에 보이는 목록에서만** 적용한다(D2): 사이드바, 모바일 메뉴, "기타" · "숨긴 탭 N" 묶음, ⌘K 명령 목록. 주소를 직접 치면 지금처럼 열린다. 화면 차단("deny")을 되살리지 않는다. 데이터 접근은 지금처럼 각 API의 역할 검사가 막는다.
4. `getAccessibleAdminNavItems`는 지금 "숨긴 항목까지 전부 돌려준다"가 불변식이고 ⌘K · active 판정 · 모바일 헤더 라벨이 여기에 기대고 있다. ⌘K 목록만 따로 거르고 이 함수의 반환은 바꾸지 않는다(주소로 들어간 화면에서 머리줄 라벨이 비지 않게).
5. 착지 경로를 같은 파일의 함수 하나로 정하고, 로그인(`app/admin/login/page.tsx`)과 `/admin`(`app/admin/page.tsx`)이 이 함수만 쓴다. 간소 사이드바 계정은 `/admin/branch/ledger`로 간다. "Overview는 숨길 수 없다"(`UNHIDEABLE_NAV_HREFS`)는 "그 계정의 착지 화면은 숨길 수 없다"로 바꾼다.
6. 간소 사이드바에서 범주 소제목 · 빈 "기타" 묶음 · "사이드바 편집" 진입점이 남지 않게 한다. 항목이 둘뿐이므로 접은 모습(아이콘만)도 함께 본다 — 장부 표가 가로를 더 넓게 쓴다(시안 1 · 4).
7. `tests/admin/nav-access*.test.ts`, `nav-override-pin.test.ts`, `nav-route-coverage.test.ts`의 "전원 동일" 전제를 고친다. "착지 경로는 그 계정에게 숨김이 아니다" 불변식 테스트를 새로 넣는다.
8. 문서를 함께 고친다: [Admin 지침 맵](admin-guidance-map.md) §2, [플레이북](playbook/README.md) §3 "사이드바는 전원 동일하다", [어드민 탭 재구성](admin-tab-restructure-2026-07-29.md), `admin-nav-access.ts` 머리 주석(2026-09-10 결정을 무엇으로 왜 바꿨는지).

끝난 기준: 일반 계정으로 로그인하면 장부가 열리고 메뉴에 두 항목만 보인다. 최고 관리자와 지정 계정은 달라진 것이 없다.

### W2. 장부 첫 화면 넓게 — 확인 목록

이 화면은 **다른 브랜치에서 이미 작업 중**이다. 여기서는 새로 지시하지 않고, 그 작업물을 볼 때 확인할 목록만 둔다. 기준 그림은 디자인 시안 1이다.

- [ ] 장부를 열면 표가 화면 위쪽 1/4 안에서 시작한다(표 위는 두 줄 이내)
- [ ] 표가 가로를 끝까지 쓴다 — 좌우 여백과 사이드바가 표를 좁히지 않는다
- [ ] 1080px 높이 화면에서 20행 이상 보인다(행 높이 28px 안팎)
- [ ] 행이 한 줄이다 — 고객명 아래 `담당자 · 지역` 보조 줄이 없다
- [ ] 담당 열이 있고, 지역 열은 뒤쪽에 있다
- [ ] 잘린 글자에 마우스를 올리면 전체가 보인다
- [ ] **[매출 난 것만]** 이 표 바로 위에 있고 한 번 클릭으로 된다(선택한 월 합계가 0보다 큰 행만)
- [ ] 머리줄 탭이 **DSH · 장부** 순서이고, 메뉴를 누르면 장부가 먼저 열린다(D4)
- [ ] 보드 · 콕핏 탭이 일반 계정에게 보이지 않는다(주소 `?lens=`로는 열림)
- [ ] 요약 띠 · 상태 줄 · 묶기 · 칩 · 범례가 지워지지 않고 펼치기 뒤에 있다
- [ ] 기본 필터가 로그인한 본인 담당이다
- [ ] 칸에 숫자를 치고 Enter 하면 저장된다
- [ ] 동기화가 멈췄을 때의 경고 띠는 접히지 않고 그대로 보인다

[Classin KR Team 스킬](../../.codex/skills/classin-kr-team/SKILL.md)의 "요약 개선 시 차트를 접어 축소하지 않는다"는 성과 화면(`/admin/branch`)을 겨냥한 규칙이다. 장부(입력 화면)는 표가 먼저이고 요약은 접어 둔다는 점을 W5의 규칙 수정 때 스킬 문서에 한 줄 적는다.

### W3. 시트 모양의 건별 표 (L6 · L7)

담당: 그로스/CRM 파트
선행 결정: D5 / 선행 작업: W0, W2 브랜치 병합

지시:

1. 기본 표를 **건별 평면 표**로 바꾼다. 시트 '2. REV'와 같은 열 순서, 같은 행 단위(같은 기관이 여러 건이면 여러 줄)로 맞춘다. 주차 검수 표(`ledger/RevMatrix.tsx`)가 시트와 가장 가깝다 — 고객 그룹 펼치기를 걷어내고 품목 행을 평면으로 펴는 쪽이 새로 만드는 것보다 빠를 것으로 본다(추정, 착수 전 확인).
2. 시트의 실제 열 구성과 한 화면에 보이는 행 수를 먼저 캡처해 기준으로 삼는다. "유사도 90%"는 이 캡처와 나란히 놓고 판단한다.
3. 지금의 고객 합산 표(월 요약)는 **기관별 뷰**로, 담당자 행 표(`ManagerTable`)는 **매니저별 뷰**로 남긴다. 둘 다 조회용이다. 기관별 뷰는 가나다순 정렬을 준다.
4. 건별 표에서 Enter 입력과 본인 담당 기본 필터가 지금과 똑같이 동작하는지 확인한다.

끝난 기준: 시트를 쓰던 매니저가 설명 없이 자기 행을 찾아 금액을 넣는다.

### W4. 견적 문서 — 탭 셋 · 첫 화면은 템플릿

담당: 견적 문서 담당 세션
결정: D8 닫힘 / 선행 결정: D9

지시:

1. 탭을 **견적서 · 계약서 · 히스토리** 순서로 둔다. SW 견적 코드 · 영수증 · 총판 미수금은 `DOCUMENT_TABS`에서 지우지 말고, **전체 사이드바를 보는 계정(W1과 같은 기준)에게만** 보인다(D8). 일반 계정에게 숨긴 탭도 `?tab=` 주소로는 열려야 한다(총판 정산 화면에서 들어오는 링크가 끊기지 않게).
2. **견적서 탭의 첫 화면을 템플릿 고르기**로 바꾼다. 기본 템플릿(`lib/standard-quote-template.ts`)과 팀 템플릿(`quote_team_templates`)을 카드로 늘어놓고, 누르면 작성기(`QuickQuoteComposer`)가 그 템플릿으로 열린다. 단종 처리된 템플릿은 내놓지 않는다. 헤더의 작성 버튼 3종(SW 단독 · HW · HW 세부 템플릿)은 이 화면으로 합친다.
3. 지금의 견적 목록(단계 묶음 + 상세)은 **히스토리 탭**으로 옮긴다. 기존 `?tab=hardware&quote=<id>` 주소는 히스토리의 그 견적으로 이어져야 한다 — 공유한 링크와 알림에서 들어오는 경로다.
4. 계약 전환한 견적이 계약서 탭에 보이는지 확인한다(§3.2). 안 보이면 탭 정리 전에 보고한다.
5. 이 화면은 지금 다른 세션이 버그를 고치고 있다(§6). 같은 파일을 건드리기 전에 그 브랜치와 합친다.

끝난 기준: 견적·문서를 열면 템플릿이 보이고, 템플릿 하나를 눌러 견적서를 만들어 저장하면 히스토리에 나타난다.

### W5a. 확도 5단계로 변경 · 규칙 수정 (진행 확정, 색만 시안 뒤 결정)

담당: 그로스/CRM 파트 + 플랫폼 파트(마이그레이션)
선행 결정: D6(색), D7(전환표 · 기본 확도 · 수금 표시 방법)

지시:

1. 단계는 **수금 · 100% · 70% · 40% · 10%** 다섯 개로 고정한다. 단계 수와 이름은 타입으로 고정하고, 각 단계의 % 값은 설정값 하나로 둔다.
2. 색은 디자인 시안 2의 A · B · C 중 고른 것을 쓴다. 고른 뒤 [DESIGN.md](../../DESIGN.md) "확도 신호 토큰"과 `lib/branch/confidence-tokens.ts`를 같은 커밋에서 고친다. 파랑 계열을 늘리는 안(B)을 고르면 "냉색 금지" 예외 범위가 넓어지므로 DESIGN.md의 예외 설명도 고친다.
3. 기존 값은 D7의 전환표대로 옮긴다(추천: 확정 → 100%, 고확도 → 70%, 예정 → 40%). 마이그레이션은 [DB 마이그레이션 런북](db-migration-runbook.md)을 따르고, 되돌릴 수 있게 옛 값을 남긴다.
4. **수금 · 100%는 사실, 70 · 40 · 10%는 예측**이라는 구분을 계산식에 반영한다. 고칠 규칙 문서:
   - [월별 목표·채움 차트](revenue-monthly-goal-chart.md) — 달성률 규칙(지난달은 확정, 이번 달은 확정+고확도, 미래 월은 전부)을 5단계 기준으로 다시 적는다.
   - [Classin KR Team 스킬](../../.codex/skills/classin-kr-team/SKILL.md) — 확도 단계와 "장부는 표가 먼저" 한 줄.
   - [DESIGN.md](../../DESIGN.md) — 확도 토큰 표와 "3단 확도" 문구, 확도 선택 토글(3버튼 → 5버튼).
5. 입력 단축키(지금 E/H/C 세 개)와 확도 선택 토글을 5단계에 맞춘다. 새 금액의 기본 확도는 D7(추천 40%).
6. 요약 띠 · 목표 차트 · 보드처럼 "확정 / 고확도 / 예정" 세 칸으로 그리는 곳을 모두 찾아 5단계 또는 "사실 / 예측" 두 묶음으로 바꾼다. 바꾸지 않은 곳이 남으면 합계가 화면마다 달라진다.
7. 시트는 글자색이 3가지뿐이다. 시트와 대조하는 동안 5단계를 시트의 3색으로 어떻게 읽을지(수금 · 100% → 빨강, 70% → 파랑, 40% · 10% → 검정) 동기화 파서와 쓰기 쪽 매핑(`lib/branch/sheet-writeback/colors.ts`)에 함께 반영한다.

끝난 기준: 장부 · DSH · KR Team 화면의 합계가 서로 맞고, 기존 데이터의 단계별 합계가 전환 전후로 같다(확정 합 = 100% 합).
