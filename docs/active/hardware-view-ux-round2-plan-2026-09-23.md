상태: 사용성 평가 완료 · 기획 확정(2026-09-23) · 이번 라운드 구현 완료(2026-09-23) · 라운드 3 첫 묶음(H-3·H-9·H-10·P-5·P-6·P-8·P-13) 시안·구현 완료(2026-09-24, §9) — 항목별 상태는 §5·§9 표가 정본

## 1. 평가 방법

- **코드 기반 휴리스틱 평가.** 운영 mutation(가져오기·확정·업로드)을 브라우저에서 실행하지 않는 규칙 때문에 실측 대신 코드 판독으로
  했다. 영역 6개(홈·입출고/입고표·내역·빠른 기록·샘플·싱크)를 병렬로 판독해 **123건**을 찾았고, 심각도 상과 데이터 정합 항목은 전부
  코드로 다시 확인했다(판독자 재검증 + 작성자 재확인). 붙여넣기·숫자 파서는 임시 테스트로 실제 입력을 돌려 확인했다(I-4·I-9·I-13).
- **판단 기준 — UI UX Pro Max(v2.13.0).** 저장소에 없는 스킬이라 공개 사본을 받아 `references/quick-reference.md` 전 규칙으로 점검했다.
  이번 평가에 많이 쓰인 규칙:

  | 규칙(스킬 ID) | 하드웨어 탭에서 본 것 |
  | --- | --- |
  | `export-option`(Charts & Data) | 하드웨어 폴더 전체에 CSV·TSV·클립보드 코드가 0건 — 읽은 숫자를 가져갈 길이 없다 |
  | `empty-states`·`error-state-chart`·`error-recovery` | 첫 조회 실패가 "원장 없음 — 시트 가져오기를 먼저 실행하세요"로 보여 **조회 오류에 파괴적 동작을 권한다** |
  | `confirmation-dialogs`·`undo-support` | 원장을 교체하고 어드민 확정까지 취소하는 가져오기에 확인이 없다(업로드·복원에는 있다) |
  | `submit-feedback`·`loading-buttons`·`timeout-feedback` | 잠금 없는 가져오기, 성공·실패 두 톤뿐인 결과, 무한 대기 |
  | `deep-linking`·`state-preservation`·`back-behavior` | 페이지·단건·유닛·입출고 하위 보기가 URL에 없다 |
  | `focus-management`·`focus-not-obscured`·`modal-escape` | 상세·거래이력·유닛 시트·CRM 확인 모달이 포커스를 옮기지 않는다 |
  | `toast-accessibility`·`aria-live-errors` | 전역 성공·오류 배너에 role·aria-live가 없다 |
  | `redundant-entry` | 샘플 전환 시 고객사를 다시 친다, 풀에서 고른 유닛을 시트에서 다시 고른다 |
  | `touch-target-size`·`web-target-size` | 체크박스 16px, md 이상 행 버튼 20px |
  | `color-not-only`·`number-tabular`·`truncation-strategy` | 90일+ 색만, 잘린 고객사명에 title 없음 |

  스킬 검색(`--domain ux`) 결과 중 주제와 맞은 것은 "Bulk Actions(Data Entry)"와 "Keyboard Navigation·Focusable Error Summary"였다.
  "inventory data table export", "stale data refresh indicator", "copy to clipboard feedback"은 반환 결과가 주제와 맞지 않아 스킬 규약대로
  "매치 없음"으로 두고 빠른 참조 규칙(`export-option`·`loading-states`)으로 대신했다. 색·타이포는 스킬 추천 팔레트가 아니라 DESIGN.md가 정본이다.
- **기존 결정 준수.** 라운드 1 기각 항목, reference §8-6(가져오기 때는 시트가 이긴다), 샘플 유닛 정본(§3-8), 확정 순차 실행(§3-3)과
  충돌하는 제안은 채택하지 않았다.

## 2. 뷰별 장점·특징 — 무엇을 가장 잘하는 뷰인가

모든 뷰에 같은 기능을 붙이면 뷰를 나눈 이유가 사라진다. **그 뷰가 이미 잘하는 일을 더 잘하게** 만드는 것만 넣는다.

| 뷰 | 이미 잘하는 것 | 이번에 키우는 방향 | 넣지 않는 것 |
| --- | --- | --- | --- |
| **홈** | 3초 요약 밴드(신선도 판정 한 함수 공유), 부분·일괄 확정 + Shift 범위 + "30일+ 미확정", 확정 경로 전체 잠금, CRM 대사 펼칠 때 1회 조회 + 겹침 2회 누르기 | **숫자를 믿게**: 오류≠빈 상태, 부족 이중 계상 제거, 원장이 바뀌면 대사 목록 재조회. **본 것을 들고 나가기**: 큐·재고 TSV/CSV | 확정 되돌리기(엔드포인트 없음), 대사 자동 조회(원장 스캔 비용), 새 타일·차트 |
| **입출고 · 입고** | lot 하나에 품목·수량·단가·금액, USD 기준 + CNY 병기, 전 품목 대수 병기 | **lot 허브**: 최신 lot이 위로, 구성 복사(입고표 붙여넣기 형식 그대로), 내역으로 가기 | lot 카드 직접 수정(내역 소관), 화면 잔량 재계산 |
| **입출고 · 출고** | 회계연도 규약 명시, 판매유형 칩, 고객사 → 거래이력·장부 딥링크, 실판매만 매출 | 기간 집계 TSV/CSV, 하위 보기·기간 URL 보존 | KRW 환산, 예측 |
| **내역** | 필터 11축 URL 왕복, 적용 칩 개별 해제, "필터 0건" vs "데이터 없음" 구분, 2,000건 상한 공개 + 더 불러오기 | **찾기 → 확인 → 가져가기**: 필터 결과 전체 CSV·TSV, 단건 링크(`?m=`)·페이지 보존, 취소 행 실제로 보기(감사 추적), 시리얼 검색 | 열별 다중 정렬(묶음 구조), 인라인 편집, 가상화 |
| **빠른 기록 시트** | 열 때마다 건 단위 초기화, 저장 대기 없음, 연속 기록, 고객사·품목 고르기, CRM 확인 게이트, 바구니 부분 실패 | 프리셋 전환 시 값이 **의미가 같은 칸**으로(도착 ↔ 대여 고객사), 샘플은 단건 전용, CRM 조회 경합 차단, 복제·붙여넣기 정확도 | 사람별 기억값, 자동 재전송, CRM 자동 링크, 파생 숫자 낙관 반영 |
| **한 화면 입고표** | 새 물량 추천, 최근 lot 칩, 데이터로 채우는 수입자·보관처·단가, 완전일치 붙여넣기, 부분 실패 격리, 초안 배너 | 불확실한 값을 입력 단계에서 드러내기(읽지 못한 단가·미적용 붙여넣기·결과 불명 실패), 행 키·lot 표기 안정화 | 서버 lot 형식 강제, 초안 무음 복구 |
| **사무실·샘플** | 순수 모델 + 테스트, "–"와 0 구분, 옮길 수 없는 유닛 사전 표시, 서버 전부-아니면-전무 | 조회 실패와 "유닛 없음" 구분, 부분 실패 뒤 재조회, 권한 표시, 후속 연락 목록(대여중 TSV/CSV), 유닛 딥링크 | 원장 기반 숫자 추가, 행 안 유닛 편집 |
| **데이터 싱크** | 스냅샷 백업 후 교체, 시트 우선 정리(§8-6), 신선도 단계 판정 | **정직한 결과**: 잠금·결과 계약·즉시 만료·확인 단계, 미러 vs 원장 "가져오기 대기 N행", 진행 중·중단 구분 | RPC 본문 변경(§6-2 미적용 마이그레이션과 충돌), 자동 가져오기 |

## 4. 설계 메모 — 이번 라운드 핵심 항목

### 4.1 가져오기 결과 계약·잠금·즉시 만료 (S-1~S-7·S-13·S-14)

- **라우트** `POST /api/admin/hardware/import-sheet`(`maxDuration = 300`)
  1. 가져오기 잠금 — 10분 창 안의 `running` 이관 기록이 있으면 `{ outcome: "running", startedAt, stage: "lock" }`(200, 실행 없음).
  2. 시트 싱크 — `runAll({ trigger: "manual", sources: ["hw"] })`. 잠겨 있으면(`skipped`) 같은 `running` 응답. 결과대로
     `expireSyncCacheTags(...branchSyncBundles(result, ["hw"]))`. 싱크 실패면 가져오기 없이 `{ outcome: "failed", stage: "sync", ledgerChanged: false }`(500).
  3. 가져오기 — 성공이면 `expireSyncCacheTags("hardwareImport")`(`hardware-inventory`·`branch-hw`, `{ expire: 0 }`) 후
     `{ outcome: "done", import, sync, warnings? }`. 실패여도 만료(실패한 이관 기록이 신선도에 바로 보이게) 후 `{ outcome: "failed", stage: "import", ledgerChanged: false }`.
- 교체 RPC가 커밋된 뒤의 이관 기록 갱신 실패는 **실패가 아니라 경고**(`runRecordError`)다.
- 이관 기록 `raw`에 `origin`(sheet·ledger_file)·파일명·`mirror_rows`·`sheet_wins_voided_ids`를 남긴다(DB 변경 없음 — 이미 있는 jsonb).
- **업로드** `import-ledger`는 `maxDuration = 300`, 성공·실패 모두 `hardwareImport` 만료, `origin: "ledger_file"`.
- **복원**은 `hardwareImport` 만료 + 되살린 시트 우선 취소 건수(S-11).
- **화면**: `describeHardwareImportOutcome`(`lib/hardware/import-outcome.ts`) 하나가 문구·톤을 정한다. 결과는 `SyncOutcomeNotice`(role=status)로,
  실패는 오류 배너(role=alert)로. 실패·시간 초과여도 화면을 다시 불러온다(재전송은 하지 않는다).
- **확인 다이얼로그**(S-3): 현재 원장의 시트 이관분을 교체한다 · 시트가 다시 실은 어드민 확정은 취소된다 · 백업이 먼저 뜬다 ·
  마지막 이관이 원장 파일 업로드였으면 "업로드한 원장을 시트 기준으로 덮어씁니다"를 경고로.

### 4.2 신선도 — 이관 상태와 미러 대기 (S-5·S-9·H-11)

- `judgeImportFreshness(importRun, { lastSuccess })`가 상태를 다섯으로 가른다: 없음 · 성공 · **진행 중**(10분 창 안) · **중단**(창 밖 running) · 실패.
  경과일은 마지막 성공 이관 기준 — 실패 한 번에 "데이터가 언제 기준인지"가 사라지지 않는다. 기존 임계(7·21일)는 그대로.
- `judgeMirrorPending(importRun, mirror)`: 이관 기록의 `mirror_rows`와 지금 미러 행 수가 다르면 "시트에 원장과 다른 행 — 입고 ±a · 출고 ±b ·
  재고 ±c, 가져오기 필요"(경고). 같으면 "행 수 기준 변경 없음". 이전 이관(기록 없음)이면 미러 교체 시각만 보인다.
  행 수 비교라 같은 행 안의 값 수정은 잡지 못한다 — 문구가 "행 수 기준"임을 밝힌다.
- 대시보드 캐시는 HW 싱크(`branchHw` 묶음)와 가져오기(`hardwareImport`)가 즉시 만료하므로 미러 값을 캐시 안에 둬도 신선하다.

### 4.3 오류와 빈 상태를 가른다 (H-1·S-10·L-8·P-3)

- 첫 조회 실패(`!data && error`)면 탭 패널 대신 "하드웨어 데이터를 불러오지 못했습니다 · [다시 불러오기]"를 보인다. "가져오기를 먼저 하세요"는
  데이터가 실제로 비었을 때만.
- 샘플 유닛 조회 실패는 트래커·풀이 "유닛 없음"·무한 스켈레톤 대신 오류와 [다시 불러오기]를 보인다.

### 4.5 뷰별 입력 동선 (C)

- 내역: `page`·`m=<id>` URL(단건 딥링크로 상세 시트), 범위 밖이면 안내. 취소 모달은 상세 위에 뜨고 실패는 모달 안에.
  거래이력 → 상세 → 닫기 = 거래이력으로 복귀. 검색에 시리얼·출발지·보관처·수입자.
- 입출고: `sub=outbound`·`iq=`·`period=` URL. lot 카드 [내역]·[추가 입고], CTA 라벨이 하위 보기를 따른다.
- 빠른 기록: 샘플 전환 시 고객사 이동(Q-1), 샘플은 단건 전용(Q-2), 첫 포커스(Q-15), 필수 표시(Q-14), ⌘↵ 힌트(Q-20).
- 샘플: `?unit=<관리번호>` 유닛 시트 딥링크, 유닛 시트 대여·반환 안내 한 줄(P-9).
- 홈: 검색 카드 확정은 확인 다이얼로그 + 큐 입력값(H-5), 대사 목록은 원장이 바뀌면 다시 조회(H-4).

### 4.6 마이크로 편의 (D)

- 배너: 성공 = `role=status`, 오류 = `role=alert`, 둘 다 닫기 버튼(S-8·H-19·I-15·Q-18).
- 포커스: 상세·거래이력·유닛 시트는 열 때 닫기 버튼, 닫을 때 트리거로(L-2·P-11). CRM 확인 모달은 주 버튼(Q-6).
- 복원 확인은 `DeleteConfirmDialog`(H-17). 큐 체크박스 누름 영역(H-18). 칩 `aria-pressed`(L-13·E-8).
- 입력 정규화: NFKC + 단위 제거(I-13·Q-9), 추천 단가 대비(I-11), 90일+ 텍스트(P-16).

- 브라우저 실측(운영 계정)으로 포커스 이동·딥링크 착지·CSV 엑셀 열기를 한 번 확인한다 — 이번 라운드는 렌더 하네스가 없어 순수 로직 테스트와 기본 게이트로 검증했다.

## 7. 하지 않는 것

- **새 쓰기 엔드포인트** — 취소 행 조회(`scope=voided`)는 읽기다. 모든 기록은 `POST …/movements`·`PATCH …/movements/[id]`로만.
- **교체·복원 RPC 본문 변경** — §6-2 미적용 금액 마이그레이션이 같은 함수를 재정의한다. 복원의 취소 되살림은 앱 층에서 한다.
- **자동 가져오기·자동 재전송** — 가져오기는 사람이 확인하고 누른다. 시간 초과 뒤에도 재조회만 한다.
- **사람별 기억값 확장·행 확정 잠금 해제** — 라운드 1 결정 유지.
- ~~**FIFO 미리보기 서버 이관(H-3)**~~ — 라운드 3에서 했다(§9). 비용은 예정 행 × 품목 원장이고, 로트 없는 예정 행은 품목·수량별로 한 번만 계산한다.
- **드릴다운 pushState(H-16)** — 탭 전환 전체의 히스토리 규약을 바꾸는 일이라 따로 설계한다(3라운드).
- **새 색·토큰** — 전부 DESIGN.md 운영 상태 스케일과 웜 뉴트럴 안에서.
