# ClassIn CRM 구조·핵심기능 적용 기획 (사용성·편의성 최우선)

기준 시점: 2026-06-27
입력: ① 기라성 CRM 리서치(Salesforce/HubSpot/Zoho/모던 — [UI 스펙](crm-ui-layout-improvement-spec-2026-06-27.md)) ② 2개 시안(스크린샷 + `ClassIn CRM System.html`)
원칙: **똑같이 복제 ❌ — 구조(하위탭·핵심기능)만 흡수**, 우리 캐논([마스터 설계](../superpowers/specs/2026-06-27-crm-unified-master-design.md))에 안착.

---

## 1. 한 줄

시안의 **스캔성(플래그)·금액 서사(funnel)·전환 분석**을 우리 작업대에 흡수하되, 시안의 좌측 4-nav를 새 탭으로 만들지 않고 **기존 6탭(현황·고객·기록·돈흐름·인사이트·연동)에 매핑**한다. 모든 적용은 **3초 스캔 · 클릭 최소 · act-in-place · 일관 배지 어휘**를 만족해야 한다.

---

## 2. 구조 매핑 — 시안 nav/세그먼트 → 우리 캐논 (신규 top-level 탭 0)

| 시안 좌측 nav | 우리 안착 위치 | 비고 |
|---|---|---|
| 대시보드 | **현황**(작업대 홈) | 이미 재배치 완료 |
| 고객 DB | **고객/통합** | 플래그·점수·세그먼트로 보강 |
| 분석·인사이트 | **인사이트** | 전환 퍼널·채널별 전환율 추가 |
| 팀 성과·KPI | **현황 하단 KPI 보드** + 인사이트 | ARR/MRR·활동량·응답 추가 |
| 저장된 세그먼트 | **고객 탭 퍼시스턴트 칩** | 칩 구현됨 → 카운트·prominence 격상 |

→ **결론: 시안의 IA는 우리 6탭에 100% 흡수된다. 새 탭 불필요(캐논 불변식 유지).** 시안의 가치는 nav가 아니라 *그 안의 핵심 기능*에 있다.

## 2.5 확정 IA 방향 (2026-06-27 결정 · 마스터 설계 §3 개정)

**결정**: CRM 하위탭을 시안처럼 좌측으로 — **글로벌 `AdminSidebar`에서 CRM 섹션을 확장**하는 방식으로 적용한다. (대안: CRM 전용 좌측 rail / 하이브리드 / 현행 상단 탭 — 모두 기각.)

**타깃 구조**:
```
고객 관리
 └ CRM ▾                       ← /admin/crm* 진입 시 자동 펼침(활성 섹션만)
     · 현황      /admin/crm
     · 고객      /admin/crm/customers/unified
         ├ 만료 임박 (N)         ← 저장된 세그먼트(카운트, 원클릭 필터)
         ├ 30일+ 미접촉 (N)
         ├ 고전환 리드 (N)
         └ 업셀 후보 (N)
     · 기록      /admin/crm/activity
     · 돈흐름    /admin/crm/deals
     · 인사이트  /admin/crm/insights
     · 연동      /admin/crm/matching   (흐리게, 유지보수)
```

**상단 `CrmSubnav` 처리(결정)**: primary 6탭은 **제거**(사이드바로 이전). **컨텍스트 sub-tab만 본문 상단에 유지**(고객: 통합·리드·원천 / 돈흐름: 매출·오더·KPI) — 페이지 레벨 맥락이라 본문이 적합.

**캐논 영향**: 마스터 설계 §3 "상단 탭" IA → **"사이드바 확장 + 컨텍스트 sub-tab"** 으로 배치 개정. 섹션 수·구성 불변(새 top-level 목적지 0 — 불변식 유지). 변경은 *배치만*(top → left-expand).

**⚠ 시퀀싱 제약**: 구현은 공유 `components/admin/AdminSidebar.tsx`를 수정한다. **동시 하드웨어 세션의 미커밋 변경이 이 파일에 있는 동안 착수 금지**(충돌·클로버 위험). 그 변경이 커밋된 뒤 진행. 그 전까지는 사이드바를 안 건드리는 CRM 작업(플래그 시스템 등)만.

**구현 분해(착수 가능 시)**:
1. `AdminSidebar` — NAV에 CRM children 정의 + 활성 섹션 expand + 세그먼트 카운트(통합 API `summary.viewCounts` 재사용).
2. `app/admin/crm/layout.tsx` + `CrmSubnav` — primary 탭 렌더 제거, 컨텍스트 sub-tab 로직만 유지.
3. 모바일 — 글로벌 사이드바의 기존 모바일 동작(햄버거/드로어) 그대로 상속(무료).
4. 마스터 설계 §3 문구 갱신.

## 3. 핵심 적용 요소 (사용성 임팩트 순)

각 항목: **무엇 / 어디 / 왜(사용성) / 현 상태 / 캐논핏**

### A. 통합 플래그·배지 시스템 ★ 최고 레버리지
- **무엇**: 고객마다 일관된 배지 — `VIP` `핫` `신규` `만료임박` `미수` `휴면` `클레임` `업셀`. 시안의 스캔성 핵심 장치.
- **어디**: 고객 리스트 행 · 우선순위 큐 칩 · 360 헤더 — **한 번 정의해 3곳에서 동일 어휘 재사용**(HubSpot 하드캡 하이라이트 패턴).
- **왜**: 매니저가 리스트를 **3초 스캔**으로 "누가 급한가"를 색·라벨로 즉시 판별. 현재는 score 숫자 + reason 텍스트라 스캔이 느림.
- **현 상태**: 신호는 대부분 **이미 데이터로 파생 가능** — `VIP`=LTV/계약액 임계, `핫`=score≥68, `신규`=lifecycle new_lead, `만료임박`=serviceRisk soon/expireAt≤30d, `미수`=outstanding>0, `휴면`=updatedAt 30일+, `업셀`=active+balance, `클레임`=cs_issue 이벤트. (클레임·VIP만 임계/소스 확정 필요)
- **캐논핏**: 파생값은 provenance 표기(§8) · DESIGN 팔레트 pastel pill · 분모불명 추정 금지(절대값만).

### B. 저장된 세그먼트 → 퍼시스턴트 빠른 필터
- **무엇**: 만료임박/미접촉/고전환/업셀 + 카운트를 고객 탭 상단 **항상 보이는 1급 필터**로.
- **어디**: 고객/통합 탭(칩 구현됨) — 카운트·시각 prominence 격상, 모바일 가로 스크롤.
- **왜**: 시안처럼 "오늘 칠 대상 묶음"에 **원클릭 진입**. 검색보다 빠른 일상 동선.
- **현 상태**: ✅ 칩+카운트 구현됨. 격상(아이콘·강조)만 남음.
- **캐논핏**: §4 작업대 우선; 신규 탭 없이 sub-filter.

### C. 돈흐름 funnel 확장 — 계약액 → 수납 → 미수 → **갱신/업셀 예상**
- **무엇**: 현재 `견적→오더→수납`에 시안의 **갱신 예상·업셀 기회** 단계를 더해 *돈의 미래*까지 한 줄에.
- **어디**: 360 드로어 돈흐름 섹션 + 돈흐름 탭.
- **왜**: 매니저가 "받을 돈(미수) + 키울 돈(갱신·업셀)"을 동시에 봄 → 다음 액션이 자명.
- **현 상태**: 견적→오더→수납 funnel 구현됨. **갱신 예상**은 serviceRisk 만료 + 직전 계약액 파생, **업셀**은 사용량/잔액 — 일부 추정이라 "예상"으로 명시.
- **캐논핏**: 공식(NEO 수납/오더) vs 파생(갱신 예상) 구분 표기; 추정은 confidence 없이 확정처럼 금지.

### D. 분석·인사이트 — 전환 퍼널 + 채널별 전환율
- **무엇**: 리드→상담→견적→오더→수납 **퍼널** + 유입 채널(웹/행사/광고)별 **전환율** 비교.
- **어디**: 인사이트 탭.
- **왜**: 시안의 "전환율 2.3배" 같은 채널 인사이트로 *어디에 시간을 쓸지* 결정. 현재 인사이트는 flat link-list.
- **현 상태**: 데이터(leads source/status, deals stage)는 있음 — 집계·시각화 신설 필요. **후속**(중간 규모).
- **캐논핏**: 개인 랭킹 ❌ → 채널·퍼널 단계 관점; freshness 표기.

### E. 팀 성과·KPI — ARR/MRR · 활동량 · 응답 골든타임
- **무엇**: 시안의 ARR/MRR, 활동량(콜·미팅 수), **응답 골든타임/48h+ 미응답**을 KPI 보드에 추가.
- **어디**: 현황 하단 KPI 보드(총/팀별/개인별) + 매니저 리포트.
- **왜**: 지사장 코칭 + "놓친 응답"을 수치로. 응답 골든타임은 리드 전환의 핵심 레버(우리 lead-activity에 신호 존재).
- **현 상태**: KPI 보드(총/팀별/개인별) 구현됨. ARR/MRR·응답 지표 추가는 데이터 매핑 필요. **부분/후속**.
- **캐논핏**: 감시 ❌ → 막힌 고객·놓친 응답 중심(§10).

### F. 고객 바로 가기 (편의) — ✅ 일부 완료
- 최근 본 고객 원클릭 칩(완료). 다음: ⌘K 팔레트에 고객 직접 점프, 검색 결과 인라인 미니카드(연락처·다음액션·위험 1줄), 즐겨찾기 핀.

## 4. 사용성·편의 설계 원칙 (이 기획의 "최대 고려")

1. **3초 스캔** — 색·배지 우선, 숫자·텍스트는 보조. (플래그 시스템 A)
2. **클릭 최소 / act-in-place** — 리스트·큐를 떠나지 않고 처리(완료·내일·콜). 이미 적용 중.
3. **일관 어휘** — 같은 배지/색/라벨을 큐·리스트·360에서 동일하게. 인지 부하 ↓.
4. **빠른 진입** — 검색(완료)·바로가기(완료)·세그먼트 칩(완료)·⌘K(후속) 4경로.
5. **출처·신선도** — 공식(NEO) vs 파생(예상/추천)을 색·라벨로 구분. 추정은 confidence 없이 확정처럼 금지.
6. **모바일 우선** — 배지/칩 가로 스크롤, 2-col은 데스크톱 향상.
7. **빠름** — 첫 화면은 캐시 스냅샷, 전수 derive·느린 외부조회 금지.

## 5. 단계 로드맵

**1차 (즉시·기존 데이터로 닫힘)**
- A. 플래그 배지 시스템 (리스트·큐·360 공통 컴포넌트) ← **최고 우선**
- B. 세그먼트 칩 prominence 격상
- F. 검색 결과 인라인 미니카드 + ⌘K 고객 점프

**2차 (집계 신설)**
- D. 인사이트 전환 퍼널 + 채널 전환율
- C. 돈흐름 funnel에 갱신/업셀 예상 단계
- E. KPI에 ARR/MRR·응답 골든타임

**3차 (백엔드)**
- 위험 read model(F5) 기반 홈 위험 strip · 큐러너 'Start N tasks' · 딜 칸반(옵트인)

## 6. 비범위 / 캐논 가드
- 신규 top-level 탭 ❌ (시안 4-nav는 6탭에 매핑).
- 감시형 auto-capture(이메일 오픈·웹 추적) ❌ — operator-authored + consent.
- 분모 불명확 weighted/ratio/예측 ❌ — 절대값·confidence만.
- 통화 혼합 합산 ❌ (매출 dedup 철칙).
- 무거운 Salesforce식 stage 게이트 ❌ — Deal Lite 유지.
