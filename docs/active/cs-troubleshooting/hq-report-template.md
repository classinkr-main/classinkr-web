# HQ 보고 양식과 에스컬레이션 규칙

중국 본사(HQ)에 WeCom으로 문의할 때 쓰는 3개 언어 양식, 에스컬레이션 규칙, 영역별 받는 곳(역할명), 자주 나오는 중국어다. 원본은 사내 `HQ_Error_Report_Template_v2.md`이며 구버전 `오류보고_템플릿_본사기술팀.md`는 폐기됐다.

- `{{ }}` 자리표시자는 WeCom 발송문을 쓸 때만 채운다. 채운 값(계정, ID, SN, IP 등)은 이 저장소·코파일럿 적재 데이터에 남기지 않는다.
- 담당자 실명은 이 저장소에 두지 않는다. 받는 곳은 역할명으로만 적는다.

## 1. 3개 언어 템플릿

중국어(WeCom 발송용), 영어, 한국어(내부 참조) 순서이고 각각 별도 코드 블록에 넣는다. 중국어만 요청받아도 한국어판을 같이 낸다.

템플릿 사용 규칙

- 중국어판과 영어판의 시각은 중국 시각으로 적는다. 한국어판은 내부 참조용이라 KST로 둔다.
- 하드웨어·전자칠판 건은 식별자를 EEO Account, UID, 제품 SN, 설치일, 세대로 바꾼다.
- 여러 플랫폼에서 교차 재현한 건은 고객 환경과 재현 환경을 블록으로 나누고, 환경별 결과를 한 줄씩 적고, 대조 실험에서 나온 단서를 따로 뺀다(D-01).
- 확인을 요청할 항목이 여럿이면 번호를 붙인다. HQ가 일부만 답했을 때 어느 것이 남았는지 다시 요청하기 쉽다(D-19).
- 템플릿에서 해당하지 않는 줄(내부 테스트 수치, 콘솔 네트워크 정상)은 뺀다. 콘솔 지표가 일부 비정상이면 구간별 수치를 그대로 적는다(D-19).
- 최신 버전은 매월 바뀌므로 이 문서에 적어 두지 않는다. 최신 여부는 접수 시점에 확인해 적고, 케이스 기록에 "최신"으로 적힌 버전은 그 당시 기준으로만 읽는다.

## 2. 에스컬레이션 규칙

- **넘기기 전에 지사에서 할 수 있는 확인을 끝낸다.** 콘솔 지표, 정상 대조군, 사내 재현. 설정 문제로 판명되면 넘기지 않는다(D-04, D-13, D-14).
- **세 언어로 쓴다.** 중국어(WeCom 발송용), 영어, 한국어(내부 참조) 순서이고 각각 별도 코드 블록에 넣는다. 중국어만 요청받아도 한국어판을 같이 낸다.
- **구조는 네 부분이다.** 인사와 한 줄 요청, 식별자 불릿, `Error info :` 블록(증상, 수치, 콘솔 상태, 관련 설정), 추정 원인 한 줄과 확인 요청. 확인 요청이 여럿이면 번호를 붙인다. 긴 서술 문단을 넣지 않는다. 불릿은 마크다운 기호 대신 `-`를 쓰고 이메일·계정은 링크 없이 원문 그대로 둔다.
- **분류를 적는다.** 버그는 `缺陷`, 기능 요청은 `需求`. 표시가 없거나 HQ가 `建议`(제안)로 받으면 백로그로 밀린다. 버그와 기능 문의를 한 메시지에 섞지 않는다(D-01, S-11, S-28). 원인이 확정되지 않은 결함 의심 건은 `疑似缺陷`로 적은 선례가 있다(S-36).
- **단말 건은 기기, OS 버전, 클라이언트 버전, 최신 여부를 같이 적는다.** HQ가 가장 먼저 되묻는 항목이다.
- **기재하지 않는 값**: Device ID, Client IP, Server(미디어·접속 서버명), Owner(영업 담당), 숙제 ID. 숙제 ID처럼 조회 키가 없을 때는 기관명, 담당자 UID, 대상 이름, 기간으로 대신한다.
- **예외**: 그 값이 증상의 직접 근거면 적는다. IP 충돌이 원인일 때의 Client IP, 서버·경로가 의심 지점일 때의 Media Server와 Port가 그렇다. 기준은 "그 값을 빼면 증상 설명이 성립하는가"다(D-02, D-19). 게이트웨이 구간은 정상인데 서버 연결만 나쁜 끊김 건은 서버와 경로가 의심 지점이므로 Media Server, Port, Client IP를 적는다(D-19).
- **지사 콘솔의 시각은 항상 KST다. HQ에 보낼 때는 중국 시각(UTC+8)으로 바꿔 적는다.** 중국 시각 = KST − 1시간(KST 18:00 → 17:00)이고 시간대를 같이 적는다. HQ가 보내는 캡처의 시각도 UTC+8이므로, 받은 시각은 1시간을 더해 KST로 읽는다(D-19, D-21). 케이스 기록에 실린 과거 발송문은 KST로 적은 것이 많으니 형식만 참고한다.
- **API 건은 콘솔 API 로그 번호로 요청을 지목한다.** 일부러 넣은 비정상 요청(프로브)은 미리 알리거나 빼고 낸다. 프로브 로그 때문에 오진이 난 선례가 있다(S-19).
- **계정, 수업명, 시각을 맨 위에 둔다.** HQ가 다른 수업을 보고 답한 선례가 있다(S-03).
- **선임 담당자에게는 완충 표현을 쓴다.** `百忙之中打扰您`, `冒昧`, `请教`. 기술팀에 처음 문의할 때 쓴 선례가 있다(D-18).
- **재문의는 앞선 회신을 한 줄로 인용하고, 그 회신이 설명하지 못하는 지표와 답받지 못한 항목을 번호로 다시 묻는다.** 小助手가 답한 건은 그 대화에 이어서 묻고, 小助手가 담당자를 안내했으면 그 담당자에게 직접 묻는다(D-05, D-19).
- **같은 담당자와 여러 건이 동시에 진행되면 건명을 적는다**(D-03과 D-05가 같은 대화창).
- **담당자가 바뀌면 첨부를 처음부터 다시 보낸다**(S-11).
- **EEO 베트남 기술지원의 답은 HQ 공식 입장이 아니다.** 확정이 필요한 것은 HQ 제품·개발 담당에게 따로 확인한다.
- **파일 전달은 WeDrive로 한다.** 화질 비교용 영상은 다시 인코딩하지 않는다. 학생 얼굴·음성이 있을 수 있어 링크는 지정 공유로 한다(D-16).
- **HQ 원격 지원(AweSun)의 식별 코드와 인증 코드는 담당자에게 1:1로만 전달한다.** 단체방에 올리지 않는다(D-16).
- HQ 답변에 `应该`(아마), `按理说`(이론상), `正常来说`(정상적으로는)가 붙어 있으면 추정이나 일반론이다. 고객에게 옮기기 전에 확답을 다시 받는다(D-16, D-05).
- HQ 1차 답변이 "네트워크 문제"여도 그대로 받지 않고 콘솔 지표와 시각을 대조한다(S-03, S-10, D-19).
- API와 기능 사양에 관한 HQ 답변은 공식 문서(docs.eeo.cn)와 교차 확인한 뒤 고객에게 전달한다.
- TAPD는 지사 계정이 읽기 전용이라 등록은 HQ에 대리 요청한다.

## 4. 자주 나오는 중국어

| 중국어 | 뜻 |
|---|---|
| `缺陷` | 버그 |
| `需求` | 기능 요청 |
| `建议` | 제안(표시하면 백로그로 밀린다) |
| `疑似缺陷` | 결함 의심(원인 미확정) |
| `疑似` | 의심됨 |
| `闪退` | 강제 종료 |
| `红外` | 적외선(WeCom 자동 번역이 "red"로 낸 선례) |
| `特写` | 트래킹(클로즈업). 자동 번역이 "특필"로 낸 선례 |
| `全景` | 파노라마 |
| `回放` | 녹화 재생 |
| `录播` | 녹화 수업(미리 올린 영상으로 하는 수업) |
| `小助手` | HQ 서비스 1차 접점 계정 |
| `排期` | 개발 일정 배정 |
| `应该` / `按理说` / `正常来说` | 아마 / 이론상 / 정상적으로는 — 추정·일반론 표시 |
| `百忙之中打扰您` / `冒昧` / `请教` | 선임 담당자용 완충 표현 |
| `班级` / `课程` / `单元` / `机构` | 코스 / 과정 / 단원 / 기관 |
| `云端录制` / `录制现场` / `本地录制` | 교실 녹화(클라우드) / 카메라 녹화(현장 녹화) / 로컬 녹화 |
