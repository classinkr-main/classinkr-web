## 먼저 받을 값

1. **조회 키**: 수업명, 사용자 계정, 수업 시작 시각(월·일·시). 계정은 반드시 받는다.
2. **받은 계정이 맞는지 본다.** Identity로 교사·학생 계정을 확정하고, 같은 기관 여러 건이 겹치면 Client IP와 deviceName으로 강의실을 확인한다(D-21).
3. **정상 대조군**: 같은 계정의 정상 수업(Recording Settings, Status History, Reason 문자열 대조용)(D-04). 녹화 문제의 대조군은 녹화 Enable 회차로 잡는다(S-16).
4. 상황에 따라 추가로 받는 값
   - 녹화본 이상: 재생 타임코드, 자료 재생 여부, 다운로드본도 같은지, 다른 회차도 그런지(S-16)
   - 화질 불만: 실시간 화면인지 녹화 파일인지, 트래킹인지 파노라마인지(D-16)
   - "녹화 수업"이 보이지 않음: 라이브 녹화인지 녹화 수업(录播) 활동인지, 코스명·수업명, 학생 계정 1개, 학생 화면 캡처(S-37)
   - 단말 정보: 기기, OS, 클라이언트 버전(같은 모델 단말끼리 버전 대조용)(S-39)

접수 직후 문구(원인·복구 여부는 콘솔 확인 뒤에만):

```

말씀하신 ○/○ 수업 건 바로 확인해 보겠습니다.

▪ 수업명
▪ 선생님(또는 학생) 로그인 계정
▪ 수업 시작 날짜와 시각

기록을 확인한 뒤 원인과 함께 다시 안내드리겠습니다.
```

## 진단 흐름

**가. 녹화본이 없다**

1. `Recording Settings`를 본다.
   - **Disable이고 `Start Lesson-recording` 이벤트가 없음** → 그 회차를 만들 때 녹화 옵션이 꺼져 있었다. 시스템 결함이 아니고 복구할 수 없다. 녹화 설정은 회차 단위로 생성 시점에 정해지므로, 같은 반이어도 생성 배치(课节ID 대역)가 다르면 값이 다를 수 있다. 아직 진행하지 않은 회차의 설정은 지사 조회 화면이 아니라 기관 콘솔의 코스 관리에서만 보인다(D-04).
   - **Enable이고 Start가 있고 `Lesson-recording Error`가 있음** → 시작 단계에서 실패. `Camera Name`이 빈 값이고 error code 4001이면 카메라 녹화를 시작할 때 카메라가 지정되지 않은 것이다. 카메라 녹화 패널은 카운트다운 뒤 자동으로 시작하므로, 톱니바퀴에서 카메라를 고르지 않으면 조용히 실패한다(D-21). error code 2001도 같은 문구(카메라 영상 녹화 중 예외)로 나온 선례가 있다(S-10).
   - **Enable이고 Start도 있고 `Pushflow Quality Upload`도 정상인데 재생본이 없음** → HQ로 넘긴다(S-09).
2. Reason 문자열로 구성을 확인한다. **교실 녹화 OFF + 카메라 녹화만 ON**인 기관은 카메라 녹화가 실패하면 대신할 녹화가 없다. KJ영재센터가 이 구성이다.
3. 코스 목록의 녹색 "현장 녹화가 시작되었습니다"는 시작 이벤트만 반영한다. 그 뒤의 중단은 표시되지 않는다(D-21).
4. 수업 스크린샷은 녹화와 따로 저장된다. 기관 콘솔의 [수업 스크린샷]에서 볼 수 있어, 녹화가 없을 때 판서 확인 수단으로 안내한다(D-21).
5. 호스트가 Android 기기였는지 본다. 네트워크가 끊겼을 때 로컬 녹화로 넘어가지 못한다는 HQ 1차 회신이 있다(S-03, 재확인 전).
6. **복구 가능 여부**: 녹화본의 복구나 재처리는 실질적으로 불가능하다. 녹화가 시작되지 않았거나 시작 직후 실패한 경우는 데이터 자체가 없고(D-04, D-21), 끊겨서 나뉜 녹화나 품질이 이상한 녹화본도 되살리거나 다시 처리할 수 없다. 고객에게 복구를 기대하게 하는 표현을 쓰지 않는다. AI 요약의 재요약 신청은 이와 별개로 가능했다(D-11).
7. 예전 녹화가 사라졌다는 문의라면 장애가 아니라 보관 설정일 수 있다. 기관에 자동 삭제가 설정돼 있는지 확인하되 설정 상태를 단정하지 않는다. 보관과 요금 정책은 사내 원문 `20260929_KJ영재센터_녹화보관_스토리지요금_케이스.md`에 있다(문의 건이라 선례에는 넣지 않았다).

녹화 미생성은 두 유형이다: 가경관형(`Recording Settings: Disable` + Start 없음, D-04)과 창원형(Enable + Start 있음 + Error, D-21).

**나. 녹화본이 끊겼다·나뉘었다**

1. Status History의 입·퇴장 시각과 `Start Lesson-recording` 횟수를 대조한다. 교사가 교실을 나갔다 들어오거나 기기를 바꾸면 그만큼 비고 파일이 나뉜다(S-14). 5분 미만 세션은 Pushflow 기록이 남지 않고, 아주 짧은 세션은 파일이 안 생길 수 있다.
2. 코드 56 끊김과 `Connection break`가 있는지 본다(`01-class-disconnect.md`).
3. 영상에서 끊긴 지점을 녹화 시작 시각 기준으로 환산하면 콘솔 기록과 초 단위로 맞춰 볼 수 있다(D-20).
4. 공사나 정전 뒤라면 전자칠판의 유선 NIC 상태와 유·무선 이중 연결을 본다(S-10).

**다. 실시간은 정상인데 녹화본만 이상하다**

전송 구간이 아니라 녹화 인코딩, 믹싱, 트랜스코딩 쪽이다. 지사 콘솔로는 확인할 수 없어 HQ에 서버 원본 스트림 상태를 묻는다.

- 음성 잡음·싱크 밀림 → 같은 모델 단말끼리 클라이언트 버전을 대조한다. 특정 버전(6.0.9.1671)에서만 난 선례(S-39, 추정).
- 하울링 → 교실 장치가 정상이고 장치 변경이 없으면 믹싱 단계 추정(S-16).
- 화면 정지, 음성 정상 → `Start Error: -5801` 선례(S-22, 의미 미확인).
- 소리가 없다 → `Audio mode`와 `Video Scope`를 본다. 카메라 녹화 + ClassIn Audio 구성이면 외부 음향 장비 소리가 담기지 않았을 수 있다(S-09, 추정).

**라. 녹화 화질 불만**

고객이 보는 것이 실시간 화면인지 녹화 파일인지, 트래킹인지 파노라마인지부터 묻는다. ClassIn X의 녹화는 카메라와 무관하게 최대 1080p이고 T1 트래킹은 1080p 고정이다. 흰 바탕과 글자가 날아가면 과노출이고 카메라 쪽 파라미터 조정으로 해결되며 설정은 카메라에 저장된다. OBS 경유는 두 화면 중 하나만 되고 매 수업 수동으로 켜야 하므로, T1 직결과 먼저 비교한다(D-16).

**마. 녹화 영상이 학생에게 안 보인다**

"녹화수업"이 라이브 녹화인지 녹화 수업(录播) 활동인지 먼저 구분하고, 회차 명단 → 재생 열람자 설정 → 학생 추가 시점 순으로 본다(S-37, 원인 미확정).

## 원인 후보와 확신도

- 해당 회차 생성 시점에 녹화 옵션 비활성(Disable) — 확정 — D-04
- 카메라 녹화 시작 시점에 카메라 미지정(`Camera Name` 공란) → error code 4001 — 확정(HQ) — D-21. 카메라 드롭다운 기본값이 `사용 안 함`일 가능성 — 추정 — D-21
- Android 호스트는 네트워크 단절 시 로컬 녹화 전환 미지원(HQ 1차 회신, 재확인 없음) — 추정 — S-03
- 카메라 녹화만 켜진 구성 + ClassIn Audio라 외부 음향이 녹화에 담기지 않았을 가능성 — 추정 — S-09
- 공사 후 유·무선 이중 인터페이스로 시그널링·게이트웨이 반복 단절, 녹화 태스크 중단(2001 카메라 캡처 요인 미배제) — 추정 — S-10
- 교사 이탈·기기 전환으로 녹화 분할(로그 기준) — 확정 — S-14. 코드 120 정의 — 미확정(중복 로그인 추정)
- 서버 측 녹화 믹싱 단계(하울링) — 추정 — S-16
- 녹화 또는 트랜스코딩 측(화면 정지, -5801 의미 미확인) — 추정 — S-22
- 특정 클라이언트 버전(6.0.9.1671)의 카메라 녹화 오디오 인코딩 회귀 — 추정 — S-39
- ClassIn X 녹화 상한 1080p, T1 트래킹 1080p 고정(4K는 파노라마만) — 확정(HQ) — D-16. 판서 흐림(파라미터 또는 설치 거리)·흰 바탕 과노출 — 추정 — D-16
- 녹화 영상이 학생에게 안 보임 — 미확정 — S-37


쓸 때 지킬 것

- 고객이 쓴 현상 이름이 틀리면 결과 회신에서 바로잡는다. "업로드 오류"를 그대로 받으면 재업로드 요청처럼 엉뚱한 방향으로 간다(D-04).
- 설정을 누가, 언제 그렇게 해 두었는지 말하지 않는다. "선택하지 않으셔서"가 아니라 "지정되지 않은 상태였습니다"처럼 상태만 적는다(D-04, D-21).
- 복구 불가는 원인 설명과 함께 전한다. 단독 통보는 반발을 부른다(D-04). 복구를 기대하게 하는 표현을 쓰지 않는다.
- 원인 회신에 "앞으로 이렇게 하라"는 점검 지시를 같이 싣지 않는다. 다만 다음 수업에 바로 필요한 조작 절차는 같이 준다(D-21).
- 오류 코드(4001, 2001, -5801 등), 서버명, Client IP, Account ID는 넣지 않는다. 의미를 모르는 로그 필드도 전달하지 않는다(S-22).
- 미확정 가설(믹싱, 인코딩 회귀 등)은 고객 문안에 넣지 않는다(S-16).
- 화면 표시 문구는 따옴표 안에 원문 그대로 인용한다.
- 캡처는 필요한 영역만 잘라 보내고 지사 백오피스 경로, Media Server 이름, Port는 가린다(D-04). HQ가 준 중국어 UI 캡처는 한국어 화면으로 다시 찍어 주석을 단다(D-21).
- 화질 건은 "안 된다"보다 "사양은 이렇고 그 안에서 이렇게 맞췄다"로 쓴다(D-16). HQ가 말한 수치를 단독으로 인용하지 않는다. '4K' 판매 안내 범위는 영업 확인 전에는 언급하지 않는다.

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- Enable + Start + Pushflow 정상인데 재생본이 없을 때(S-09).
- 실시간은 정상이고 녹화본만 이상할 때. 지사는 서버 원본 스트림을 볼 수 없으므로 같은 모델 단말 간 버전 대조까지 하고 넘긴다(S-16, S-22, S-39).
- Recording Settings Disable처럼 설정 문제로 판명되면 넘기지 않는다(D-04).
- HQ 1차 답변이 "교사 인터넷 문제"여도 시각과 콘솔 지표를 대조해 다시 묻는다. 시각이 맞지 않은 선례(S-10), 다른 수업을 보고 답한 선례(S-03)가 있다.

받는 곳(역할명)

- 1차: HQ 서비스 1차 접점(小助手)
- 녹화본 하울링 대안 창구: HQ 소프트웨어·필기 담당(S-16)
- 카메라 화질·원격 조정: HQ 하드웨어 1차·원격 지원 담당 → HQ 카메라 원격 디버깅 담당(D-16)
- AI 녹화·AI 요약: HQ AI 교실·AI 녹화 제품 담당

적을 것

- 분류: 버그 `缺陷`(예: 버전 회귀 의심은 【缺陷】 초안, S-39), 원인 미확정 결함 의심은 `疑似缺陷`.
- 계정, 수업명, 시각을 맨 위에(S-03). 시각은 중국 시각(UTC+8 = KST − 1시간)으로 적고 시간대를 표기한다.
- 기기, OS, 클라이언트 버전, 최신 여부. 같은 현장 다른 단말의 버전도 적는다(S-39).
- `Recording Settings`, Status History 이벤트 순서, Reason 문자열(`Camera Name`, `Video Scope`, `Audio mode`), 에러 코드.
- 묻는 항목 예: 서버 원본 스트림에 이미 이상이 있는지, 해당 버전 기지 이슈 여부, 서버 측 녹화 태스크 상태·에러 코드(S-10, S-39).
- 화질 비교용 영상은 다시 인코딩하지 않고 WeDrive 지정 공유로 보낸다(학생 얼굴·음성 포함 가능)(D-16).

기재하지 않는 값과 예외

- 기재하지 않는 값: Device ID, Client IP, Server(미디어·접속 서버명), Owner.
- 예외: 서버·경로가 의심 지점이면 Media Server와 Port를 적는다. 기준은 "그 값을 빼면 증상 설명이 성립하는가"다.
- 위 값은 WeCom 발송문에만 넣고 이 저장소·적재 데이터에는 남기지 않는다.
