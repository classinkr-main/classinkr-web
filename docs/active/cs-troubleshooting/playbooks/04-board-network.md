# 전자칠판 네트워크

## 증상 표현

| 고객 표현 | 실제 현상 | 선례 |
|---|---|---|
| "수업 중 네트워크가 끊긴다"(전자칠판) | 메인 NIC 고정 IP가 다른 기기와 충돌(`Duplicate`)해 유선 마비, Wi-Fi로 폴백 | D-02a |
| "인터넷은 되는데 유선이 이상하다고 한다" | 메인 유선망 링크(100Mbps)는 성립하나 수신 0패킷, DHCP 무응답. 인터넷은 Wi-Fi가 대행해 문제가 가려짐 | D-15b |
| "통신사가 장비 쪽 문제라고 했다" | ISP가 점검한 범위(회선~공유기)가 정상이라는 뜻이지 전자칠판 결함 확정이 아님 | D-02 |
| "칠판 시계가 조금씩 느려진다" | 약 1분/45일(약 15ppm). RTC 정상 오차 범위라 하드웨어 결함이 아니라 시간 동기화가 안 걸리는 상태 | S-29 |

증상 동의어: 전자칠판 인터넷 안 됨, 칠판 네트워크 끊김, 유선 안 됨, 랜 안 됨, 랜선 인식, IP 충돌, 와이파이로만 됨, 인터넷 느림, 칠판 시계 느림, 시간 안 맞음, OPS 네트워크

## 먼저 받을 값

1. **조회 키**(수업 중 발생 시): 수업명, 사용자 계정, 수업 시작 시각.
2. **하드웨어 값**: 전자칠판 SN, 시스템 버전, 설치일, OPS 사양.
3. **`ipconfig /all` 원문**(원격·방문 시). 고객 담당자에게 받을 때는 `ncpa.cpl` 창 사진과 `ipconfig` 결과 사진.
4. 같은 학원의 정상 교실 자료(대조군).
5. **조치 전에 증거를 남긴다.** 재부팅·재설정·케이블 재체결 전에 `ipconfig /all`, 설정 화면을 캡처한다(D-07).

## 진단 흐름

1. **규격부터 대조한다.** 메인 NIC는 자동 IP, 카메라 NIC는 `192.168.1.222` 고정. 규격에서 벗어난 설정이 보이면 값이 그럴듯해 보여도 1순위로 의심한다(D-02).
2. **`ipconfig /all` 원문**을 본다. Windows 네트워크 문제 해결사는 링크가 있고 고정 IP가 들어 있으면 "이상 없음"을 내므로 근거가 되지 않는다(D-02).
3. **`Duplicate`**는 같은 망의 다른 기기가 그 IP를 쓰고 있다는 뜻이다. 동시에 케이블과 배선은 살아 있다는 반증이다(D-02).
4. **유선이 죽으면 Wi-Fi로 자동으로 넘어가** 수업이 "되긴 되는" 상태가 되고 문제가 가려진다. Wi-Fi가 인터넷을 대신하고 있는지 본다(D-02, D-07, D-15).
5. 링크는 있는데 수신이 0패킷이면 배선·스위치·어댑터 쪽이다. 같은 자리에 노트북 USB-LAN을 직결해 IP를 받는지로 기기 쪽과 배선 쪽을 가른다(D-15b).
6. **수업 중에는 ping 같은 연결 테스트를 못 돌린다.** 그런 확인이 필요한 건은 수업이 없는 시간에 방문한다(D-02).
7. ISP의 "장비 쪽 문제"는 그들이 점검한 범위(회선~공유기)가 정상이라는 뜻이지 전자칠판 결함 확정이 아니다(D-02).
8. 고객사 장비를 건드리지 않고 쓸 수 있는 **조회 전용 명령**:

   ```
   ipconfig /all
   arp -a
   route print
   netsh wlan show interfaces
   netstat -ano | findstr LISTENING
   w32tm /query /status
   ```

   `ipconfig /release`, `/renew`, `w32tm /resync`, `netsh int ip set`은 쓰지 않는다. 조회처럼 보이지만 상태를 바꾸고 `Duplicate` 같은 증거를 없앤다(D-07).
9. Windows 시계가 계속 밀리는 교실은 NTP가 막힌 망일 수 있다. 로그 시각을 대조할 때 주의한다(S-29, D-07).
   - S-29의 판별 명령 제안: `w32tm /query /status`, `sc qc w32time`, `w32tm /stripchart`로 본 뒤 국내 NTP를 지정한다. 후보 원인은 기본 동기화 주기 7일, UDP 123 차단, w32time 미자동이다. Windows Update 차단과는 별개 서비스이나 차단 방식(도메인 차단, 화이트리스트 방화벽)에 따라 연결될 수 있다.

보충(선례에서 확인된 구성)

- 배선 선례(D-02): 메인 랜선은 벽단자에서 전자칠판 하단 LAN 포트로 들어가 ASIX USB 랜카드로 잡힌다. 카메라는 PoE 스위치를 거쳐 OPS 본체 LAN(내장 Realtek)에 물린다. 다만 어느 NIC가 메인인지는 배선에 따라 기기마다 달랐고 고정 IP가 엉뚱한 NIC에 들어간 경우도 있었으므로, 어댑터 이름이나 설정값만으로 역할을 단정하지 않는다.
- D-15b 기기는 양쪽 어댑터 모두 Fast Ethernet 100Mbps라 권장 최소 170Mbps에 미달했다.
- 카메라 NIC 쪽 문제(CameraCMS 접속 실패, PoE)는 `03-camera-not-detected.md`, 전자칠판에서 생긴 수업 중 끊김은 `01-class-disconnect.md`를 함께 본다.

## 원인 후보와 확신도

- 메인 NIC 고정 IP 충돌(`Duplicate`) — 확정 — D-02a
- 메인 유선망 수신 0패킷: 칠판 선과 단말기 선이 다른 선, 랜툴 시공 불량, 스위치 포트 MAC 정책, USB 랜어댑터 불량 중 하나 — 추정(후보 4개, 미분리) — D-15b
- Windows 시계 지연: NTP 미동기화(기본 주기 7일, UDP 123 차단, w32time 미자동 후보) — 추정 — S-29
- 카메라 고정 IP가 다른 NIC에 설정됨(같은 기기에서 함께 발견) — 확정 — D-15a

## 고객 안내 문구

결과 회신 뼈대(카카오톡):

```
안녕하세요, ○○님. ○○ 교실 전자칠판 네트워크 건 확인 결과입니다.

▪ 원인
(확인된 사실. 추정이면 "~로 추정됩니다")

▪ 조치 / 현재 상태
(조치 내용과 남은 확인)

▪ 다시 발생하면
(알려 달라는 정보: 교실, 발생 시각)
```

쓸 때 지킬 것

- 고객사 네트워크 장비 설정은 지사가 바꾸지 않는다. 근거(측정값)를 붙여 고객사 담당자에게 요청한다.
- 고정 IP를 누가, 언제 넣었는지 말하지 않는다. "지정되지 않은 상태였습니다", "해제가 필요합니다"처럼 상태만 쓴다.
- 확인한 범위(그 기기 한 대)까지만 답한다. "학원 전체 네트워크 문제"로 일반화하지 않는다(D-20).
- 하드웨어 결함·불량이라는 말을 하지 않는다. 시계 지연(S-29)도 결함이 아니라 동기화 상태 문제로 설명한다.
- 고객 측 IP 값, 서버명, 내부 로그 필드는 넣지 않는다.
- 재부팅(restart)과 초기화(reset)를 구분해 적는다.

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- 규격 대조, `ipconfig /all`, 노트북 직결 대조로 배선 쪽과 기기 쪽을 가른 뒤에도 기기 쪽(어댑터·OPS) 이상이 남을 때.
- OPS 출하 이미지 설정(시간 동기화 등)이 원인으로 보일 때(S-29, HQ 미문의).

받는 곳(역할명)

- 네트워크·접속: HQ 네트워크·접속·메모리 담당
- 하드웨어·원격: HQ 하드웨어 1차·원격 지원 담당(영향 기기 스크리닝·일괄 배포 후보, S-29)
- 출하 이미지·OPS 구성: HQ 하드웨어 총괄·OPS 이미지 담당(S-29)

적을 것

- 분류(`缺陷` / `疑似缺陷` / `需求`), 하드웨어 식별자(EEO Account, UID, 제품 SN, 설치일, 세대).
- 어댑터 구성(메인·카메라 NIC 종류, 설정 방식), 배선 경로, 측정 결과(링크 속도, 수신 패킷, DHCP 응답 여부).
- 업데이트 제한 같은 지사 조치가 있으면 먼저 밝힌다.
- 시각은 중국 시각(UTC+8 = KST − 1시간).

기재하지 않는 값과 예외

- 기재하지 않는 값: Device ID, Client IP, Server, Owner.
- 예외: IP 충돌이 원인이면 충돌한 IP를 적는다(D-02). 기준은 "그 값을 빼면 증상 설명이 성립하는가"다.
- 고객사 실제 IP 값은 WeCom 발송문에만 넣고 이 저장소·적재 데이터에는 남기지 않는다(이 문서에는 "고정 IP 충돌"로만 적는다).
