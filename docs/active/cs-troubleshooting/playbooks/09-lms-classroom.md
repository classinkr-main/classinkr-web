# 수업·LMS·교실 기능

## 증상 표현

| 고객 표현 | 실제 현상 | 선례 |
|---|---|---|
| "코스에서 삭제한 학생이 수업 기록에 '청강생'으로 남아 있다" | 「코스 자료 열람 허용」 옵션이 켜진 상태에서 삭제해 완료 수업의 학생 신분 유지 | S-01 |
| "'코스를 떠났습니다'가 떴는데 명단에 그대로 있다" | 기관 계정 2개(메인·하위)에 동명 코스, 동명 학생 계정 2개 — 퇴장한 계정과 남은 계정이 다름 | D-14 |
| "숙제 사진을 더 올릴 수 없다(지난번엔 됐다)" | 마감 전이지만 교사가 채점 완료·'모두 공개'한 뒤라 `변경` 버튼이 사라짐 | S-38 |
| "단원을 추가하면 저장이 안 된다" | 과정(课程)당 단원(单元) 최대 100개 사양 | D-12 |

| "필기가 붓처럼 굵기가 변한다" | 필기 효과 설정(기기마다 토글 수가 다름) | D-17 |

| "숙제 번호 목록이 전부 1.로 나온다" | 애플 계열 기기에서만, 휴대폰 모드에서 재현 | D-01 |
| "자료 업로드가 느리다" | 실제로는 클라우드 PDF를 불러오는(다운로드) 구간 | S-25 |

| "여러 파일을 올리면 파일 사이에서 멈춘다" | 대시보드와 클라이언트 양쪽에서 동일 | S-02 |
| "AI 답안지에 정답이 선택되지 않는다" | 정답 포함 PDF를 올려도 문항 구조만 생성 | S-11 |
| "에이전트가 안 보인다" | AgentIn 좌하단 신분이 Student로 표시 | S-12 |

증상 동의어: 학생 삭제 안 됨, 퇴장했는데 남음, 명단 정리 안 됨, 청강생, 숙제 수정 불가, 숙제 재제출, 추가 업로드 불가, 단원 상한, 단원 추가 안 됨, 로고 업로드 반려, 스킨 이미지, 필기 굵기, 붓 효과, 필압, 펜 색, 번호 목록 깨짐, 업로드 느림, 자료 로딩 느림, PDF 느림, AI 답안지, 에이전트 안 보임, 발음 오디오

## 먼저 받을 값

1. **조회 키**: 수업명(또는 코스명), 사용자 계정, 발생 날짜·시각.
2. 사용 기기·OS·클라이언트 버전(필기·렌더링처럼 기기마다 다른 기능은 필수)(D-17, D-01).
3. 기능 건이면 그 설정 화면 캡처(코스 생성 옵션, 숙제 설정, 채점 상태 등).
4. 하위 계정을 가진 기관이면 기관 계정 목록(동명 코스 점검용)(D-14).
5. 업로드·불러오기 지연이면: 파일 종류·크기, 파일 수, 상시/간헐, 업로드인지 불러오기인지(S-02, S-25).
6. 이미지 반려면: 실제 업로드한 파일 원본(메신저 '사진' 전송은 재압축되므로 파일로)(D-10).

## 진단 흐름

| 문의 | 먼저 볼 것 | 선례 |
|---|---|---|
| 삭제·퇴장한 학생이 남아 있다 | 코스 생성 시 "코스 자료 열람 허용" 옵션, 동명 계정과 동명 코스(하위 계정 보유 기관) | S-01, D-14 |
| 숙제를 수정·추가할 수 없다 | 채점이 완료·공개됐는지, 마감이 지났고 "마감 후에도 추가 제출 허용"이 꺼져 있는지. 교사가 재채점 → 수정에 대한 콜백 → 완료 후 공개로 다시 연다 | S-38 |
| 단원을 더 만들 수 없다 | 과정(课程)당 단원 100개 상한. 과정을 나누는 것이 1차 안내 | D-12 |
| 제목 표시줄 이미지가 반려된다 | 높이가 정확히 24px인지(너비 1280px 이하, 50KB 이하) | D-10 |
| 필기가 붓처럼 굵기가 변한다 | 사용 기기. iPad는 토글 2개, PC는 1개 | D-17 |
| 펜 기본 색이 이상하다 | 그 기기에서 마지막에 쓴 색을 이어받는 것으로 보임 | S-17 |
| 특정 기기에서만 화면이 깨진다 | 플랫폼 × 기능 매트릭스로 사내 재현 후 HQ에 넘긴다 | D-01 |

기능이 "원래 그런 것"인지는 사내 테스트 계정으로 조건을 바꿔 가며 재현해 확정한다. 추측으로 답하지 않는다(S-38, D-10).

선례별 세부

- **동명 계정**(D-14): "나갔는데 명단에 남아 있다"는 동명 계정 중복을 먼저 의심하고 계정 식별자(휴대폰/이메일) 단위로 대조한다. 하위 계정 보유 고객은 동명 코스 존재를 기본 점검한다.
- **삭제 학생 잔존**(S-01): 고객이 준 계정 정보는 콘솔로 대조한 뒤 HQ에 넘긴다. 한국어 UI '청강생'이 插班生/Transfer와 같은지는 미확인.
- **숙제 잠금**(S-38): 제출물 잠금 조건은 ① 채점 완료·공개 ② 마감 경과 + '마감 후에도 추가 제출 허용' OFF 두 가지다. "지난번엔 됐다"면 채점 시각과 수정 시각의 선후를 먼저 본다. 웹으로는 숙제를 제출할 수 없다. 예방은 제출이 끝난 뒤 채점.
- **제목 표시줄 이미지**(D-10): 경로는 콘솔 → 일반 설정 → 교실 설정 → 스킨 설정 → 제목 표시줄 설정 → 사용자 정의 이미지. 규격은 높이 정확히 24px / 너비 1280px 이하 / 50KB 이하 / PNG·JPG. 최빈 원인은 Figma Export 배율 2x(2560×48) → 비율 유지 축소로 높이가 24px이 아님 → 메신저 '사진' 전송 재압축 순이다. 예시 파일은 성공하고 고객 파일만 실패하면 파일 규격 문제로 확정한다.
- **필기 붓 효과**(D-17): 사용 기기부터 확인한다(PC+펜 태블릿 / iPad+Apple Pencil / 전자칠판 / Android). iPad는 `판서 붓끝 효과`와 `펜 필압 감지` 두 토글을 모두 꺼야 균일해짐(내부 테스트). PC 경로는 계정 및 설정 → 교실 설정 → 펜 필압 감지 효과(스타일러스). 전자칠판에서 붓 효과가 나는 원인은 미해결.
- **숙제 렌더링**(D-01): 플랫폼 × 기능 재현 매트릭스와 단일 변수 대조(휴대폰 모드 토글). WeCom 복사·붙여넣기는 HTML 태그가 지워지므로 실제 제출이나 로그 파일로 전달한다. 지사의 초기 가설(`<ol>` 분해)은 HQ 조회로 기각됐다 — 증상이 비슷하다고 HQ 내부 구조를 단정하지 않는다.
- **단원 상한**(D-12): 과정 분할이 1차 안내. 특정 기관 상한 조정 가능 여부는 HQ 확인 중이었다. 용어: 코스 = 班级, 과정 = 课程, 단원 = 单元.
- **클라우드 드라이브 지연**(S-02, S-05, S-25): 업로드 구간인지 다운로드(불러오기) 구간인지 먼저 확정한다. 대시보드와 클라이언트에서 모두 나오면 서버·계정 측으로 분류한다. 콘솔 네트워크 지표가 정상이면 네트워크를 배제하고 내부 테스트 속도와 대조한다. HQ가 준 도메인·진단 수치는 실측(nslookup, ping, Speedtest)으로 대조한다. 파일 삭제·재업로드는 증거 객체를 없앤다. 임시 조치는 수업 전 자료 미리 열기(S-25). 속도 단위(KB/s, kbps)를 확인해 적는다(`../aliases.json`).
- **AI 답안지·AgentIn**(S-11, S-12): 버그와 기능 문의를 한 메시지에 섞지 않고 업로드 파일 형식을 명시한다. "에이전트가 안 보인다"면 AgentIn 좌하단 신분 표시부터 확인한다(좌하단 전환 아이콘으로 사용자가 직접 바꿀 가능성).
- **따라읽기 발음 오디오**(D-23): 단어 단위로 표기 음표와 대조해 증상 유형(어말 탈락, 어두 탈락, 무음)을 나눠 적는다. 재보고 요청 초점은 전체 오디오 자산 일괄 재생성·검증이었다.

## 고객 안내 문구

결과 회신 뼈대(카카오톡):

```
안녕하세요, ○○님. ○○ 건 확인 결과입니다.

▪ 원인
(확인된 사실. 사양이면 "사양은 이렇고 그 안에서 이렇게 하시면 됩니다")

▪ 해결 방법
(바로 할 조작 절차)

▪ 다시 발생하면
(알려 달라는 정보: 수업·코스명, 계정, 화면 캡처)
```

쓸 때 지킬 것

- 스펙 기대와 달랐던 건은 "안 된다"보다 "사양은 이렇고 그 안에서 이렇게 맞췄다"로 쓴다(단원 상한, 1080p 등).
- 설정을 누가 그렇게 해 두었는지 말하지 않는다. "옵션이 켜진 상태였습니다"처럼 상태만 쓴다.
- 고객 파일에 문제가 있을 가능성은 확인 전에 언급하지 않는다(S-25). 이미지 규격 건은 예시 파일 대조로 규격 문제가 확정된 뒤에 규격을 안내한다(D-10).
- "원래 그런 것"이라는 답은 사내 재현으로 확정한 뒤에만 한다(S-38, D-10).
- 다음 수업에 바로 필요한 조작 절차(재채점 → 수정에 대한 콜백 → 완료 후 공개, 토글 위치 등)는 결과 회신에 같이 준다.
- 내부 로그, 계정 ID, 서버·도메인 정보는 넣지 않는다.

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- 사내 테스트 계정으로 재현해 사양인지 결함인지 갈랐는데 결함이 의심될 때(D-01, S-11).
- 사양 자체의 조정(특정 기관 상한 조정 등)을 요청할 때(D-12, `需求`).
- 서버·계정 측이 의심되는 업로드·불러오기 지연(S-02, S-05, S-25).
- 설정·사용법·사양으로 판명되면 넘기지 않는다(S-38, D-10, D-14).

받는 곳(역할명)

- LMS 구조·상한·AgentIn·Answer Sheet: HQ LMS·AgentIn 담당(小助手를 거치지 않고 직행)(D-12, S-11)
- AI LMS: HQ AI LMS PM(S-11)
- 필기·소프트웨어: HQ 소프트웨어·필기 담당. 따라읽기 오디오 재보고도 이 담당이 1차 접점 후보였다(D-23)
