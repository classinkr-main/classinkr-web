# 전자칠판 하드웨어

## 증상 표현

| 고객 표현 | 실제 현상 | 선례 |
|---|---|---|
| "두 대를 붙여 쓰면 혼자 터치된다" | 약 10cm 간격으로 나란히 두면 고스트 터치 점이 한 번에 10개 이상 간헐 발생 | D-05 |
| "수업 중 터치가 가끔 멈춘다" | 간헐 터치 프리징, 시간이 지나면 저절로 복구 | S-21 |
| "화면에 하얀 얼룩이 있다, 터치가 덜 된다" | 구름·줄무늬 형태 백색 잔류물(마른 극세사로 제거됨) + 터치 민감도·인식률 소폭 저하 | D-03 |
| "화면에 파란 세로줄이 생겼다" | 화면 전체를 세로로 관통, 재시작 후에도 지속 | S-07 |
| "화면이 깨졌다" | 하단 중앙부에서 방사형으로 번진 유리 파손. IR 터치라 깨져도 동작해 계속 쓸 위험 | S-18 |
| "새로 받은 칠판의 왼쪽 화면 내리기 버튼이 안 된다" | 좌측 '화면 하강' 터치 센서 완전 무반응(우측 정상). SW 업데이트 후 정상 | S-20 |
| "작업 표시줄이 터치로 안 눌린다" | 'ClassIn 자체 최소화' + '다른 프로그램 최대화'가 동시에 충족되면 작업 표시줄 일부가 터치 무반응(마우스 정상, 재현율 100%) | S-06 |
| "칠판에서 Store 앱이 설치가 안 된다" | Store 앱이 구버전이고 자체 업데이트 실패. OPS는 지사 조치로 Windows Update 비활성 | S-23 |

증상 동의어: 터치 안 됨, 터치 먹통, 터치 튐, 유령 터치, 혼자 눌림, 터치 멈춤, 터치 인식률 저하, 화면 얼룩, 백화, 잔류물, 세로줄, 줄 생김, 액정 깨짐, 유리 파손, 센서 안 됨, 화면 내리기, 작업 표시줄, 스토어 설치 오류

## 먼저 받을 값

1. **SN, 시스템·펌웨어 버전, 설치일**을 먼저 받는다. 설치 후 기간으로 보증 범위 안인지 적는다. HQ는 하드웨어 건에서 SN을 반드시 요구한다(SN이 `BS86A`로 시작하면 86인치 2세대).
2. 증상의 범위: 화면 전체인지 특정 영역인지, 수업을 OPS에서 하는지 안드로이드에서 하는지, 부팅 로고에서도 보이는지(S-07, S-21).
3. **재부팅이나 리셋 전에 로그와 발생 시각을 확보한다**(S-21).
4. 증거 사진: 정면, 전체 검정 화면, 반사 없음, 조치 전후(D-03). 파손 건은 발생 시각, CCTV, SN, 모서리 4곳 사진, 펜 팁(S-18).
5. 고객이 주는 대조 정보("다른 지점은 같은 모델을 붙여 써도 정상")도 기록한다(D-05).

## 진단 흐름

1. **SN, 시스템·펌웨어 버전, 설치일**을 먼저 받는다. 설치 후 기간으로 보증 범위 안인지 적는다.
2. 증상의 범위를 좁힌다. 화면 전체인지 특정 영역인지, 수업을 OPS에서 하는지 안드로이드에서 하는지, 부팅 로고에서도 보이는지(S-07, S-21).
3. 재부팅이나 리셋 전에 로그와 발생 시각을 확보한다(S-21).
4. 선례별 첫 확인:
   - 신품인데 한쪽 센서만 완전 무반응 → 교체 전에 SW 업데이트부터(S-20). 3손가락 제스처가 되면 SW 경로는 정상이다.
   - 2대를 나란히 두면 고스트 터치 → 1대 전원을 끄고도 나는지. 꺼도 나면 2대 간 간섭이 아니다(D-05)
   - 화면에 흰 잔류물 → 마른 극세사로만 닦고 세정제는 쓰지 않는다. SN으로 생산 배치를 확인한다(D-03)
   - 파란 세로줄 → 부팅 로고에서도 보이면 패널·T-CON, 안드로이드 진입 후에만 보이면 신호 쪽(S-07)
   - 유리 파손 → 전원 차단과 접근 통제 같은 안전 안내가 먼저다(S-18)
5. 고객이 주는 대조 정보("다른 지점은 같은 모델을 붙여 써도 정상")는 반박할 대상이 아니라 증거로 쓴다(D-05).
6. 증거 사진은 정면, 전체 검정 화면, 반사 없음, 조치 전후로 찍는다(D-03).
7. HQ: HQ 하드웨어 1차·원격 지원 담당(원격·하드웨어 1차) → HQ 전자칠판 2세대 담당 / HQ 전자칠판 3세대 담당 → 보증·A/S 판정은 HQ 하드웨어 A/S·보증 판정 담당. OPS 이미지·출하 구성은 HQ 하드웨어 총괄·OPS 이미지 담당.

OPS(Windows) 쪽 선례

- 작업 표시줄 터치 무반응(S-06): HQ의 "재현 안 됨"은 재현 절차가 같은지부터 확인한다. 마우스와 터치, ClassIn 종료 후 재현으로 책임 범위를 가른다. HQ가 안내한 임시 조치 "작업 표시줄 아래쪽 누르기"는 실측과 반대(맨 윗줄만 유효)라 고객 안내에 쓰지 않는다. 별도 언어 기능(FOD) 설치 실패 `0x80004002`는 실사용 영향 없음.
- Store 앱 설치 불가(S-23): Store 오류에서 Edge 설치는 의미가 없다. 업데이트 제한이 지사 조치임을 HQ에 먼저 밝힌다. 후보 조치(업데이트 활성화 → 앱 설치 → 재비활성화)는 미실행, HQ 확인을 먼저 받기로 했다.
- 간헐 터치 프리징(S-21): 전체 먹통인지 특정 영역만인지 먼저 가르고, 수업을 OPS에서 하는지 안드로이드에서 하는지 확인한 뒤 리셋을 안내한다. 안드로이드 리셋은 OPS 데이터에 영향이 없고 안드로이드는 활성화 절차를 다시 거친다.

되풀이된 패턴

- 사실과 가설을 표로 나누고, 붙어 있는 변수를 가르는 실험을 설계한다(D-03의 생산 배치 vs 보관 환경).
- 변수를 하나씩만 바꾼다(1대 전원 차단, D-05).
- HQ의 "정상 범위" 진술을 받아 두면 "더 띄우세요" 같은 반복 안내로 끝나는 것을 막을 수 있다. 다만 그 수치만 떼어 고객에게 인용하지 않는다(D-05).
- 재체결·재부팅으로 나은 건은 원인이 특정된 것이 아니다(S-21).

## 원인 후보와 확신도

- 화면 백색 잔류물: 1순위 생산 배치 요인(배치 260318), 2순위 보관 환경(창고 결로), 3순위 포장재 휘발분, 4순위 AF 코팅. 배치와 보관 변수 미분리 — 추정(미확정) — D-03
- 고스트 터치: IR 간섭(HQ 판정이나 설명만 듣고 내린 판단). 스탠드 각도·높이, 1대의 IR 프레임 이상, 교실 내 다른 적외선원, 접지 가설 — 추정(미확정) — D-05
- 작업 표시줄 터치 무반응: ClassIn 판서 오버레이의 터치 좌표 판정(HQ: 일부 Win11 버전 기지 이슈, 7/20 패치) — 추정 — S-06
- 파란 세로줄: 패널 또는 케이블 측 하드웨어 — 추정 — S-07
- 유리 파손: 외부 점 충격(사진만으로 확정 불가) — 추정 — S-18
- 좌측 하강 센서 무반응: 하드웨어 불량 아님, SW 업데이트 후 정상(어떤 업데이트인지 미기재) — 확정 — S-20
- 간헐 터치 프리징 — 미확정 — S-21
- Store 설치 불가: Windows Update 비활성으로 Store 자체 업데이트 불가 — 추정 — S-23

## 고객 안내 문구

결과 회신 뼈대(카카오톡):

```
안녕하세요, ○○님. ○○ 교실 전자칠판 건 확인 상황입니다.

▪ 확인된 내용
(확인된 사실. 추정이면 "~로 추정됩니다". 원인 확정 전에는 "확인 중")

▪ 지금 하실 일
(안전 안내, 다음 수업에 필요한 조작)

▪ 추가로 부탁드리는 것
(SN, 설치일, 사진·영상 조건)
```

쓸 때 지킬 것

- **하드웨어 결함·불량이라는 말을 하지 않는다.** 원인 확정 전에는 "확인 중"까지만 한다(D-03, D-05).
- **파손 건의 원인 판단을 고객에게 먼저 말하지 않는다.** 귀책 문제가 걸려 있다. 안전 안내(전원 차단, 접근 통제, 낙하 방지)가 먼저다(S-18).
- **보증, 교체, 환불, 가격, 보상 여부는 내부 합의 전에 고객에게 먼저 꺼내지 않는다.**
- HQ가 말한 수치("10cm면 정상" 등)를 고객에게 단독으로 인용하지 않는다. 이미 그 거리에서 문제가 난 현장에서는 바로 반박당한다(D-05).
- WeCom 자동 번역 결과를 그대로 옮기지 않는다. `红外`(적외선)가 "red"로 나온 선례가 있다(D-05). 이전 안내의 용어가 틀렸으면 정정한다(D-05: NFC → IR).
- HQ가 안내한 임시 조치라도 실측과 다르면 고객에게 쓰지 않는다(S-06).
- 재부팅(restart)과 초기화(reset)를 구분해 적는다.
- 고객 파일·사용 방식에 문제가 있을 가능성은 확인 전에 언급하지 않는다.

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- SN·버전·설치일과 범위 좁히기(전체/영역, OPS/안드로이드, 부팅 로고), 단일 변수 실험을 마친 뒤.
- SW 업데이트로 해소되는지 먼저 본다(S-20). 해소되면 넘기지 않는다.
- 보증·A/S 판정이 필요한 건.

받는 곳(역할명)

- HQ 하드웨어 1차·원격 지원 담당 → HQ 전자칠판 2세대 담당 / HQ 전자칠판 3세대 담당 → HQ 하드웨어 A/S·보증 판정 담당
- OPS 이미지·출하 구성: HQ 하드웨어 총괄·OPS 이미지 담당
- 소프트웨어·터치 보정: HQ 소프트웨어·필기 담당(S-06, S-21)
- 1차 접점: HQ 서비스 1차 접점(小助手) → 담당자 안내 시 직접 문의(D-05)

적을 것

- 하드웨어 건의 식별자: EEO Account, UID, 제품 SN, 설치일, 세대. 설치 후 기간과 보증 범위 안인지 명시(S-07).
- 증상 범위, 재현 조건(재현율), 단일 변수 실험 결과, 증거 사진(정면·전체 검정·반사 없음·전후).
- 분류: `缺陷` / `疑似缺陷`. 같은 담당자와 여러 건이 동시에 진행되면 건명을 적는다(D-03과 D-05가 같은 대화창).
- 사실을 정확히 적는다. "다른 기기도 발생"처럼 실제(1대)와 다르게 나간 선례가 있다(S-21).
- 업데이트 제한 같은 지사 조치를 먼저 밝힌다(S-23). 담당자가 바뀌면 첨부를 처음부터 다시 보낸다.
- 시각은 중국 시각(UTC+8 = KST − 1시간).

기재하지 않는 값과 예외

- 기재하지 않는 값: Device ID, Client IP, Server, Owner.
- 제품 SN·설치일은 HQ가 반드시 요구하므로 WeCom 발송문에는 적는다. 이 저장소·적재 데이터에는 남기지 않는다.
- HQ 원격 지원(AweSun)의 식별 코드와 인증 코드는 담당자에게 1:1로만 전달한다.
