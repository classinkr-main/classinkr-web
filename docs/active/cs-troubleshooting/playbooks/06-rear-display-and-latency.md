# 후면 TV·보조 화면·화면 지연

## 증상 표현

| 고객 표현 | 실제 현상 | 선례 |
|---|---|---|
| "후면 TV가 안 나온다(no signal)" | Windows 디스플레이 검색에서도 안 잡힘(OS가 못 보므로 ClassIn 문제 아님). 케이블이 패널 HDMI(입력 전용)에 꽂혀 있음 | S-24 |
| "후면 모니터를 인식하지 못한다" | Windows에 디스플레이가 1개만 표시. OPS HDMI 출력 연결은 확인됨, 남은 후보는 입력 소스·HDMI 선·OPS HDMI 출력 | S-40 |
| "2차 화면 좌우에 검은 띠가 생긴다" | ClassIn 결함 아님 — 2차 화면 데스크톱 모드가 16:10이라 16:9 패널에 레터박스 | D-13 |
| "칠판 1대와 TV 2대에 같은 화면을 띄우니 느리다" | 지연 전량이 노트북→칠판 화면공유(네트워크) 구간 1.0~1.5초. 칠판→TV HDMI 구간은 0.1~0.2초로 정상 | D-08 |

증상 동의어: 후면 TV 안 나옴, 보조 모니터 안 됨, 화면 신호 없음, no signal, 듀얼 모니터 인식 안 됨, 비디오월 안 됨, 확장 화면 안 됨, 검은 띠, 레터박스, 화면 꽉 안 참, 화면 지연, 딜레이, TV가 늦게 나옴

## 먼저 받을 값

1. 구성: 전자칠판 모델·세대, 보조 화면(TV·모니터) 모델, 케이블과 분배기 유무, 어느 포트에 꽂았는지(사진).
2. Windows가 그 화면을 보는지: Win+P, 디스플레이 "감지" 결과 캡처.
3. 검은 띠면: 「설정 > 시스템 > 디스플레이 > 고급 디스플레이」의 디스플레이 1, 2 캡처 2장(D-13).
4. 지연이면: 화면 구성도(소스 → 칠판 → TV), 무선/유선 구간, 각 화면의 지연 체감 위치.
5. 하드웨어 건이므로 SN·시스템 버전·설치일도 받는다.

## 진단 흐름

- **보조 화면이 안 잡힌다**: Win+P와 디스플레이 "감지"로 Windows가 그 화면을 보는지 먼저 확인한다. Windows가 못 보면 ClassIn 문제가 아니다. 케이블이 전자칠판 패널의 HDMI IN이 아니라 **OPS의 HDMI 출력**에 꽂혀 있는지 본다. 노트북을 TV에 꽂아 보는 테스트는 TV 입력단만 검증한다(S-24, S-40).
  - S-24 방문 검증 순서(선례): OPS HDMI로 이설 → Win+P "확장" → 디스플레이 인식 → Video wall. 실패하면 정상 모니터로 OPS 출력 확인. 방문 시 예비 모니터를 챙긴다.
  - S-40 남은 확인(선례): 입력 소스 확인, 양끝 재연결, 선의 Source/Display 방향 표기 확인(방향성 광 HDMI 포함), 선 교체. 안 되면 여분 HDMI와 DP-HDMI 선을 들고 방문.
- **보조 화면에 검은 띠**: 「설정 > 시스템 > 디스플레이 > 고급 디스플레이」의 디스플레이 1, 2 캡처를 받아 데스크톱 모드와 활성 신호 모드의 화면비를 대조한다(D-13). 선례는 디스플레이 2 해상도를 패널 비율(3840×2160), 배율 100%로 바꿔 해소했다.
- **화면 지연**: 밀리초 스톱워치를 모든 화면에 띄워 동시에 찍고 구간별로 나눈다. 조건은 한 번에 하나만 바꾼다. 무선 환경의 화면공유 구간 지연은 1.0~1.5초가 실측 기준이고, HDMI 구간은 0.1~0.2초다. S86 2세대는 루프아웃을 지원하지 않는다(D-08, 3세대 98인치만 지원).

무선 미러링의 검은 여백은 `05-mirroring.md`(S-36)를 본다.

## 원인 후보와 확신도

- HDMI를 패널 HDMI IN(입력 전용)에 꽂은 오배선(OPS HDMI 출력 불량 미배제) — 추정 — S-24
- 후면 모니터 미인식(입력 소스, HDMI 선, OPS HDMI 출력 후보) — 미확정 — S-40
- 2차 화면 데스크톱 모드 16:10으로 16:9 패널에 레터박스 — 확정 — D-13
- 노트북→칠판 무선 화면공유 구간 지연 1.0~1.5초(실측). HQ "HW 개선 방안 없음" — 확정 — D-08

## 고객 안내 문구

결과 회신 뼈대(카카오톡):

```
안녕하세요, ○○님. ○○ 교실 화면 출력 건 확인 결과입니다.

▪ 원인
(확인된 사실. 추정이면 "~로 추정됩니다")

▪ 조치 / 현재 상태
(바꾼 설정 또는 배선, 남은 확인)

▪ 다시 발생하면
(알려 달라는 정보: 화면 사진, 디스플레이 설정 캡처)
```

쓸 때 지킬 것

- Windows가 화면을 못 보는 단계면 ClassIn 문제가 아님을 설명하되, 고객 장비 결함으로 단정하지 않는다. 원인 확정 전에는 "확인 중"까지만 한다.
- 지연 건은 "안 된다"보다 "사양은 이렇고(무선 구간 1.0~1.5초 실측) 그 안에서 이렇게 맞췄다"로 쓴다. HQ가 말한 수치를 단독으로 인용하지 않는다.
- 설정을 누가 해 두었는지 말하지 않고 상태만 쓴다("데스크톱 모드가 16:10으로 되어 있었습니다").
- 원인 회신에 점검 지시를 같이 싣지 않는다. 다만 다음 수업에 바로 필요한 조작 절차(해상도 변경 경로 등)는 같이 준다.
- 캡처는 필요한 영역만 잘라 보낸다.

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- Windows가 OPS HDMI 출력에 연결된 정상 모니터도 못 볼 때(OPS 출력 이상 의심).
- 지연 개선 방안(소프트웨어 트랙) 확인이 필요할 때. 선례는 HQ "HW 개선 방안 없음" 회신 후 SW 트랙 회신 대기(D-08).
- 화면비·배선·설정 문제로 판명되면 넘기지 않는다(D-13).

받는 곳(역할명)

- 하드웨어 1차: HQ 하드웨어 1차·원격 지원 담당(D-08 경유)
- 세대별: HQ 전자칠판 2세대 담당 / HQ 전자칠판 3세대 담당

적을 것

- 분류(`缺陷` / `疑似缺陷` / `需求`), 하드웨어 식별자(EEO Account, UID, 제품 SN, 설치일, 세대).
- 구성도, 케이블·포트, Windows 인식 여부, 구간별 측정값(지연 건).
- 시각은 중국 시각(UTC+8 = KST − 1시간).

기재하지 않는 값과 예외

- 기재하지 않는 값: Device ID, Client IP, Server, Owner. 증상 설명에 필요한 값만 예외로 적는다.
- 제품 SN 등 식별 값은 WeCom 발송문에만 넣고 이 저장소·적재 데이터에는 남기지 않는다.
