# API

증상 동의어: API 오류, 권한 오류, 권한 없음, 서명 오류, 인증 실패, 코스 생성 실패, 웹훅 안 옴, 콜백 안 옴, 데이터 구독, datasub, 콜백 주소 변경, 연동 오류, 참관 모드, 청강, 콘솔 흰 화면, API 문서 중국어

## 먼저 받을 값

1. 기관 SID(기관 UID). API에서는 SID와 SECRET 쌍이 인증 단위다. SECRET·safeKey 값 자체는 받지 않고 기록하지 않는다.
2. 호출한 API 이름(엔드포인트)과 요청 시각, 응답 원문(errno, 메시지).
3. 콘솔 API 로그 번호(HQ에 요청을 지목할 때 쓴다).
4. 일부러 넣은 비정상 요청(프로브)이 있었는지와 그 로그 번호(S-19).
5. 웹훅·콜백이면: 콜백 URL, 엔드포인트가 돌려주는 응답 본문, 구독 항목.
6. 콘솔 화면 오류면: 경로, 발생 빈도, 오류 문구 원문(캡처).

## 진단 흐름

1. **errno 102**는 순서대로 본다: 호출한 API가 실제로 있는지 → safeKey와 timeStamp 생성 → 쓰기 권한 활성화. 고객이 AI가 만든 코드로 없는 엔드포인트를 부른 선례가 있다(W-04). 조회 API가 성공했다는 것은 서명이 맞다는 근거가 되지 않는다(S-19).
2. HQ에는 콘솔 API 로그 번호로 요청을 지목한다.
3. **datasub 활성화, 콜백 URL 변경, VA 발급**은 WeCom이 아니라 HQ API 요청 전용 메일함으로 메일을 보낸다(주소는 사내 원문 참조). 사내 도메인(@classin.com) 계정에서 보낸 메일만 수신된다. 필수 정보는 SID, 콜백 URL, 알림 이메일, 구독 항목.
4. 웹훅 수신 실패는 응답 포맷부터 본다(W-03). 콜백 URL은 등록 전에 본사 쪽에서 DNS가 풀리는지 확인한다(W-05).
5. `addCourseClass` 등 v1 인터페이스는 2025-05-26부로 deprecated다. LMS 인터페이스로 안내한다.
6. AI 기능(요약, 스크립트)은 API로 제공되지 않는다.
7. 공식 문서는 docs.eeo.cn. 콘솔의 API 메뉴는 중국어 전용이라 영문 문서(docs.eeo.cn/api/en/)를 안내한다(T-04).
8. 확정이 필요한 API 사안은 HQ AI 교실·AI 녹화 제품 담당(제품)과 HQ API 총괄에게 확인한다. EEO 베트남 기술지원(HQ 공식 입장 아님)의 답만으로 고객에게 안내하지 않는다.

선례별 세부

- **S-19**: 프로브 로그만 보고 "safeKey 오류"로 진단한 선례가 있다. 정상 safeKey 요청도 102였고, "읽기 성공 = 서명 검증됨" 논리는 고객 실험(잘못된 safeKey로도 조회 성공)으로 무효가 됐다. 유효 근거는 "콘솔에서는 코스 생성 성공, API는 102"라는 대조다. 질문은 "102가 권한과 보안 검증 중 어느 쪽인지, API 경로에 별도 설정이 있는지"로 정리했다. `createClass`의 101002005(Signature error)는 고객이 sid·timeStamp 누락과 form→JSON 전환으로 자체 해결했다.
- **W-03**: 응답을 `{ "error_info": { "errno": 1, ... } }` 형식으로 수정한 뒤 정상. 문서상 "에러 10003 = 응답 포맷 오류" 일반 규칙이 있다.
- **W-04**: 문서 표기는 "No Permission"이며, 102는 공식 에러표상 보안 검증(safeKey) 실패이므로 ① 호출 API 실존 여부 ② safeKey/timeStamp 생성 로직 순으로 점검한다. 공식 문서 기준으로 연동하도록 안내.
- **W-05**: URL 교체 후 해소. URL 변경은 이메일로 요청한다.
- **W-08**: 원인 추정은 API로 생성한 리소스에서 `.enabled` 설정 객체가 초기화되지 않음. 발송문만 있고 결과는 기록되지 않았다.
- API와 기능 사양에 관한 HQ 답변은 공식 문서(docs.eeo.cn)와 교차 확인한 뒤 고객에게 전달한다.

## 원인 후보와 확신도

- errno 102가 권한 없음(쓰기 인터페이스 미활성)인지 보안 검증 실패인지 — 미확정(HQ 백엔드 판정 필요) — S-19
- 존재하지 않는 API 호출 — 추정(원문 단정형, 확신도 표기 없음 → 강등) — W-04
- 웹훅 엔드포인트 응답 포맷 미충족 — 추정(표기 없음 → 강등, 수정 후 정상) — W-03
- 본사 측 DNS 해석 실패(Supabase Edge Functions 도메인) — 추정(표기 없음 → 강등, URL 교체 후 해소) — W-05
- Datasub 승인 지연: HQ 내부 시스템 장애 — 추정(표기 없음 → 강등) — W-02
- API 링크가 아니라 모니터 섹션에서 auditor로 입장 — 추정(표기 없음 → 강등) — W-01
- 콘솔 코스 관리 크래시: `.enabled` 설정 객체 미초기화 — 추정 — W-08
- 콘솔 API 메뉴 중국어 전용 — 미확정(원인 미기재) — T-04

쓸 때 지킬 것

- HQ·베트남 측 답변은 공식 문서와 교차 확인한 뒤 전달한다. EEO 베트남 기술지원의 답은 HQ 공식 입장이 아니다.
- HQ가 확답하지 않은 기본값·사양은 전달하지 않는다.
- 서버명, 내부 로그 필드, 다른 고객 사례는 넣지 않는다. SECRET·safeKey 값은 어디에도 적지 않는다.
- 없는 엔드포인트를 불렀더라도 "잘못 쓰셨다"가 아니라 "공식 문서 기준으로는 이 API가 제공되지 않습니다"처럼 상태로 쓴다.
- AI 기능(요약, 스크립트)은 API로 제공되지 않는다는 점을 사양으로 안내한다.

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- errno 102 점검 순서(API 실존 → safeKey/timeStamp → 쓰기 권한)를 마치고도 권한·검증 중 어느 쪽인지 가를 수 없을 때(S-19).
- 콘솔 화면 크래시처럼 제품 결함이 의심될 때(W-08).
- datasub 활성화·콜백 URL 변경·VA 발급은 WeCom이 아니라 API 요청 전용 메일함으로 보낸다.

받는 곳(역할명)

- API 총괄: HQ API 총괄
- 제품 사양: HQ AI 교실·AI 녹화 제품 담당
- 보안·계정 권한: HQ 보안·백엔드 권한 담당
- 참고 창구: EEO 베트남 기술지원(HQ 공식 입장 아님) — 같은 문제를 먼저 겪은 경우가 많지만 확정은 HQ에서 받는다.

적을 것

- 콘솔 API 로그 번호로 요청을 지목한다. 일부러 넣은 비정상 요청(프로브)은 미리 알리거나 빼고 낸다. 프로브 로그 때문에 오진이 난 선례가 있다(S-19).
- 기관 SID, 호출 API, 요청 시각(중국 시각 UTC+8 = KST − 1시간), 응답 원문, 콘솔에서는 되는지 대조 결과.
- 분류: 버그 `缺陷`, 기능 요청 `需求`. 섞지 않는다.
- 확인 요청이 여럿이면 번호를 붙인다.

기재하지 않는 값과 예외

- 기재하지 않는 값: SECRET·safeKey 값, Device ID, Client IP, Server, Owner.
- 기관 SID와 로그 번호는 WeCom·메일 발송문에만 넣고 이 저장소·적재 데이터에는 남기지 않는다.
