# 결제

## 증상 표현

| 고객 표현 | 실제 현상 | 선례 |
|---|---|---|
| "원화로 받은 결제링크가 유로로 나온다" | KRW로 발행한 결제링크를 한국 고객이 열면 통화가 EUR로 표기되고, EUR 상태에서는 국내 결제수단(한국 카드 결제, 카카오페이, 네이버페이 등)이 노출되지 않음 | D-22 |
| "청구액보다 더 많이 빠져나갔다" | KRW→EUR→KRW 이중 환전으로 초과 결제 | D-22 |
| "충전 결제가 계속 로딩만 된다" | 실패 지점은 PG(Smartro) 이후 카드사(BC ISP) 인증 구간 — Airwallex·ClassIn 구간이 아님 | S-27 |
| "결제창·인증서 창 글자가 ◆로 깨진다" | Windows "Beta: 세계 언어 지원을 위해 Unicode UTF-8 사용" 옵션(코드페이지 65001)에서 나는 글자 깨짐 | S-27 |

증상 동의어: 결제 오류, 결제 실패, 결제창 멈춤, 무한 로딩, 결제링크 통화, 유로 결제, 원화 결제 안 됨, 카드 결제 안 보임, 간편결제 안 보임, 초과 결제, 환전 수수료, 결제창 글자 깨짐, 인증서 창 깨짐, 충전 실패

## 먼저 받을 값

1. 결제 시도 날짜·시각, 결제 수단(개인/법인 카드, 간편결제), 브라우저.
2. 어느 화면에서 멈췄는지 캡처(Airwallex 화면인지, PG·카드사 인증 창인지).
3. 통화 표기 문제면: 결제 화면 캡처(표시 통화, 보이는 결제수단).
4. 글자 깨짐이면: 깨진 창 캡처. Windows 언어 설정의 UTF-8 베타 옵션 상태(원래 꺼져 있으면 건드리지 않는다).
5. 결제 금액·카드 정보·결제링크 URL은 내부 처리 경로(결제 담당)로만 다루고 이 문서·적재 데이터에는 남기지 않는다.

## 진단 흐름

- KRW로 만든 Airwallex 결제링크가 EUR로 보이면: "다른 통화로 결제"에서 KRW를 고르고, "카드"가 아니라 "한국 카드 결제(Local Card)"를 고르게 한다(D-22).
- 결제창이 멈추거나 글자가 깨지면 실패 지점이 어느 구간인지(Airwallex, PG, 카드사 인증) 먼저 나눈다. 결제부터 되게 하고 원인 조사는 그다음이다. 우회는 간편결제나 카드사 앱결제(S-27).
- 금액 보상이나 환불 방침은 지사가 정하지 않는다. HQ 창구는 HQ 결제·인보이스 담당.

선례별 세부

- **D-22**: 근본 원인 미규명. Airwallex CS는 "고객 위치 기반 자동 표기"라 설명하나 한국 IP에서 재현되지 않는다고 적혀 있고(재현 주체 불분명), 본사도 재현 불가로 회신했다. 본사는 Airwallex 한국 계정 개설을 시도하겠다고 회신했다. 남은 것: 초과분 처리 방침(최우선), 한국 계정 개설 일정, Presentment Currency 설정값·KRW 고정 가능 여부, 타 고객사 초과 결제 전수 점검.
- **S-27**: 깨진 글자가 정적 UI인지 로컬 저장 데이터인지 구분한다. 체크가 원래 꺼져 있으면 건드리지 말고 캡처를 받아 `chcp`(949/65001)를 확인한다. 고액 결제 시 뜨는 팝업은 추가 본인인증 안내창이었다. 우회는 카카오페이/네이버페이, 페이북 앱결제(QR).
- 같은 UTF-8 베타 옵션 계열 글자 깨짐은 `08-app-launch-login-audio.md`(S-26)도 본다.

## 원인 후보와 확신도

- KRW 결제링크 EUR 자동 표기: 근본 원인 미규명(Airwallex 설명은 고객 위치 기반, 본사 재현 불가). 초과 결제의 직접 원인은 KRW→EUR→KRW 이중 환전 — 미확정 — D-22
- 충전 결제 실패·결제창 글자 깨짐: Windows UTF-8 베타 옵션(코드페이지 65001) + 법인카드 공동인증서 관문(고객 PC 미검증) — 추정 — S-27

## 고객 안내 문구

결과 회신 뼈대(카카오톡):

```
안녕하세요, ○○님. 결제 건 확인 결과입니다.

▪ 지금 결제하시는 방법
(우회 절차. 예: "다른 통화로 결제" → KRW 선택 → "한국 카드 결제(Local Card)" 선택)

▪ 확인된 내용
(확인된 사실만. 원인 미규명이면 확인 중이라고만)

▪ 추가 문의
(금액 관련 문의는 담당자가 확인 후 따로 안내)
```

쓸 때 지킬 것

- **결제부터 되게 한다.** 우회 절차를 먼저 주고 원인 조사는 그다음이다(S-27).
- **환불, 보상, 금액 처리 방침은 지사가 정하지 않고 먼저 꺼내지 않는다.** 결제·환불·중대 클레임 회신은 내부 승인이 필요한 범위다.
- 원인이 미규명이면 "고객 위치 때문" 같은 설명을 단정해 전하지 않는다(D-22).
- 결제 금액, 카드 끝자리, 결제링크 URL, 고객 PC 설정을 누가 바꿨는지는 회신에 넣지 않는다.
- UTF-8 옵션이 원래 꺼져 있으면 고객에게 건드리게 하지 않는다(S-27).

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- 결제 시스템 쪽(통화 표기, 계정 설정)이 원인으로 보일 때(D-22).
- 초과 결제·환불 처리 방침이 필요할 때 — 지사는 정하지 않는다.
- PG·카드사·고객 PC 구간 문제로 판명되면 결제 시스템 문의는 하지 않고 우회로 처리한다(S-27, HQ 문의안 미작성).

받는 곳(역할명)

- HQ 결제·인보이스 담당

적을 것

- 재현 여부(어느 환경에서 재현됐는지, 재현 주체), 영향 고객사 수, 우회 절차와 그 결과.
- 확인 요청은 번호를 붙인다(예: ① 초과분 처리 방침 ② 계정 설정값·KRW 고정 가능 여부 ③ 일정).
- 시각은 중국 시각(UTC+8 = KST − 1시간).

기재하지 않는 값과 예외

- 결제 금액, 카드 정보, 실사용 결제링크 URL은 이 저장소·적재 데이터에 남기지 않는다. HQ 결제 담당에게 필요한 값은 내부 결제 처리 경로로만 전달한다.
