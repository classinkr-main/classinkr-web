# 앱이 안 열린다·로그인 후 멈춘다·소리가 안 난다

## 증상 표현

| 고객 표현 | 실제 현상 | 선례 |
|---|---|---|
| "노트북에서 ClassIn이 안 열린다(휴대폰은 된다)" | 설치 후 더블클릭해도 무반응. 학생 PC에 인강용 DRM 플레이어(Kollus Player v3) 설치 확인 | S-08 |
| "태블릿에서 앱이 켜지자마자 꺼진다" | 같은 기기 이전 정상 입실 이력, 같은 계정 다른 기기 정상 — 버전·계정 문제 배제 | S-30 |
| "로그인하면 흰 화면에서 멈춘다(재설치·재부팅해도 같다)" | "Login succeeded"는 여러 건인데 입실 기록 없음. 기기 측 OS·앱·IP 변화 없음 | S-35 |
| "학생이 선생님 목소리를 못 듣는다" | 교사 마이크 표시는 움직이고 네트워크 지표 양호. 학생 iPad가 블루투스 이어폰 + Device List [Unknown] | S-15 |
| "설치 오류창 글자가 전부 ?로 나온다" | 글자 깨짐과 설치 실패는 별개. 백그라운드에서 다른 설치(Office) 진행 중 | S-26 |
| "인증번호·초기 비밀번호 문자가 안 온다" | 해외 SMS 업체 발송분이 한국 단말에서 해외 발신으로 인식돼 스팸 차단 | W-06 |
| "문자가 서로 다른 해외 번호로 여러 번 온다" | 하나의 문의에 대해 App과 AI Risk Monitor가 서로 다른 해외 번호로 SMS 발송 | W-07 |

증상 동의어: 실행 안 됨, 앱 안 열림, 클릭해도 반응 없음, 앱 꺼짐, 튕김(실행 직후), 강제 종료, 로그인 후 멈춤, 흰 화면, 로딩 안 됨, 소리 안 들림, 음성 안 나옴, 무음, 블루투스, 글자 깨짐, 물음표, 인증번호 안 옴, 문자 안 옴, 스팸 문자

## 먼저 받을 값

1. **조회 키**: 사용자 계정(반드시), 발생 날짜와 시각, 수업명(입실했다면).
2. 기기, OS 버전, 클라이언트 버전, 최신 여부. 같은 계정으로 다른 기기는 되는지, 같은 기기에서 다른 계정은 되는지.
3. 실행 직후 꺼지면: 꺼지는 장면의 화면 녹화(스플래시, 로그인, 홈 중 어디서). 재설치 여부, 최근 OS·보안앱 변화, 저장공간(S-30).
4. PC만 안 되면: 설치 파일 종류, 깔려 있는 보안 프로그램·인강 플레이어(S-08).
5. 소리가 안 나면: 출력 장치(블루투스 이어폰 등), 앱 권한, 같은 수업의 다른 학생은 들렸는지(S-15).
6. 글자 깨짐이면: 오류창 캡처, Windows 언어 설정 화면.
7. SMS 미수신이면: 수신 번호의 통신사, 스팸 보관함 확인 여부.

## 진단 흐름

1. 입실 전에 죽은 것은 콘솔 수업 기록에 없다. 로그인 이력에서 버전, 접속 노드, IP가 바뀐 시점을 찾는다(S-35).
2. **같은 기기에 다른 계정, 같은 계정으로 다른 기기**를 교차로 시험해 기기 쪽인지 계정·서버 쪽인지 가른다(S-30, S-35).
3. 모바일은 되고 PC만 무반응이면 인강용 DRM·보안 플레이어(Kollus Player, NSD 등)가 깔려 있는지 묻는다(S-08, 추정).
4. 실행하자마자 꺼지면 화면 녹화로 어느 단계(스플래시, 로그인, 홈)에서 꺼지는지 먼저 특정한다(S-30).
5. 소리가 아예 안 들리면 네트워크가 아니라 출력 경로다. 블루투스 이어폰, 앱 권한을 보고 같은 수업의 다른 학생은 들렸는지 묻는다(S-15).
6. 오류창 글자가 `????`나 ◆로 깨지면 Windows의 "Beta: 세계 언어 지원을 위해 Unicode UTF-8 사용" 옵션과 시스템 로캘을 본다(S-26, S-27).

보충(선례별)

- 콘솔 계정 조회(Account Quick Check)는 입실 세션만 보여주므로 실행 즉시 종료는 HQ 크래시 업로드나 인증 로그로 확인한다(S-30).
- 기기 측 변화가 0이면 서버·계정 쪽을 의심한다(S-35). 임시로 다른 기기 입실을 권고한 선례가 있다.
- 콘솔 시각은 이미 KST다. KST로 다시 환산해 시각을 틀린 선례가 있다(S-30).
- 깨진 오류창은 원문부터 복원한다. 중문판 기반 OPS는 로캘을 바꾸면 하드웨어 유틸 표시가 깨질 수 있어 UTF-8 베타 해제를 먼저 한다(S-26). 체크가 원래 꺼져 있으면 건드리지 말고 캡처를 받아 `chcp`(949/65001)를 확인한다(S-27).
- SMS 미수신(W-06) 임시 안내: 통신사 해외 문자 차단 해제, 스팸 보관함 확인. 근본 조치는 한국(+82) 발송을 국내 발신사(네이버 클라우드 SENS)로 전환하는 것으로 진행 중이었다.

## 원인 후보와 확신도

- 인강 DRM·보안 플레이어(Kollus Player v3·NSD류)의 카메라·마이크 접근 차단이 메시지 없이 실행을 막음 — 추정 — S-08
- iPad 블루투스 오디오 출력 라우팅 또는 앱 권한 — 추정 — S-15
- 태블릿 실행 직후 종료(저사양·가용 메모리 정황은 있으나 정상 이력이 있어 단정 불가) — 미확정 — S-30
- 로그인 후 흰 화면: 서버 측 또는 계정 데이터 변화로 홈 화면 로딩 실패 — 추정 — S-35
- 설치 오류창 글자 깨짐: 시스템 로캘·UTF-8 베타 옵션 불일치(설치 실패 원인은 미확인) — 추정 — S-26
- SMS 미수신: 해외 발신 SMS가 한국 단말에서 스팸 차단(원문 단정형, HQ·통신사 검증 기록 없음) — 추정(표기 없음 → 강등) — W-06
- 여러 해외 번호로 SMS 발송 — 미확정(원인 미기재) — W-07

## 고객 안내 문구

접수 직후 문구:

```
안녕하세요, ○○님. 클래스인입니다.
말씀하신 ○/○ 건 바로 확인해 보겠습니다.

정확한 기록을 찾기 위해 아래 내용 부탁드립니다.
▪ 로그인 계정
▪ 사용 기기와 발생 날짜·시각
▪ (가능하면) 앱이 꺼지거나 멈추는 장면 화면 녹화

기록을 확인한 뒤 원인과 함께 다시 안내드리겠습니다.
```

결과 회신 뼈대(카카오톡):

```
안녕하세요, ○○님. ○/○ 건 확인 결과입니다.

▪ 원인
(확인된 사실. 추정이면 "~로 추정됩니다")

▪ 지금 하실 일
(바로 할 조작)

▪ 다시 발생하면
(알려 달라는 정보: 기기, 발생 시각, 화면 녹화)
```

쓸 때 지킬 것

- HQ 1차 답변이 "네트워크 불안정"이어도 그대로 옮기지 않는다. 로그인 이력·지표와 대조한 뒤 쓴다(S-35).
- 확정 전 원인은 확인된 사실과 미확인 항목을 나눠 쓴다. 고객 기기·파일 문제 가능성은 확인 전에 언급하지 않는다.
- 원인을 가르기 위한 확인 요청(다른 기기로 로그인해 보기, 화면 녹화)은 목적을 밝혀 요청한다.
- 오류 코드, 서버명, 접속 노드, Client IP, Account ID는 넣지 않는다.
- 재설치·재부팅(restart)과 초기화(reset)를 구분해 적는다.
- 결제창 글자 깨짐은 결제부터 되게 하는 것이 먼저다(`12-payment.md`).

## HQ로 넘기는 조건과 적을 것

넘기는 조건

- 교차 시험(같은 기기/다른 계정, 같은 계정/다른 기기)으로 기기 쪽이 배제되고 서버·계정 쪽이 의심될 때(S-35).
- 실행 즉시 종료라 콘솔에 기록이 없을 때: 크래시 업로드 기록, 유사 사례, 기기 측 로그 확보 방법을 묻는다(S-30).
- 보안 프로그램 충돌·출력 경로·로캘처럼 고객 환경으로 판명되면 넘기지 않는다.

받는 곳(역할명)

- 1차: HQ 서비스 1차 접점(小助手)
- SMS: HQ SMS 담당, 인프라: HQ 인프라·데이터 저장 담당(W-06)
- EEO 베트남 기술지원(HQ 공식 입장 아님)이 "유사 건 해결"이라 해도 확정은 HQ 담당에게 따로 받는다(S-35).

적을 것

- 분류: `缺陷` / `疑似缺陷`, 기능 문의와 섞지 않는다.
- 기기, OS 버전, 클라이언트 버전, 최신 여부(HQ가 가장 먼저 되묻는다).
- 로그인 이력에서 본 시각과 변화(버전·노드·IP 변화 유무), 교차 시험 결과, 화면 녹화.
- 시각은 중국 시각(UTC+8 = KST − 1시간).
- 계정과 시각을 맨 위에 둔다.

기재하지 않는 값과 예외

- 기재하지 않는 값: Device ID, Client IP, Server(접속 서버·노드명), Owner. 노드·IP 변화가 증상의 직접 근거면 예외로 적는다.
- 위 값은 WeCom 발송문에만 넣고 이 저장소·적재 데이터에는 남기지 않는다.
