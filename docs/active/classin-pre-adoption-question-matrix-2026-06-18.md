## 1. 답변 원칙

- 이 질문지는 기능 설명표가 아니라 도입 전 리스크 체크리스트로 본다.
- ClassIn은 전자칠판 단품이 아니라 전자칠판, OPS, 녹화, LMS, 관리자 데이터, 권한 관리를 묶는 수업 시스템 OS로 답한다.
- 관리자, 권한, 스토리지, 개인정보, 서버, 계약, 가격은 단정하지 않고 최신 계약·정책 확인 범위를 분리한다.
- 기능이 가능한 항목도 "누가 볼 수 있는가"를 반드시 붙인다. 특히 녹화·저장·통계는 관리자 또는 권한 받은 계정 기준이다.
- 개인정보와 마케팅 추적 데이터, 학생 학습 데이터는 섞어 설명하지 않는다.

## 5. 공개 문서와 챗봇 반영 기준

신규 공개 문서 `pre-adoption-faq-22-questions`는 아래 질문에 답한다.

- "도입 전 어떤 질문을 확인해야 하나요?"
- "수업 녹화와 현장 녹화는 누가 관리하나요?"
- "회원가입 때 어떤 개인정보가 필요한가요?"
- "오프라인에서도 칠판을 쓸 수 있나요?"
- "스토리지, 서버, 콘텐츠 소유권은 어떻게 확인해야 하나요?"

챗봇 답변은 세 문단을 넘기지 않는다.

1. 먼저 가능한 것과 권한 기준을 답한다.
2. 계약·법무·서버·가격처럼 확인 필요한 것은 분리한다.
3. 관련 자료 또는 상담 CTA로 연결한다.

## 6. 리드 해석

이 질문지를 신청하거나 관련 질문을 많이 하는 리드는 "도입 전 검토 고의도 리드"로 본다.

- 관심사는 기능 체험보다 리스크 제거다.
- 상담에서는 먼저 "이미 어떤 장비와 도구를 쓰고 있는지"보다 "결정 전에 가장 불안한 항목이 무엇인지"를 묻는다.
- 서버, 개인정보, 소유권, 가격을 묻는 리드는 기술/계약 확인이 필요하므로 답변 속도보다 정확성이 우선이다.
- 녹화, 오프라인 칠판, 회원가입, 과제 같은 질문은 즉시 답변해 신뢰를 만든 뒤 확인 필요 항목을 담당자 확인으로 넘긴다.
- 리포트 자동화, 수업 일괄 알림, 자체 리포트 제작을 묻는 리드는 API 활성화 여부, 데이터 구독 범위, 개발 주체, 자체 시스템과의 동기화 방향을 별도 확인 항목으로 분리한다.

상담 요청 문장 예시:

> 우리 학원은 현재 ___ 때문에 ClassIn 도입을 검토하고 있습니다. 가장 확인하고 싶은 항목은 ___, ___, ___이고, 데모에서는 ___ 장면을 보고 싶습니다. 견적에는 ___까지 포함되는지 확인이 필요합니다.

| 레벨 | 기준 | 예시 |

| 쇼룸 검증 | 설명보다 실제 장면 확인이 빠르다. | 관리자 계정으로 녹화 찾기, OPS 단독 구동, 오프라인 칠판 필기, 외부 PC 연결 |

주의할 점:

- 스토리지 용량, 서버 위치, 가격, 무료/유료 권한은 이전 메모나 구두 정보만으로 단정하지 않는다.
- "가능"이라고 답할 때도 관리자, 권한 받은 교사, 학생 중 누가 접근하는지 붙인다.
- 전자칠판 비교 질문에는 하드웨어 스펙만 말하지 않고 EDB, 녹화, LMS, 관리자 데이터가 이어지는 흐름을 붙인다.
- 결제, 오프라인 출석, 고급 경영 리포트는 약한 영역이므로 API/외부 시스템/상담 확인 범위로 분리한다.
- API는 기능 가능성보다 인증, 데이터 구독 범위, 호출 주체, 개발·운영 책임, 개인정보 동의 절차를 먼저 확인한다.
