# Partner Portal Document Hub Guidelines

기준 시점: 2026-04-09

이 문서는 파트너 포털의 `문서 허브`를 행동 중심으로 재정의하기 위한 운영 지침이다.
문서 경험을 `만들기 / 발송하기 / 보기·정리` 3축으로 통일하고, 화면과 상태, 액션, 정리 기준을 하나의 원칙으로 묶는다.

## 1. 제품 한 줄 정의

파트너 포털 문서 허브는 `문서를 찾는 곳`이 아니라 `문서를 만들고, 보내고, 확인하고, 정리하는 운영 허브`다.

핵심 목표는 다음 3가지를 동시에 만족하는 것이다.

- 새 문서를 빠르게 만든다.
- 같은 방식으로 발송한다.
- 현재 상태를 한눈에 보고 정리한다.

## 2. 핵심 원칙

### A. 행동이 우선이다

- 사용자는 먼저 `무슨 문서를 할지`가 아니라 `무슨 행동을 할지`로 들어온다.
- 따라서 화면의 첫 분류 기준은 문서 종류가 아니라 `만들기 / 발송하기 / 보기·정리`다.
- 견적서, 계약서, 영수증은 모두 같은 운영 흐름 안에서 다뤄야 한다.

### B. 문서와 발송본을 분리한다

- `문서`는 원본과 버전의 기준이다.
- `발송본`은 그 문서가 외부로 나간 특정 전달 단위다.
- 한 문서에 여러 발송본이 붙을 수 있고, 발송본은 채널과 수신자와 만료 조건을 가진다.

### C. 상태는 줄이고, 의미는 분리한다

- 문서 상태와 발송 상태를 섞지 않는다.
- 보기 좋게 하나의 배지로 뭉개지 말고, 서로 다른 질문에 답하는 두 개의 상태 축으로 유지한다.

### D. 링크와 PDF는 목적이 다르다

- 링크는 열람과 공유 중심이다.
- PDF는 보관과 출력 중심이다.
- 둘을 같은 버튼처럼 보이게 하지 말고, 같은 문서에서 파생된 서로 다른 산출물로 취급한다.

### E. 정리는 폴더가 아니라 큐다

- 문서 정리는 사람이 폴더를 만들듯 수동으로 정리하는 구조보다, 상태와 다음 행동으로 자동 분류되는 구조가 맞다.
- `작성 중`, `발송 준비`, `열람됨`, `응답 대기`, `만료 임박`, `완료/보관` 같은 큐를 먼저 만든다.

### F. 반복 작업을 줄인다

- 마지막 거래, 마지막 수신자, 마지막 채널, 마지막 공개 버전은 모두 기억한다.
- 새 문서 작성과 재발송은 가능한 한 이전 문서를 복제하거나 이어쓰는 흐름이어야 한다.

## 3. IA 재구성

### A. 전역 네비게이션

권장 1차 메뉴는 다음처럼 단순화한다.

- `홈`
- `거래`
- `문서`
- `캘린더`
- `수납`

원칙:

- `견적서 / 계약서 / 영수증`은 전역 메뉴가 아니라 `문서` 안의 필터다.
- 사용자가 메뉴 이름만 보고도 행동을 떠올릴 수 있어야 한다.
- 문서 종류를 메뉴로 나누면 발송과 정리 기준이 분산된다.

### B. 문서 허브 내부 구조

문서 허브는 세 개의 작업 모드로 나눈다.

- `만들기`
- `발송하기`
- `보기·정리`

권장 화면 배치:

- 상단: 모드 전환 + 전역 검색 + 새 문서
- 좌측: 큐/필터/문서 종류
- 중앙: 문서 리스트 또는 편집 캔버스
- 우측: 선택 문서 상세, 버전, 발송 이력, 출력 정보

### C. 거래 상세와의 역할 분리

- 전역 `문서`는 운영 큐와 검색의 중심이다.
- 거래 상세의 `문서` 탭은 해당 거래에 붙은 문서를 빠르게 확인하고 수정하는 맥락이다.
- 전역 화면은 `모아보기`, 거래 화면은 `이어작업`에 가깝다.

## 4. 행동별 흐름

### A. 만들기

사용자가 해야 하는 일:

- `새 문서`를 누른다.
- 거래를 고른다.
- 문서 종류를 고른다.
- 템플릿을 고른다.
- 초안을 저장한다.

필수 원칙:

- 시작 버튼은 하나여야 한다.
- 시작점에서 문서 종류를 고를 수는 있지만, 종류별로 다른 진입점이 너무 많으면 안 된다.
- 새로 만드는 것보다 `최근 문서 복제`, `최근 거래에서 이어쓰기`가 더 빠르게 느껴져야 한다.

추천 보조 액션:

- `최근 문서 복제`
- `초안 이어쓰기`
- `이 거래의 마지막 문서 사용`

### B. 발송하기

사용자가 해야 하는 일:

- 발송할 버전을 고른다.
- 받는 사람을 고른다.
- 채널을 고른다.
- 보안 옵션을 확인한다.
- 발송한다.

필수 원칙:

- 발송 UI는 문서 종류마다 달라지지 않는다.
- 견적서, 계약서, 영수증 모두 같은 발송 절차를 탄다.
- 발송 직전에는 반드시 `버전`, `수신자`, `채널`, `만료`, `출력 허용`이 보인다.

추천 보조 액션:

- `링크 복사`
- `PDF 첨부`
- `카카오 재전송`
- `만료 연장`

### C. 보기·정리

사용자가 해야 하는 일:

- 현재 문서 상태를 확인한다.
- 마지막 발송과 마지막 열람을 본다.
- 다음 액션을 정한다.
- 필요 없는 것은 보관하거나 만료시킨다.

필수 원칙:

- 리스트는 `무슨 문서인지`보다 `무슨 상태인지`가 먼저 읽혀야 한다.
- 정리 기준은 폴더가 아니라 큐다.
- 문서 행의 가장 중요한 정보는 `최신 버전`, `마지막 발송`, `마지막 열람`, `다음 액션`이다.

추천 큐:

- `작성 중`
- `발송 준비`
- `발송됨`
- `열람됨`
- `응답 대기`
- `만료 임박`
- `완료/보관`

## 5. 문서 상태와 발송 상태 분리 규칙

### A. 문서 상태

문서 자체의 생애주기를 뜻한다.

권장 값:

- `draft`
- `ready`
- `active`
- `completed`
- `archived`

의미:

- `draft`: 아직 작성 중이다.
- `ready`: 발송 가능한 상태다.
- `active`: 외부에 노출되거나 협의가 진행 중이다.
- `completed`: 문서 목적이 끝났다.
- `archived`: 운영 대상에서 내려왔다.

### B. 발송 상태

외부 전달 단위의 생애주기를 뜻한다.

권장 값:

- `not_sent`
- `preparing`
- `sent`
- `opened`
- `expired`
- `revoked`
- `failed`

의미:

- `not_sent`: 아직 발송되지 않았다.
- `preparing`: 발송 준비 중이다.
- `sent`: 발송되었다.
- `opened`: 열람되었다.
- `expired`: 만료되었다.
- `revoked`: 회수 또는 폐기되었다.
- `failed`: 전달 실패가 발생했다.

### C. 두 상태를 섞지 않는 규칙

- 문서 상태가 `completed`여도 발송 상태는 `sent`일 수 있다.
- 문서 상태가 `ready`여도 발송 상태는 `not_sent`일 수 있다.
- 발송 상태가 `opened`여도 문서 상태는 여전히 `active`일 수 있다.
- 화면 배지는 상황에 따라 두 개를 함께 보여주되, 하나의 값으로 합치지 않는다.

### D. UI 표기 규칙

- 리스트에는 문서 상태를 주 배지로 보여준다.
- 상세 패널에는 발송 상태와 열람 상태를 별도로 보여준다.
- 문서가 여러 발송본을 가지면 최신 발송본과 대표 발송본을 구분한다.

## 6. 출력 / PDF / 링크 원칙

### A. 링크 원칙

- 링크는 버전 고정이어야 한다.
- 고객이 보는 링크는 항상 특정 버전을 가리킨다.
- 최신 버전으로 자동 치환하지 않는다.
- 재발송은 새 버전 또는 새 발송본으로 관리한다.

### B. PDF 원칙

- PDF는 보관용 산출물이다.
- PDF는 발행 시점 버전을 기준으로 만든다.
- 같은 문서라도 발송용 PDF와 출력용 PDF가 다를 수 있다면 분리한다.

### C. 출력 원칙

- 출력은 링크 열람과 분리한다.
- 출력 허용 여부를 문서/발송본 수준에서 명시한다.
- 출력 가능한 문서는 사용자가 바로 뽑을 수 있어야 하고, 출력 불가 문서는 이유가 보여야 한다.

### D. 채널 원칙

- 기본 채널은 링크다.
- 보조 채널은 PDF다.
- 상황에 따라 카카오나 이메일 같은 전달 채널을 추가하되, 채널마다 발송본이 따로 생긴다고 본다.

### E. 권장 버튼 묶음

- `링크 열기`
- `링크 복사`
- `PDF 저장`
- `출력용 열기`
- `재발송`

### F. 보안 원칙

- 원본 파일 URL은 직접 외부에 노출하지 않는다.
- 비밀번호가 필요한 경우 평문 저장을 피한다.
- 만료 연장은 기존 발송본을 되살리기보다 새 발송본을 만드는 쪽이 안전하다.

## 7. v1 우선순위

### P0

- 전역 `문서` 메뉴를 기준 허브로 두고, 종류별 메뉴 의존도를 줄인다.
- `만들기 / 발송하기 / 보기·정리` 모드를 문서 허브의 상단 기준으로 둔다.
- 문서 상태와 발송 상태를 분리한 데이터/표기 규칙을 확정한다.
- 문서 상세에 `버전`, `발송본`, `열람`, `출력` 정보를 한 화면에 묶는다.

### P1

- 공통 발송 모달을 하나로 통일한다.
- `최근 문서 복제`, `마지막 수신자 기억`, `마지막 채널 기억`을 넣는다.
- 리스트에 `다음 액션` 컬럼을 추가한다.
- 문서 허브에 스마트 큐를 도입한다.

### P2

- 거래 상세의 문서 탭과 전역 문서 허브의 역할을 더 명확히 분리한다.
- 재발송, 만료 연장, 출력 허용 변경 같은 고급 액션을 발송본 단위로 관리한다.
- 열람, 다운로드, 출력 로그를 상세 패널에서 시각화한다.

### 구현 시 금지

- 문서 종류별로 서로 다른 발송 플로우를 새로 만들지 않는다.
- 링크와 PDF를 같은 버튼 의미로 섞지 않는다.
- 정리 기능을 수동 폴더 구조로 먼저 풀지 않는다.

## 8. 최종 판단

문서 허브는 `문서함`이 아니라 `행동 허브`여야 한다.
사용자는 문서를 찾기 위해 들어오는 것이 아니라, 만들고 보내고 보고 정리하기 위해 들어온다.
이 원칙이 무너지면 문서 경험은 다시 종류별 탭과 파일함으로 되돌아간다.
