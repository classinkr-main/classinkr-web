# 콘텐츠 후킹 루프 랩 (Content Hook Lab)

기준일: 2026-10-28

| 단계 | 독자 상태 | 목표 행동 | 주 채널 | 출발점 리드마그넷 (intentScore) |
| --- | --- | --- | --- | --- |
| **TOFU** 인지 | 문제를 문제로 못 느낀다. 클래스인을 모른다 | 스크롤 멈춤 · 클릭 · 가벼운 자료 신청 | 블로그(검색·관점 전환), 메타·인스타 피드, 숏폼 첫 3초 | 27 이하 — 운영 누수 진단표, 비교 워크시트, 온라인 3분 판단표, 사례 매칭 브리프, 학부모 스크립트 키트 |
| **MOFU** 고려 | 문제를 알고 해법을 비교한다 | 자료 다운로드 · 이메일 열람 · 재방문 | 리드마그넷 랜딩, 이메일 너처링, 리타게팅, 비교형 블로그 | 28~33 — 전자칠판 체크리스트, 녹화→복습 가이드, 관리자 데이터 점검표, 90일 파일럿, 리소스 절감 계산, 강사 EDB SOP, 밤 10시 온라인 |
| **BOFU** 결정 | 클래스인을 검토 중. 리스크와 내부 설득이 고민이다 | 상담 · 쇼룸 예약 · 견적 요청 | 쇼룸·상담 CTA, 설명회, 영업 후속 이메일, 리타게팅 | 34 이상 — 데이터·API 브리프, 설치 AV 체크리스트, 쇼룸 데모 키트, 도입 전 22질문 |

- intentScore 구간은 출발점이다. 신규 리드마그넷 제안도 허용하되 `NEW:`로 표시하고 제작 난이도(상·중·하)를 붙인다.
- 단계별 톤([voice-charter.md](../brand-canon/voice-charter.md) §2·§3): TOFU는 긴장·관점 전환 허용(허위 공포 금지), MOFU는 비교·근거·자신감, BOFU는 안심·리스크 제거·다음 행동 1개(과장된 긴급성 금지). 이메일 카피에 홈의 공포 소구를 그대로 옮기지 않는다.

## 3. 후보 1개의 형식 (콘셉트 패키지)

| 필드 | 내용 |
| --- | --- |
| ID | `<T\|M\|B>-L<루프>-<번호>` (예: `T-L2-07`) |
| 앵글 | 찌르는 페인·관점 한 줄 (what-is-classin §3 페인 번호 표기) |
| 타깃 | 구매자(원장·실장·운영 책임자) × ICP 타입(입시·보습 / 다지점·프랜차이즈 / 온라인·하이브리드) |
| 후킹 | 첫 줄·썸네일 문구, 25자 이내 |
| 블로그 제목 | 40자 이내 |
| 리드마그넷 | 기존 slug 또는 `NEW: 이름 — 형식` |
| 카피 | 광고 기본 텍스트 2~3문장 |
| CTA | 버튼 문구 1개 |
| 근거 | 기댄 캐논 문서·섹션 |

한 루프의 20개는 서로 겹치지 않게 분산한다: 페인 6종 중 4종 이상, ICP 3타입 모두, 형식(질문형 · 숫자형 · 현장 일화·고백형 · 반론형 · 체크리스트형 · 비교형) 4종 이상.

## 4. 1루프 = 생성 → 테스트 → 랭킹 → 선별 → 3개

### 4.1 생성 (20개)

| 루프 | 구성 (합계 20) |
| --- | --- |
| 1 | 원장 명예의 전당 상위 3(디펜딩 챔피언, 원문 그대로) + 장점 풀 결합 7 + 신규 10. 원장이 비어 있으면 신규 20 |
| 2 ~ 마지막 | 직전 Top3 원문(엘리트) 3 + 변이 6(Top3마다 2개: 후킹만 교체 / 같은 앵글 다른 형식) + 교배 5(Top3 × 장점 풀) + 신규 6(아직 안 쓴 페인·ICP·형식 우선) |

- 신규 몫은 줄이지 않는다. 점수가 높은 앵글로만 수렴하는 것을 막는다.

### 4.2 테스트

**A. 하드 게이트** — 하나라도 걸리면 탈락(점수 0, 사유 기록).

1. 금지 표현([voice-charter.md](../brand-canon/voice-charter.md) §4, [positioning](../classin-korea-positioning-guidelines.md) §11).
2. 확인되지 않은 수치·가격·국내 기관 수·모델 스펙 단정. 회사 수치는 [company-facts.md](../brand-canon/company-facts.md) ✅ 값만, 출처 표기와 함께.
3. 지뢰밭 단정([what-is-classin.md](../brand-canon/what-is-classin.md) §9): 서버 위치·콘텐츠 소유권, "3개월이면 도입 완료", AI가 완벽히 판단, 재등록·성과 보장.
4. 한계 은폐: 결제·정산, 오프라인 출입·출석, 고급 경영 리포트, 자체 CRM·ERP를 클래스인이 해결한다고 읽히는 문장.
5. 단계 톤 위반: BOFU·이메일의 공포 소구, 허위 긴급성("오늘만", "마지막 기회").
6. 폐기어("학원 시스템 OS") 사용, 또는 기존 리드마그넷·블로그 제목과 사실상 같은 내용.

**B. 블라인드 심사** — Agent 도구로 **생성에 참여하지 않은 서브에이전트 1개**를 심사위원으로 띄운다. 심사위원에게는 게이트를 통과한 후보 본문(ID를 무작위로 다시 매기고 루프·출처·생성 의도는 숨김)과 아래 루브릭·페르소나만 준다. 서브에이전트를 쓸 수 없으면 직접 심사하고 보고서에 "자기 심사"라고 적는다.

- 루브릭 100점: 후킹 강도 25 · 페인 적중 20 · 단계 적합 20 · 리드마그넷 연결 15 · 신선함 10 · 이번 주 제작 가능 10
- 페르소나 패널 3명 — 각자 멈춤·클릭·행동(다운로드 또는 상담)을 0~5점으로 매기고 한 줄 반응을 남긴다.
  - P1 목동 중·고등 입시 보습 원장 — 단일 지점, 강사 8명, 구형 전자칠판 사용
  - P2 수도권 8개 지점 프랜차이즈 운영 실장 — 지점·강사 간 품질 편차, 표준화 고민
  - P3 오프라인 영어학원 원장 — 온라인 반을 열지 고민, 코로나 시절 줌 수업의 기억
- 최종 점수 = 루브릭 × 0.6 + 패널 평균(45점 만점을 100으로 환산) × 0.4
- 원장 '실측 피드백'의 이긴 패턴과 닮으면 +5, 진 패턴과 닮으면 −5 (사유 표기).

### 4.3 랭킹 · 선별

- 점수 내림차순. 동점이면 패널 '행동' 합 → 신선함 순.
- 1~3위 = 이번 루프 Top3 → 다음 루프의 엘리트.
- Top3 안에 앵글이 거의 같은 후보 2개가 있으면 낮은 쪽을 4위로 내리고 다음 후보를 올린다(다양성 유지).
- 4~10위 = 장점 추출: 후보마다 가장 좋은 요소 1개(단어 · 구조 · 앵글 · 형식)를 한 줄로 → 장점 풀.
- 11~20위와 탈락 = 폐기. 같은 탈락 사유가 반복되면 '피할 패턴'에 1줄 추가.

## 5. 최종 산출물 (마지막 루프의 Top3)

마지막 루프 Top3를 바로 제작에 넘길 수 있는 브리프로 완성한다.

1. **블로그** — 제목 3안, 메타 설명(80자 이내), H2 아웃라인 5~7개, 도입 첫 문단 초안, 글 말미 리드마그넷 연결 문단
2. **리드마그넷** — 기존 slug면 앞세울 섹션과 랜딩 첫 줄, `NEW`면 형식·목차·문항 수·제작 난이도
3. **광고 카피** — 메타 기본 텍스트 2안, 헤드라인 3안(40자 이내), 설명 1줄
4. **후킹 5종** — 썸네일 문구, 글·광고 첫 줄, 이메일 제목, 숏폼 첫 3초 대사, 알림톡 첫 줄
5. **실측 테스트 설계** — 무엇과 무엇을 비교할지, 채널, 성공 기준(지표·기간), 결과를 원장 '실측 피드백'에 적는 형식
6. **근거 · 리스크** — 기댄 캐논, 상담 확인이 필요한 표현

## 6. 기록

### 6.1 실행 보고서 — `docs/reports/content-hook-lab/<YYYY-MM-DD>-<STAGE>.md`

날짜는 KST 기준. 같은 날 같은 단계 파일이 이미 있으면 `-2`, `-3`을 붙인다.

1. 요약 — 최종 Top3 한 줄씩(점수), 루프별 최고점·평균 추이, 심사 방식(블라인드 / 자기 심사), LOOPS 값
2. 최종 Top3 완성안(§5)
3. 루프 로그 — 루프마다 20개 표(ID · 후킹 · 블로그 제목 · 리드마그넷 · 게이트 · 점수), Top3 표시, 추출한 장점, 폐기 사유 요약
4. 원장 반영 내역

### 6.2 원장 — `ledger/<STAGE>.md`

- **실측 피드백**: 사람 전용. 루틴은 읽기만 한다.
- **명예의 전당**: 이번 Top3를 넣고 점수 순으로 최대 10개 유지. 상태(후보 · 제작중 · 발행 · 보류)를 사람이 바꿨으면 덮어쓰지 않고, '제작중'·'발행' 항목은 밀어내지 않는다.
- **장점 풀**: 최대 30줄. 넘치면 오래되고 아직 쓰이지 않은 것부터 뺀다.
- **피할 패턴**: 최대 20줄.
- **실행 기록**: 한 줄 추가(날짜 · LOOPS · 최고점 · 보고서 링크).

## 7. 커밋 · 실패 처리

- 이 폴더(`docs/active/content-hook-lab/`)와 보고서 폴더(`docs/reports/content-hook-lab/`) 밖은 수정하지 않는다. 앱 코드·데이터·다른 문서는 건드리지 않으며 빌드·테스트는 필요 없다.
- 커밋 메시지: `content-hook-lab: <STAGE> <YYYY-MM-DD> <LOOPS>루프 Top3`
- push 전에 `git pull --rebase`. 단계마다 파일이 나뉘어 있어 충돌은 드물다. 충돌이 나면 원격 내용을 살리고 이번 실행분을 다시 얹는다. 네트워크 실패는 2·4·8·16초 간격으로 재시도한다.
- 루프 도중 실패하면 끝난 루프까지로 보고서를 쓰고, 요약 맨 위에 `중단: <사유>`를 적는다.

## 8. 사람이 할 일

- 아침에 보고서의 최종 Top3를 보고, 쓸 것은 원장 명예의 전당에서 상태를 '제작중'으로 바꾼다.
- 실제 광고·발행 성과(CTR · 다운로드 · 상담 전환)를 원장 '실측 피드백'에 적는다. 다음 실행부터 점수 가중치에 반영된다.
