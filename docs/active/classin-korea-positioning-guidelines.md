## 1. 핵심 정체성

Classin은 단순 화상수업 도구, 전자칠판, LMS 중 하나가 아니라 **학원 시스템 OS**로 설명한다.

한 문장 기준:

> Classin은 전자칠판, 수업 녹화, EDB 교안, LMS, 학생 관리, 관리자 데이터를 한 흐름으로 묶는 학원 시스템 OS입니다.

이 정체성은 홈페이지, 제품 페이지, 블로그, 가이드, 자료실, 챗봇, 상담 스크립트에 모두 우선 적용한다. 기능을 먼저 나열하기보다 "수업 전 준비 → 실시간 판서 → 녹화 → 복습 → 과제·시험 → 관리자 데이터"의 운영 흐름으로 설명한다.

## 2. 1순위 타겟

1순위 타겟은 한국 학원 원장, 관리자, 실장, 캠퍼스 운영 책임자, 교육기관 의사결정자다.

이들은 보통 아래 문제를 가지고 있다.

- 선생님 수업 준비, 녹화 배포, 보강 안내, 과제 관리가 여러 도구에 흩어져 있다.
- 전자칠판은 있지만 녹화, 자료 재사용, 학생 관리, LMS와 이어지지 않는다.
- 구형 전자칠판은 외장 PC, HDMI, 터치 케이블, 별도 녹화 프로그램, 라이선스 만료 문제로 운영 손이 계속 간다.
- Classin을 잘 모르기 때문에 "Zoom이랑 뭐가 달라요?", "기존 전자칠판이랑 뭐가 달라요?"라고 묻는다.
- 가격이 일반 전자칠판보다 높게 느껴질 수 있다.
- 좋은 수업이 강사 개인기와 개인 자료에 의존한다.
- 원장은 수업 품질, 특이사항, 네트워크 문제, 녹화·복습 제공 상태를 늦게 알게 된다.

## 3. 한국 로컬 도입 현실

한국 학원에서는 아직 온라인 전면 전환보다 오프라인 교실 중심 도입이 일반적이다.

- 가장 현실적인 첫 사용 범위는 전자칠판, 수업 녹화, 수업 관리다.
- 학생 개인 기기 기반의 완전한 하이브리드 수업은 일부 선도 학원에서 먼저 활용한다.
- 표준 도입 모델은 "전자칠판 실시간 판서 → 수업 녹화 → 다시보기 복습 → LMS 숙제·시험" 흐름이다.
- 도입 기간은 평균 3개월 안팎으로 설명하되, 보통 3~4개월, 넓은 기관은 6개월~1년까지 걸릴 수 있다고 안내한다.
- 국내 사용 기관·보드 수는 정확한 CRM/계정 데이터 확인 전까지 단정하지 않는다.

## 4. 가치 기둥

모든 콘텐츠는 아래 네 가지 가치 중 최소 하나에 연결한다.

| 가치 | 설명 |
| --- | --- |
| 강사 리소스 절감 | 수업 준비, 자료 재호출, 녹화 업로드, 복습 배포, 보강 안내, 상담 준비 시간을 줄인다. |
| 수업 품질 표준화 | 우수 강사의 교안·판서·수업 흐름을 EDB와 녹화로 남겨 반·강사·지점 편차를 줄인다. |
| 학생 경험 확장 | 오프라인/온라인 구분 없이 복습, 보강, 상호작용, 과제·시험 흐름을 더 촘촘하게 제공한다. |
| 관리자 운영 가시성 | 수업 시간, 출결·참여, 특이사항, 네트워크 상태, 녹화·LMS 데이터를 권한 기반으로 확인한다. |

## 5. 제품 설명 기준

### EDB

EDB는 Classin 칠판 파일이다. 판서, 이미지, 텍스트가 상호작용 가능한 상태로 유지되는 수업 파일로 설명한다.

강조할 점:

- 최대 50페이지 칠판과 함께 쓰면 수업 흐름을 페이지 단위로 이어갈 수 있다.
- 매번 칠판을 지우거나 자료를 하나씩 다시 띄우는 시간을 줄인다.
- 우수 강사의 판서·이미지 배치·문제 풀이 흐름을 기관 자산으로 남길 수 있다.
- 신규 강사 온보딩과 지점별 수업 표준화에 유리하다.

### Classin Board

Classin Board는 큰 화면 장비가 아니라, OPS와 Classin 소프트웨어가 연결된 수업 시스템으로 설명한다.

강조할 점:

- OPS 내장 PC를 통해 윈도우 기반 수업 환경을 제공한다.
- 일반 안드로이드 기반 디스플레이형 전자칠판과 달리 외장 PC·케이블·별도 녹화 프로그램 의존을 줄인다.
- 판서, 녹화, EDB, LMS, 클라우드 자료 흐름이 함께 작동할 때 가치가 커진다.
- 하드웨어 상담에서는 칠판, 카메라, 스탠드 또는 벽걸이, 소프트웨어, 온보딩을 한 패키지로 본다.

### 관리자 데이터

관리자 대시보드는 "감이 아니라 기준으로 운영을 보는 장치"로 설명한다.

확인 가능한 범위:

- 수업 시간과 진행 상태
- 출석·참여와 수업 특이사항
- 네트워크 상태
- 녹화·복습 제공 상태
- 과제·시험·LMS 활동
- 권한 있는 관리자 또는 교사 계정의 데이터 접근

학생 데이터와 내부 운영 데이터는 권한 기준을 분리한다. 마케팅 이벤트 추적과 학생 학습 데이터도 섞지 않는다.

### API와 자동화

API는 고급 고객에게 "가능성"으로 열어두되, 기술 문서 자체를 전면에 세우지 않는다. 원장 언어로 자동화 후보를 먼저 정리한 뒤 공식 API 문서로 연결한다.

설명 단계:

1. ClassIn 앱 푸시로 안내와 알림 업무를 정리한다.
2. 데이터 구독과 코스·수업 정보 조회 API로 운영 데이터를 가져온다.
3. SDK, 가상계정, 수업 중계 등은 공식 API 문서를 기준으로 별도 설계한다.

참고 링크:

- [ClassIn API 공식 문서](https://docs.eeo.cn/api/en/)

## 6. 정직하게 분리할 한계

Classin을 만능 학원 관리 프로그램처럼 말하지 않는다.

아래 영역은 과장하지 않고 별도 시스템, API 연동, 커스텀 리포트, 상담 확인 범위로 분리한다.

- 결제와 정산
- 오프라인 출입·출석
- 고급 경영 리포트
- 자체 CRM·ERP와의 세부 연동
- 모델별 정확한 가격, 재고, 설치 가능 여부
- 확인되지 않은 하드웨어 스펙
- AI가 사람의 정서, 뇌파, 학습 이전 상태를 자동 측정한다는 식의 표현

가격 질문에는 정확한 금액을 단정하지 않는다. 견적은 전자칠판 단품 가격이 아니라 전자칠판, OPS, 카메라, 스탠드/벽걸이, 소프트웨어, 설치, 온보딩이 포함된 학원 시스템 OS 구성으로 설명하고 상담으로 연결한다.

## 7. 비교 프레임

비교는 기능표보다 운영 흐름 기준으로 한다.

| 비교 대상 | 답변 기준 |
| --- | --- |
| Zoom | Zoom은 화상회의 중심이고, Classin은 수업 전 준비부터 판서, 녹화, LMS, 관리자 데이터까지 잇는 수업 운영 시스템이다. |
| 일반 전자칠판 | 일반 전자칠판은 화면 출력과 판서에 머무는 경우가 많고, Classin Board는 OPS·소프트웨어·EDB·녹화·복습 흐름까지 연결한다. |
| 학원 관리 프로그램 | 결제·오프라인 출석을 전부 대체한다고 말하지 않는다. 수업·학습 운영 데이터를 중심으로 기존 시스템과 연결할 범위를 정한다. |
| 별도 LMS | Classin은 LMS만이 아니라 실시간 수업, EDB, 녹화, 복습, 관리자 데이터가 함께 작동한다는 점을 강조한다. |

## 8. 콘텐츠 표면별 적용 기준

### 홈페이지와 제품 페이지

- 첫 메시지는 "전자칠판을 넘어, 학원 수업 운영을 하나의 시스템으로"에 가깝게 잡는다.
- CTA는 "도입 문의"만 반복하지 말고 쇼룸, 90일 로드맵, 리소스 절감 계산, 전자칠판 구축 체크리스트로 나눈다.
- 하드웨어 페이지는 화면 크기보다 OPS, 윈도우 기반, 카메라, 녹화, 클라우드 연결, 설치 방식으로 설명한다.
- 소프트웨어 페이지는 실시간 수업, EDB, 녹화, LMS, 관리자 데이터를 한 흐름으로 묶는다.

### 블로그

- 블로그는 문제 인식과 관점 전환을 담당한다.
- "왜 필요?", "Zoom이면 충분?", "전자칠판 있는데 왜 바꿔?" 같은 반론을 운영비·강사 리소스·표준화 관점으로 풀어낸다.
- 글 끝 CTA는 해당 주제와 가까운 리드마그넷 또는 상담으로 연결한다.

### 가이드와 문서센터

- 가이드는 기능 소개보다 운영자가 따라 할 순서, 체크리스트, 흔한 실수, 복사 문구를 우선한다.
- 챗봇이 바로 인용할 수 있도록 `chatbotSummary`는 원문보다 과장하지 않는다.
- 제품 기능명은 [classin-software-feature-inventory.md](./classin-software-feature-inventory.md)를 따른다.

### 자료실과 리드마그넷

자료실은 블로그와 가이드의 하위 CTA 허브로 둔다. 일반 랜딩, 제품 페이지, 블로그, 가이드에서 주제별 CTA로 끌어온다.

현재 리드마그넷 역할:

| slug | 역할 |
| --- | --- |
| `academy-system-checklist` | 전체 운영 누수 진단. 첫 접점과 포지셔닝 CTA에 사용한다. |
| `electronic-whiteboard-classroom-checklist` | 전자칠판 구매 전 교실 시스템 기준을 잡는다. 하드웨어 페이지와 장비 비교 글에서 사용한다. |
| `academy-software-selection-worksheet` | Zoom·전자칠판·LMS 비교를 기능명이 아니라 운영 흐름으로 정리한다. |
| `classin-90-day-adoption-roadmap` | 도입 일정이 구체화된 리드에게 파일럿 순서와 30/60/90일 기준을 제안한다. |
| `academy-resource-reduction-calculator` | 가격 부담 리드에게 줄어드는 강사 리소스와 반복 업무 시간을 숫자로 보게 한다. |
| `academy-admin-dashboard-template` | 원장·실장·관리자에게 주간 운영 지표와 권한 기준을 제안한다. |
| `academy-data-automation-brief` | API·리포트·자동화 니즈가 있는 고급 리드에게 원장 언어의 설계 브리프를 제공한다. |

### 챗봇

챗봇은 짧게 공감하고, 바로 기준을 잡아주고, 다음 행동으로 연결한다.

답변 원칙:

- Classin을 한 기능의 대체재가 아니라 학원 수업 운영 시스템으로 설명한다.
- Zoom, 전자칠판, LMS와의 차이는 기능명이 아니라 운영 흐름 기준으로 답한다.
- 약한 영역은 과장하지 않고 API, 외부 시스템, 상담 확인 범위로 분리한다.
- 가격 질문은 한 번에 금액을 단정하지 않고 학원 규모·상황·패키지에 따라 다름을 전제로 받는다. 단품 가격보다 구성과 줄어드는 운영 리소스로 프레이밍하고, 패키지 안내 페이지(`/l/omo1`)와 상담으로 연결한다.
- 전자칠판 사이즈·모델 질문은 S75·S86을 표준으로 먼저 안내하고, S98 Pro·S110 같은 대형 모델은 사용자가 대형 공간이나 특정 모델을 명시할 때 공개한다.
- EDB 질문은 "상호작용 가능한 칠판 파일", "50페이지 칠판", "교안 재사용"으로 답한다.
- 답변 끝에는 관련 가이드, 리드마그넷, 목동 쇼룸, 도입 문의 중 하나를 자연스럽게 연결한다.

대표 질문:

- "Classin은 Zoom이랑 뭐가 달라요?"
- "전자칠판 있는데 왜 또 바꿔요?"
- "EDB 파일이 뭐예요?"
- "수업 데이터와 리포트를 API로 연동할 수 있나요?"
- "가격이 비싼 이유가 뭔가요?"
- "우리 학원은 어떤 순서로 도입해야 하나요?"

## 9. CTA 운영 기준

CTA는 구매 압박보다 다음 판단을 돕는 쪽으로 설계한다.

| 상황 | 우선 CTA |
| --- | --- |
| Classin을 잘 모르는 첫 방문자 | 학원 시스템 OS 진단표, "Classin이 무엇인지" 가이드 |
| 전자칠판 비교 중 | 전자칠판 구매 전 교실 시스템 체크리스트, 하드웨어 상담 |
| 가격 부담 | 강사 리소스 절감 계산 워크시트, 견적 구성 가이드 |
| 도입 의향 있음 | 90일 파일럿 로드맵, 목동 쇼룸 상담 |
| 관리자 운영 고민 | 관리자 데이터·권한 운영 점검표 |
| API·자동화 니즈 | 학원 데이터·API 자동화 설계 브리프, 공식 API 문서 |

목동 쇼룸은 실제 수업 흐름을 체험하는 가장 강한 CTA다. 단순 문의보다 "우리 학원 대표 수업 자료를 가져와 EDB·판서·녹화 흐름을 확인한다"는 맥락으로 안내한다.

## 10. 추적과 리드 스코어링 기준

자료 다운로드와 CTA 클릭은 리드 의도를 남기는 행동으로 본다.

운영 원칙:

- 리드마그넷 `sourceDetail`은 `lead_magnet:{slug}` 형태를 유지한다.
- 다운로드 이벤트는 `download_materials`와 `lead_magnet` 값을 함께 남긴다.
- 자료실 카드 조회는 `view_resource_card`, 상세 조회는 `view_resource`로 남긴다.
- 고급 자료는 더 높은 intent score를 부여한다.
- 마케팅 픽셀과 리드 스코어링은 동의 정책을 따른다.
- 학생 학습 데이터와 마케팅 추적 데이터는 섞지 않는다.

리드 해석:

- `academy-resource-reduction-calculator`: 가격 방어·ROI 관심 리드
- `academy-admin-dashboard-template`: 원장/실장 운영 관리 리드
- `academy-data-automation-brief`: API·자동화 고의도 리드
- `classin-90-day-adoption-roadmap`: 일정 구체화 리드

## 11. 문장 규칙

권장 표현:

- "학원 시스템 OS"
- "수업 운영 흐름"
- "강사 리소스 절감"
- "수업 품질 표준화"
- "전자칠판, 녹화, EDB, LMS, 관리자 데이터가 한 흐름으로 이어집니다."
- "가격은 장비 단가보다 줄어드는 운영 리소스와 도입 범위까지 함께 봐야 합니다."

주의 표현:

- "모든 학원 관리 기능을 대체합니다."
- "결제와 오프라인 출석까지 모두 해결합니다."
- "AI가 학생 상태를 자동으로 완벽하게 파악합니다."
- "가장 싸다", "무조건 절감된다" 같은 보장형 문구
- 확인되지 않은 기관 수, 보드 수, 모델 스펙, 가격
