## 1. 핵심 관점

소형학원은 **에이스 강사 한 명**이면 굴러간다. 대형학원은 정반대다 — 강사·반·지점이 늘수록 **"좋은 수업이 개인기에 의존하는 구조" 자체가 경영 리스크**가 된다. (콘텐츠 코퍼스에서 22회 반복되는 핵심 명제: *좋은 수업이 에이스 개인기에 의존하면 안 된다 → 시스템으로 표준화*.)

대형에서 모든 문제는 **곱셈**으로 커진다: 강사 N × 반 M × 지점 K. 작은 누수도 수십 배로 쌓인다. 소프트웨어는 이 곱셈을 **표준화·자동화·가시화**로 되돌리는 장치다. 그래서 소프트웨어 ROI가 가장 크고 가장 차별화되는 구간이 **다지점·온라인·리포트 확장형 대형학원**이다. (현장형 소형 보습에서도 판서·녹화·복습 가치는 나오지만, 최고 가치 구간은 아니다.)

## 2. 5축 — 문제(대형에서 곱셈) → 소프트웨어 기능 → 효과

| 축 | 대형에서의 문제 | 클래스인 소프트웨어 기능 | 효과 |
| --- | --- | --- | --- |
| 수업 품질 표준화 | 반·강사·지점별 품질 편차 — 학부모 불만이 나야 비로소 보임(숨은 구매 동인) | EDB 교안(살아있는 칠판 파일, ~50p) · 문제 은행 · 공유 드라이브 | 에이스 수업을 복제 가능한 **기관 자산**으로. 신규강사 온보딩·지점 확장에도 품질 유지 |
| 강사 리소스 절감 | 준비·녹화·복습·채점 반복업무가 **강사 수 × 반 수**만큼 쌓임 | 녹화 자동 복습 배포 · LMS 자동채점·AI 출제(보조) · 일괄 수업 생성(2~50개) | 강사는 수업에 집중, 반복업무 시간을 구조적으로 절감 |
| 관리자 운영 가시성 | 원장이 모든 반·지점을 직접 못 봄 → 감으로 운영 | 수업 모니터링(Drop-in 잠입 감독) · 학습 데이터 · 권한 관리 | 감이 아니라 **권한 기반 데이터**로 문제를 학부모 불만 전에 포착 |
| 녹화 콘텐츠 통제 | 녹화 강의 무제한 재시청·콘텐츠 유출 리스크 | 녹화 수업 — 시청 횟수·재생 제어 · 열람 기간 · 저작권 보호 | 복습만 열고 콘텐츠는 보호 — 다지점·프랜차이즈에 특히 중요 |
| 수업 몰입 균일화 | 반마다 다른 참여도·수업 몰입 | 교실 도구(객관식/선착순 퀴즈·그룹 토론·랜덤 선택) · BYOD 개인 칠판 | 모든 반에 균일한 상호작용 + 학생별 풀이 즉시 피드백 |

## 3. 소프트웨어만의 기능 총람 (대형학원 앵글)

하드웨어 없이 소프트웨어만으로 나오는 가치 중, 대형학원이 특히 좋아할 기능들.

### A. 녹화·복습 — "결석생·복습을 자동화"

- **녹화 수업 / 다시보기**(콘텐츠 단일 최다 언급): 결석 보강·복습 제공을 강사 손 안 거치고 표준으로. 재등록·학부모 체감 가치.
- 대형이 특히 좋아하는 **통제 옵션**: 시청 가능 횟수 · 재생속도/플레이바 드래그 제어 · 열람 기간 · 저작권 보호 · 선행 학습 조건 · 토론 공간.

### B. LMS·평가 — "과제·시험·채점을 반 수만큼 절감"

- **LMS 학습활동 9종**: 숙제 · 시험 · OMR 카드 · 일일 과제 · 학습 자료 · 토론 · 녹화 수업 · SCORM.
- **AI 자동채점 · AI 출제**(항상 "보조"): 채점·출제 반복을 절감. **OMR 카드**로 오프라인 종이 시험을 디지털 채점 흐름으로.
- **AI 어학**(따라읽기·받아쓰기·외워말하기, 영어+중국어): 어학 대형학원 특화.
- 문제은행 "제공 범위"는 **기관 설정·계약에 따라 다름**으로 표기.

### C. 대량 운영·표준화 — "대형에서만 체감"

- **일괄 수업 생성(2~50개)**: 정규+특강+다반 시간표를 한 번에.
- **문제 은행**: 우수 문항을 기관 자산화·재사용.
- **EDB 교안(~50p)**: 우수강사 판서·풀이 흐름을 자산화 → 온보딩·지점 표준화(대형의 최대 레버).
- **공유 드라이브 / 리소스 센터 / 수업 자료 라이브러리**: 강사 간 자료 공유로 파편화 방지.
- **기관 브랜딩(로고·스킨)**: 프랜차이즈·다지점이 자기 브랜드 화면으로.

### D. 관리·가시성 — "원장이 못 보던 반을 본다"

- **수업 모니터링(Drop-in 잠입 감독, 알림 없이 접속)**: 여러 반 품질 실시간 점검. 표현은 "1분 스크린샷 감시" ✕ → **"권한 기반 운영 데이터 가시성"** ◯.
- **관리자 콘솔 데이터(학습 데이터·라이브&플레이백)**: 수업 시간·출결·참여·특이사항·녹화/복습 제공 상태.
- **권한 관리(계정 계층)**: 원장/실장/교사/지점별 접근 분리 — 다지점·다강사 필수.

### E. 수업 몰입·상호작용 — "반 편차 없이 균일한 몰입"

- **교실 도구 팔레트(30+)**: 객관식/선착순 퀴즈 · 그룹 토론 · 랜덤 선택(발표자 지정) · 트로피 순위 · 타이머 · STEM 가상실험(화학/물리/기하).
- **BYOD + 개인 칠판**: 학생 개인기기로 문제 받고 교사가 학생별 풀이를 한 화면에서 확인·피드백·상점.
- **온스테이지(1v0~1v12)**: 대형 반의 온·오프라인 병행 구성.

## 4. 정직하게 그을 선 (신뢰 무기)

소프트웨어를 "만능 학원 관리 프로그램"처럼 말하지 않는다. 아래는 대체가 아니라 **별도 시스템 / 공식 API / 커스텀 리포트로 역할 분담**이 정직하다.

- 결제·정산 · 오프라인 출입·출석 · 고급 경영 리포트 · 자체 CRM·ERP 세부 연동.
- AI는 항상 "보조"로 hedge(자동으로 완벽 측정한다는 표현 금지).
- 가격·국내 기관/보드 수·모델 스펙은 공개 문서에 단정하지 않는다 → 규모 확인 → 패키지 안내 → 상담 확정.

## 5. 세일즈·콘텐츠 적용

- **관점 순서**: 기능 나열보다 "흩어진 도구가 운영비·강사 리소스를 먹는다 → 곱셈으로 커진다"를 먼저.
- **비교는 운영 흐름 기준**: Zoom/일반 전자칠판/학원관리 프로그램/별도 LMS와의 차이는 기능표가 아니라 수업 운영 흐름으로. (positioning §7)
- **CTA**: 목동 쇼룸(대표 수업 자료 지참) · 90일 파일럿 로드맵 · 강사 온보딩·EDB SOP · 관리자 데이터 점검표. 가격 부담 리드는 리소스 절감 계산 워크시트. (positioning §9)
- **리드마그넷 연결**: `teacher-edb-onboarding-sop-kit`(표준화), `academy-admin-dashboard-template`(가시성), `academy-resource-reduction-calculator`(리소스 절감/ROI), `parent-replay-retention-script-kit`(녹화·복습).
