## 1. 병합 원칙

제공 묶음은 새 정본이 아니라 상세 후보, 현장 메모, 마케팅 카피, 자산 위치 정보로 취급한다. 적용 우선순위는 다음과 같다.

1. 현재 저장소가 명시한 SSOT
2. 적용 모델·세대·시장·효력일이 확인된 최신 공식 원문
3. 원문과 연결된 한국어 정리본
4. 재현 조건이 기록된 현장 검증
5. 제공 묶음의 후보·TODO·프로젝트 메모

자료가 다르면 하나를 임의로 고르지 않는다. `확정`, `조건부`, `자료 충돌`, `본사 확인 필요` 상태를 유지하고, 고객에게 전달하기 전에 CS 담당자가 적용 범위를 판단한다.

## 3. 주요 충돌 결정

### 브랜드와 회사

- 한국 1차 카테고리는 **수업 시스템 OS**다. `가장 교실다운 AI 교육 플랫폼`은 마케팅 슬로건 후보이며 카테고리를 대체하지 않는다.
- 회사 수치는 [회사 팩트 SSOT](./brand-canon/company-facts.md)를 따른다. 제공 묶음의 8만+ 기관, 30억 USD 가치평가, 미확인 기술 파트너는 사용하지 않는다.
- 국내 도입 기관 수, 사례 성과, 학술 효과 수치는 공개 동의와 원자료 확인 전 단정하지 않는다.

### 소프트웨어

- 현행 기준은 EDB 교안, 50페이지 칠판, 30+ 교실 도구, 녹화→복습→LMS 흐름, 일반 LMS 활동 9종이다.
- 녹화 다운로드, 워터마크, 저작권 보호는 관리자 권한·설정·계약 범위에 따라 달라질 수 있다. `항상 앱 전용`, `항상 다운로드 차단`으로 말하지 않는다.
- RAG 기반 기관 AI, AI 음성 어시스턴트, 2,000명·49카메라·50ms는 버전·계약·한국 제공 범위를 확인한다.

### 보드와 마이크

- 한국 현행 보드 라인업은 S65·S75·S86·S98 Pro·S110이다.
- 2.0 세대는 S65/S75/S86/S110, 3.0 세대는 S65/S75/S86/S98 Pro다. 정확한 수치는 [기능·제품 인벤토리](./classin-software-feature-inventory.md)의 검증표를 사용한다.
- S75·S86은 세대에 따라 모델명, OPS, 소비전력, 치수가 달라질 수 있다. 답변 전에 모델명과 세대를 확인한다.
- S65는 현행 정본에서 규격서 미확보다. 제공 묶음의 수치만으로 확정하지 않는다.
- 현행 마이크 정본은 DT2 Pro(MS21A)다. DT1(MS10A)은 레거시·특정 패키지 참고이며 S110 필수 구성으로 자동 적용하지 않는다.

### 카메라와 PoE

- T1/S1은 고정형 4K 추적 카메라, OT1/OS1은 20배 광학줌 PTZ 별도 라인이다.
- OT1의 802.3af 지원은 본사 확인 상태다.
- OS1은 PoE 단독 현장 동작이 확인됐지만, 정확한 802.3af 규격 지원은 별도 본사 확인이 필요하다.
- PoE 문의에는 카메라 모델, PoE 스위치·인젝터 규격, Cat5e 이상 케이블, 거리와 실제 설치 결과를 함께 기록한다.
- T1/S1의 렌즈·화각·크기는 규격서와 설명서가 충돌한다. 현행 정본은 규격서 값을 우선하되 공개 전 적용 모델을 재확인한다.

### 가격·계약·환불·보증

- 제공 묶음의 글로벌 최소 결제 주기, 장기 결제 할인, 선불·환불 불가 문구를 한국 정책으로 사용하지 않는다.
- 주문·계약·프로모션·결제 내역을 확인한 뒤 담당자가 환불 가능 여부와 일정을 안내한다.
- AS 기간, 출장 AS, 모델별 설치 가능 여부와 비용은 최신 계약·견적·현장 확인 전 확정하지 않는다.

## 4. 소통 템플릿

### 고객 임시 안내

```text
안녕하세요.
현재 확인된 범위: {confirmed}
추가 확인 중인 항목: {pending}
확정 전 안내하지 않는 항목: {guardrail}
다음 안내: {owner} · {reply_due_at}
```

마케팅 CTA나 위기감을 넣지 않고 상태, 확인 범위, 다음 시점을 전달한다.

### 내부 인수인계

```text
[CS-{case_id}] {one_line_summary}
우선순위 / 상태 / 담당자:
분류 태그:
제품·모델·세대·앱 버전:
문의 / 현상:
영향·긴급도:
확인한 내용 / 시도 결과:
고객에게 안내한 내용:
미확정·충돌·리스크:
다음 액션 / 담당자 / 기한:
관련 근거·첨부:
```

### 본사 확인

```text
[KR-CS][{priority}][{area}][{case_id}] {summary}

Case: KST 발생시각, 한국 담당자, 최소화한 기관·계정 식별자, 모델·세대·버전
Impact: 영향 사용자·수업·기기 수, 수업 차단 여부, 고객 시한
Reproduction: 절차 / Expected / Actual / Frequency
Korea checks: 확인 항목 / 시도한 조치 / 임시 우회 결과
Evidence: 개인정보 제거 첨부와 내부 케이스 링크
Request: 질문 1~3개, 원인·조치·버그 여부·ETA 중 필요한 항목
Reply needed by: {KST}

Please include applicable market/models, generation, effective date, and source document/version.
```

본사 회신 원문과 한국어 요약은 함께 보존한다. 회신을 고객 답변으로 자동 전송하지 않는다.

## 5. 태그와 큐

태그는 검색 가능한 안정 분류에만 쓴다.

- 영역: `area:software`, `area:board`, `area:camera`, `area:mic`, `area:billing`, `area:account`, `area:contract`
- 의도: `intent:howto`, `intent:incident`, `intent:policy`, `intent:install`, `intent:hq_confirmation`
- 주제: `topic:recording`, `topic:login`, `topic:audio_video`, `topic:network`, `topic:permission`, `topic:refund`, `topic:warranty`
- 근거: `evidence:confirmed`, `evidence:conditional`, `evidence:hq_pending`, `evidence:conflict`, `evidence:field_verified`

상태, 우선순위, 담당자, 다음 액션, 기한, 대기 대상은 태그에 섞지 않고 구조화 필드로 관리한다. 코파일럿의 권장 태그는 자동 적용하지 않고 담당자가 확인한다.

## 6. 원문과 자산 운영

- 한국어 정리본을 활성 지식으로 사용하고 원어 원본은 검증용으로 보존한다.
- 정리본에는 출처일, 문서 버전, 모델 코드, 세대, 시장 범위, 원문 위치를 남긴다.
- 숫자와 모델 코드는 번역하거나 임의 보정하지 않는다.
- 캡처·사진·로그는 고객·학생 얼굴, 연락처, 계정, 계약·결제 정보를 확인하고 최소화한다.
- 내부 AI·MCP로 원본을 보낼 때는 기본값을 끄고 담당자의 민감정보 확인 뒤에만 포함한다.
- Drive·WeCom 접근 정보는 내부 근거 위치이며 고객 답변·외부 템플릿에 노출하지 않는다.

## 7. 코드 적용

- [내부 CS 지식 선택기](../../lib/internal-cs-chat/knowledge.ts)가 질문과 큐 태그를 기준으로 관련 항목을 선택한다.
- [코파일럿 컨텍스트](../../lib/internal-cs-chat/context.ts)가 공개 문서 근거와 정리된 내부 기준을 함께 모델에 전달한다.
- 자료 충돌 또는 본사 확인 항목이 선택되면 심층 검토를 요구하고, 고객 초안에는 외부 사용 경계를 유지한다.
- 답변 메타데이터에는 선택한 지식 ID, 상태, 외부 사용 범위, 검토 사유와 권장 태그를 남긴다.
- 화면의 `소통 초안 3종`에서 고객 임시 안내, 내부 인수인계, 본사 확인 문안을 대화 맥락으로 생성한다.

## 8. 갱신 절차

1. 새 본사 자료나 현장 결과를 받으면 기존 항목의 모델·세대·시장·버전과 비교한다.
2. 원문과 한국어 요약을 연결하고 변경 지점을 기록한다.
3. `확정`, `조건부`, `자료 충돌`, `본사 확인 필요` 중 하나를 지정한다.
4. 외부 사용 범위를 `담당자 검토 후 안내`, `내부 전용`, `확인 전 단정 금지`로 지정한다.
5. CS 담당자 검토 뒤 정본과 지식 선택기를 함께 갱신한다.
6. 승인·수정 사례를 회귀 후보에 넣고 기존 질문에 대한 상태·모델 라우팅이 유지되는지 확인한다.
