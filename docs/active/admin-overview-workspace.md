# Admin Overview 운영 브리핑

`/admin/overview`는 브리핑과 스코어카드를 결합한다. 상단 요약 → 먼저 볼 항목 → 리드·데모·설치/배송 현황 → 기존 유입 차트와 퍼널 → 전체 지표 → 일정·콘텐츠·캠페인 순서다. 참조 시안의 예시 실적·추이·목표는 사용하지 않는다.

## 원천과 집계

| 영역 | 원천 | 표시 기준 |
| --- | --- | --- |
| 리드 현황 | 기존 Overview lead summary | 테스트·미확인 제외, 현재 신규·연락중·전환·종료 상태. 24시간 후속 신호는 기존 action-kpis 정의를 그대로 사용하며 확인 게이트가 다르다. |
| 데모 현황 | Compass 읽기 전용 `compass_demos_v` | 실제 `kind=demo` 회차. 예정은 오늘~30일 뒤 `booked`, 완료 기록은 이번 달 `done`. 지난 예약을 완료로 추정하지 않는다. 미팅·취소·노쇼는 예정에 합치지 않는다. |
| 설치·배송 예정 | `hardware_movements` | 취소되지 않은 outbound 중 재고 원장의 동일 예정 판정을 적용한 전량. 품목 행 수와 장비 수량을 구분하며, 날짜 경과·미지정도 남긴다. |
| 연간 매출 | 기존 Branch summary, REV 확정 | 4–3월 회계연도, CNY. 승인 목표만 사용하며 미승인 조정안은 제외한다. |
| 나머지 운영 지표 | 기존 OS·방문·챗봇 요약 | 기존 소스별 health와 실패 재시도를 유지한다. 하드웨어·콘텐츠·행사 기준은 기존 운영 기준이라고 명시한다. |

데모·설치 집계 날짜는 한국 시간 기준이다. 데모의 조회 상한 도달은 부분 집계로 표시하고 합계를 최소치로 표기한다. 데모 회차와 Admin 리드는 모집단이 다르므로 두 수치를 전환 퍼널처럼 나누지 않는다. 설치·배송 예정은 미확정 원장 기록이며 설치 확정·출고 완료·매출 실적으로 간주하지 않는다. 원장 날짜는 캘린더 날짜로 읽고 오래된 예정도 연도를 포함해 보여준다.

## 구현·권한·장애

- `lib/admin/overview/operations-summary.ts`: 순수 집계 및 날짜 창.
- `lib/admin/overview/operations.ts`: 읽기 전용 원천 조립, 소스별 실패 격리.
- `/api/admin/overview/operations`: 기존 하드웨어 읽기 역할을 검증하고, 데모는 추가로 CRM 읽기 역할을 확인한다. CRM 권한이 없으면 데모 원천을 호출하지 않는다.
- 하드웨어 저장소는 키셋 페이지로 전량 조회해 대시보드의 최근 2,000행 제한으로 예정이 누락되지 않게 한다. 기존 하드웨어 캐시 무효화 태그를 공유한다.
- 클라이언트는 새 운영 응답을 영속 캐시하지 않는다. 조회 실패는 0건으로 대체하지 않고 정상 소스는 유지한다. 개별 원천 재시도와 전체 재시도를 제공한다.
- 전체 지표는 영역 선택·주의 항목 필터를 제공한다. 추이에는 실제 원천 시계열만 쓰고 시안의 예시 변화율·스파크라인을 복제하지 않는다.

이 화면의 조회·검증은 원천 시트, Compass 기록, 재고 원장을 수정하거나 동기화를 실행하지 않는다.
