# Classin CS 팀 운영 표준 가이드 런북 (CS Ops Standard Runbook)

- **기준 일자**: 2026-08-07
- **문서 목적**: Classin 어드민 CS 운영 데스크(`/admin/cs-chatbot`), 보강 큐(`question_clusters`), 회귀 검수 시스템을 사용하는 CS 매니저 및 담당자를 위한 표준 운영 절차(SOP)입니다.

---

## 1. CS 운영 데스크 계기판 대시보드 (`/admin/cs-chatbot`)

운영 데스크 상단 스트립에는 실시간 고객 응대 및 챗봇 연동 지표가 표기됩니다.

1. **질문 및 대화 수 (Volume)**: 최근 7일/30일 기준 접수된 전체 질문과 대화 세션을 나타냅니다.
2. **폴백 비율 (Fallback Rate)**: AI/챗봇이 확답을 주지 못하고 기본 안내문(Fallback)을 제시한 비율입니다. **Target: 15% 이하 유지**.
3. **초안 승인율 (Approval Rate)**: 내부 CS 응대 생성 건 중 관리자 검토를 통해 확정된 비율입니다.
4. **모델 모드 (Model Mode)**:
   - **자동 (Auto)**: 기본 빠른 응답 모델(Flash)을 사용합니다.
   - **Pro 심층 검토**: 라이선스, 계약, 복잡한 네트워크 장애 건은 Pro 모델로 재검토를 실행합니다.

---

## 2. 미해결 질문 보강 큐 (`question_clusters`) 처리 절차

챗봇이나 내부 CS에서 반복 발생한 미해결 질문은 **문서 보강 큐 (`/admin/docs?tab=gaps`)**로 유입됩니다.

### 처리 5단계 흐름:
1. **큐 수집 확인**: 소스 배지(`챗봇`, `내부CS 폴백`, `내부CS 검토`)를 확인합니다.
2. **대화 딥링크 검토**: "대화 열기" 버튼을 클릭하여 고객이 유입된 실제 대화 텍스트 맥락을 파악합니다.
3. **기존 문서 매핑**: 이미 관련 문서가 있다면 해당 클러스터에 `mappedArticleId`를 지정합니다.
4. **신규 문서/FAQ 초안 작성**: 기존 지식이 없다면 "초안 저장"을 누르고 `DocsArticleEditor`에서 새 FAQ 지식을 발행(`status="published"`)합니다.
5. **자동 재색인 확인**: 문서 발행 또는 매핑 즉시 RAG 청크(`docs_ai_chunks`)에 자동 반영되며 큐 상태가 `published`로 전환됩니다.

---

## 3. 회귀 검수 후보 (Regression Candidates) 판정 가이드

이전 답변 또는 문서 수정 후 회귀 검수 항목에 등록된 건은 다음 4가지 상태로 판정합니다.

- **`통과 (Pass)`**: 답변이 정확하고 고객 문의가 적절히 해소됨.
- **`수정 필요 (Needs Fix)`**: 지식이 부족하거나 오해의 여지가 있어 지식 보강 큐로 재유입 조치.
- **`반영됨 (Promoted)`**: 관련 문서가 신규 작성되거나 보강되어 지식으로 승격 완료됨 (문서 매핑 시 자동 전파).
- **`제외 (Excluded)`**: 단순 오타, 의미 없는 텍스트, 테스트 질의인 경우 큐에서 제외.

---

## 4. CS 응대 톤 & 보이스 헌장 (Voice Charter)

1. **마케팅 카피와 CS 응대 톤 분리**:
   - '아직도', '시대는 끝났습니다', '200% 구매', 자극적인 구매 유도 카피를 CS 고객 답변 기본 문안에 넣지 않습니다.
2. **권장 순서와 점검 문장 제공**:
   - 불안을 자극하지 않고, 사용자가 즉시 실행할 수 있는 확인 순서(전원, 콘센트, 네트워크 연결 등)를 부드럽게 안내합니다.
3. **검토 상태 명시**:
   - 확정되지 않은 수리/환불/계약 건은 임의로 승인하지 말고 담당자의 검토 상태를 명확히 안내합니다.

## 6. 채널톡 최근 문의 원인 검토 (`/admin/channel-talk`)

채널톡 문의는 고객이 처음 표현한 증상만으로 분류하지 않고, 상담 과정에서 확인된 실제 원인과 해결 결과까지 연결합니다.

1. **최신 상담 동기화**: `최근 상담`에서 동기화를 실행합니다. 기본 동기화는 열린 상담과 종료 상담을 함께 가져옵니다.
2. **원인 검토 열기**: 상담 행의 `원인 검토`를 누릅니다. 상담 전문은 행을 열 때만 조회됩니다.
3. **후보 선택 또는 수동 작성**: 자동 후보가 있으면 수정하고, 없으면 `수동 검토`를 선택합니다. 자동 후보는 확정 답변이 아니라 검토 초안입니다.
4. **연결 정보 기록**: `표면 증상 → 실제 원인 → 판별 질문 → 해결 방법 → 해결 결과` 순서로 보완합니다. 한 상담에 문제가 여러 개면 후보별로 나누어 저장합니다.
5. **근거 선택**: 실제 원인을 확인한 상담원 메시지와 필요한 고객 메시지를 선택합니다. `승인 + 확정` 사례는 실제 원인과 상담원 근거가 모두 있어야 저장됩니다.
6. **시각 자료 확인**: `[이미지 첨부]`, `[파일 첨부]` 또는 사진·캡처 언급이 보이면 채널톡 데스크에서 원본을 확인합니다. 파일 URL·파일명·스토리지 키는 내부 전문과 검색 청크에 저장하지 않습니다.
7. **상태 판정**:
   - `검토 중`: 추가 확인이 필요합니다.
   - `승인`: 담당자가 근거를 확인했습니다.
   - `제외`: 잘못 분리됐거나 지식화할 가치가 없는 후보입니다.
   - 원인 확정도는 `미확인 / 추정 / 확정`, 해결 결과는 `결과 미확인 / 해결 방법 안내 / 고객 해결 확인 / 아직 미해결`로 별도 기록합니다.
8. **지식 승격 경계**: 저장 또는 승인만으로 공개 챗봇 답변, 골든셋, 문서 검색 지식에 자동 반영되지 않습니다. 반복성과 재현성을 별도로 검토한 뒤 문서 보강 큐에서 명시적으로 승격합니다.

최초 배포 시 [원인 검토 저장소 마이그레이션](../../supabase/migrations/20260807_channel_conversation_cases.sql)을 먼저 적용합니다. 미적용 상태에서는 후보와 상담 전문은 읽을 수 있지만 저장은 잠깁니다.
