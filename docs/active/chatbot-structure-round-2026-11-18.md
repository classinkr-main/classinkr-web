# 챗봇 구조 변경과 측정 — 정해 둔 답 관문, 두 번째 검색, 모델 장애 시 고정 문구(2026-11-18)

기준일: 2026-11-18 · 담당 파트: 챗봇/CS([플레이북 05](./playbook/05-chatbot.md))

이 문서는 2026-11-18 작업의 기록이다. 지금의 답 결정 흐름·스위치·고정 문구·측정 방법은 [플레이북 05](./playbook/05-chatbot.md)가 정본이다. 바로 앞 작업은 [첫 방문자 질문 점검(2026-11-13)](./chatbot-first-contact-audit-2026-11-13.md)에 있다.

모든 측정은 실제 Gemini + 정적 문서 경로(`scripts/chatbot-live-eval.ts`)다. 운영 벡터 검색 경로는 재지 않았다(운영 DB 접근 없음). 채점은 모델 심사(1차 심사 → 실패 건 독립 재확인)이고 사람 검수는 아니다.

## 요약

- 정규식과 정해 둔 답을 질문마다 더하는 방식은 처음 보는 질문에 통하지 않았다(좋은 답 29% → 30%). 그래서 구조를 바꿨다: 정해 둔 답을 내기 전에 모델이 맞는 답인지 판정하는 **관문**, 못 찾았을 때 문서 목차에서 다시 고르는 **두 번째 검색**.
- 측정 도중 Gemini 선결제 크레딧이 떨어져 모든 호출이 HTTP 402를 돌려줬다. 그 뒤의 측정은 무효다. **"구조 변경 뒤 처음 보는 질문에서 좋은 답 비율이 올랐는가"는 아직 재지 못했다.**
- 모델이 죽은 상태에서 확인되지 않은 검색 조각이 답으로 나가는 결함이 드러나 4차에서 고쳤다(고정 문구 + 상담 버튼, 결제·인증 실패 차단기, 무효 측정 감지).

## 모델이 죽은 상태에서 드러난 결함과 4차 수정

모든 모델 호출이 실패한 상태의 90문항에서 46건이 검색 조각 초안을 그대로 답으로 냈고, 그중 38건이 엉뚱한 답으로 심사됐다(좋은 답 1). 전체로는 엉뚱한 답 45/90. 원인은 근거 선별 호출이 실패하면 확인되지 않은 검색 조각을 그대로 내보내는 기존 동작이었다(낱말 목록 밖 질문만 보류하고 있었다).

4차에서 고친 것:

- **선별 실패 시 고정 문구.** 모델이 켜져 있는데(키 있음, 모드 `select`·`generate`) 선별 호출이 실패하면(HTTP 오류·시간 초과·해석 실패) 조각 대신 `MODEL_UNAVAILABLE_ANSWER`를 낸다. 상담 버튼이 뜨고(`handoff`, `needsHandoff`), 답 캐시에 넣지 않고, 두 번째 검색을 돌리지 않는다. 관문 뒤 문서 경로의 선별 실패도 같다.
- **차단기.** 401·402·403을 받으면 60초 동안 챗봇 Gemini 호출을 보내지 않는다. 관문은 `skipped`·`model_unavailable`로 기존 답을 유지하고 캐시하지 않는다. 임베딩이 막히면 키워드 검색만 한다.
- **관문이 버린 뒤의 고정 문구.** 문장을 못 고르면 분류별 틀·되묻기 문구로 돌아가지 않고 사실 질문 → `NO_SOURCE_FACT_ANSWER`, 증상 → `SYMPTOM_AFTER_GATE_ANSWER`, 그 밖 → 분류와 무관한 일반 되묻기를 낸다.
- **잡담 공감 답.** `small_talk`만 관문에서 뺐다. `emotional_concern`은 제품 주장(API 연동·중복 입력 감소·파일럿)을 담고 정규식이 넓어 관문에 남겼다.
- **무효 측정 감지.** 측정 스크립트의 `modelError`, 5% 기준 종료 코드 2, 앞 20줄 조기 중단.

4차 검토에서 확인된 지적 4건(반박 1건)과 처리:

| 지적 | 처리 |
|---|---|
| 측정 스크립트가 차단기 때문에 관문이 판정 없이 넘긴 줄을 모델 오류로 세지 않는다(`skipReason`도 결과 줄에 없음) | 고침(64d5fe89). 관문이 차단기를 보고 넘길 때도 `notifyModelCircuitBlocked()`로 알리고, 스크립트는 `gateSkipReason`·`secondChanceReason`이 `model_unavailable`이면 `modelError`로 센다. 모의 402 재현에서 `모델 호출 실패 줄`이 10/23 → 23/25 |
| 위와 같은 결함(확인 안 된 정해 둔 답이 정상 줄로 채점됨) | 위와 같이 고침 |
| 모델 장애로 두 번째 검색을 못 돌렸는데도 '공개 안내에서 찾지 못했어요'라고 단정하고 상담 버튼도 없다 | 차단기가 열린 경우(`model_unavailable`)만 고침: `MODEL_UNAVAILABLE_ANSWER`로 바꾼다. 차단기가 닫힌 상태의 일시 실패(오류·시간 초과)는 그대로 둠(아래 사람이 정할 일) |
| `small_talk`를 관문에서 빼면서 '~하기 싫은데 …할 수 있나요?' 꼴의 기능 질문에도 확인 없이 공감 한마디가 나간다 | 일부 고침: 묻는 말 표시(`hasQuestionSignal`)가 있으면 관문에 넘긴다. 정규식 자체는 모델 없는 답을 바꾸므로 그대로 둠. 관문이 건너뛰어질 때(모델 꺼짐·장애)는 여전히 공감 답이 나간다 |

## 아직 재지 못한 것

- **구조 변경(관문·두 번째 검색·4차 수정) 뒤 처음 보는 질문에서 좋은 답 비율이 올랐는가.** holdout2는 402 상태에서만 돌아 채점하지 못했다. 크레딧을 충전한 뒤 아래 방법으로 잰다.
- 4차 수정 뒤 모델이 살아 있을 때의 동작(관문·선별·두 번째 검색의 정상 경로). 4차 측정은 모두 모델이 죽은 상태였다.
- 운영 벡터 검색(Supabase) 경로. 모든 측정이 정적 문서 경로다.
- 챗봇 밖 Gemini 9곳 수정은 404 폴백을 단위 테스트(모의 응답)로만 확인했다. 해당 라우트를 실제로 구동해 보지는 않았다.

## 다시 재는 방법

크레딧을 충전한 뒤 저장소 루트에서 차례로 실행한다. `GEMINI_API_KEY`는 환경 또는 `.env.local`에서 읽는다(스크립트는 `SUPABASE`가 든 값을 읽지 않고 정적 문서로만 잰다). 결과는 저장소 밖 작업 폴더에 둔다.

```bash
WORK=$(mktemp -d)
```

1) 모델이 살아 있는지 한 문항으로 확인한다. 종료 코드 0, `모델 호출 실패 줄: 0 / 1`이어야 한다. 2가 나오면 아직 결제·키 문제다.

```bash
echo '[{"id":"probe","question":"수업 녹화는 어디서 봐요"}]' > "$WORK/probe.json"
npx tsx scripts/chatbot-live-eval.ts --in "$WORK/probe.json" --out "$WORK/probe.jsonl"; echo "exit $?"
```

2) 시험 질문 묶음을 측정 스크립트 입력으로 꺼낸다(묶음 이름은 `holdout1`·`holdout2`). 질문 내용을 화면에 찍지 않는다.

```bash
node -e 'const [k,o]=process.argv.slice(1);const s=require("./data/chatbot-holdout-sets.json").sets.find(x=>x.key===k);if(!s)throw new Error("묶음 없음: "+k);require("fs").writeFileSync(o,JSON.stringify(s.cases,null,2));console.error(k,s.status,s.cases.length+"문항 →",o)' holdout2 "$WORK/holdout2-input.json"
```

3) 기본 설정(모드 `select`, 관문·두 번째 검색 켬)과 모델 없는 답을 함께 돌린다.

```bash
npx tsx scripts/chatbot-live-eval.ts --in "$WORK/holdout2-input.json" --out "$WORK/holdout2.jsonl" --concurrency 4; echo "exit $?"
npx tsx scripts/chatbot-live-eval.ts --in "$WORK/holdout2-input.json" --out "$WORK/holdout2-off.jsonl" --mode off
```

4) 종료 코드가 2면 무효 측정이다. 채점하지 않는다. 0이면 결과 줄을 1차 심사 → 실패 건 독립 재확인으로 채점하고, 위 2차 holdout1 표와 같은 분류(좋은 답·일부만 답함·엉뚱한 답·문서에 있는데 못 찾음·문서에 없어 못 찾음·불필요한 되묻기)로 센다.

5) 회귀로 평가셋도 돌린다(`{cases:[...]}`를 그대로 받는다).

```bash
npx tsx scripts/chatbot-live-eval.ts --in data/chatbot-first-contact-set.json --out "$WORK/first-contact.jsonl"
npx tsx scripts/chatbot-live-eval.ts --in data/chatbot-fresh-open-set.json --out "$WORK/fresh-open.jsonl"
```

6) holdout2를 채점한 결과를 수정 근거로 쓰면 그 묶음의 `status`를 `dev`로 내리고, 다음 측정에는 새 묶음을 만든다(규칙은 `scripts/chatbot-persona-loop/README.md`).

1~3차의 371문항 측정 입력 파일은 저장소에 커밋하지 않았다. 같은 질문이 위 두 평가셋으로 그대로 재구성되는지는 확인하지 못했다.

## 사람이 정할 일

### 운영·정책

- **Gemini 선결제 크레딧 충전.** 운영이 같은 결제 계정을 쓰면 운영 챗봇·블로그 AI·마케팅 인사이트도 지금 모델 호출이 실패한다.
- **관문 기본 모델.** lite(가로채기 71% 잡음, 0.96초) vs `gemini-3.5-flash`(83%, 약 0.35초 더 느리고 단가 높음). `CHATBOT_ANSWER_GATE_MODEL`.
- **운영 Supabase 읽기 접근 허용 여부.** 실제 미해결 질문 수집, 벡터 검색 경로 측정에 필요하다.
- **공개 범위 정책.** 금액 숫자 비공개, 특정 학원 확인 안 함, 회사 국적, 내부 원가, 무료 체험 문구('2주' 표기 불일치), 요금제 이름 불일치(Pro·비즈니스 / Standard·Plus / Learning Space·Business), 최대 인원·무대 인원 숫자 불일치, 대형 전자칠판 크기 공개 범위.
- **first-contact 세트 기대값 6개 변경**(compare-03, compare-12, compare-14, customers-05, customers-07, customers-08)과 세트 확대(192 → 247)의 타당성.
- **DPA 답 충돌.** DPA 답은 '수탁사 현황이 공개 문서에 없다'고 하는데 개인정보처리방침 8절에 수탁사 표가 있다(손대지 않음).
- **쇼룸 주소 표기 두 가지.** '806호' / '8층 806호(드림타워)'.
- **잡담 정규식(`small_talk`) 좁히기.** 관문이 건너뛰어질 때(모델 꺼짐·장애) '~하기 싫은데 …할 수 있나요?' 꼴 질문에 공감 답이 나간다. 좁히면 모델 없는 답이 바뀐다.
- **두 번째 검색의 일시 실패에 상담 버튼을 띄울지.** 차단기가 닫힌 상태의 오류·시간 초과는 지금 '못 찾음'(버튼 없음)으로 나간다. 바꾸면 상담 연결 정책이 바뀐다.

## 운영 영향(배포하면 바뀌는 것)

- **추가 호출.** 정해 둔 답이 나가는 요청마다 작은 모델 호출 1회(관문, 약 1초). 같은 (질문, 답) 판정은 10분 캐시. 못 찾음으로 끝나는 사실 질문은 최대 3회 추가 호출(목차 고르기 약 13,000 토큰 입력 → 근거 선별 → 관문), 약 2초.
- **검색 증가.** 낱말 목록 밖 질문도 검색하므로 운영의 임베딩·벡터 검색 호출이 늘어난다.
- **선별 시간 초과의 답이 바뀐다.** 정상 운영에서도 선별이 시간 초과(`select` 3.5초, `generate` 2초)하면 예전에는 검색 조각이 나갔고, 이제는 `MODEL_UNAVAILABLE_ANSWER`와 상담 버튼이 나간다. 약한 근거 초안(`WEAK_SOURCE_DRAFT_ANSWER`)과 낱말 목록 밖 보류(`NO_SOURCE_FACT_ANSWER`)도 이 경우 같은 문구로 바뀐다.
- **결제·인증 실패 때.** 차단기가 열린 60초 동안 챗봇 Gemini 호출이 나가지 않는다(관문은 기존 답 유지, 선별은 고정 문구, 임베딩은 키워드 검색만). 실측(402 상태)에서 질문당 호출 중앙값이 4 → 0(holdout1), 3 → 0(371문항). 열릴 때마다 `[chatbot] Gemini HTTP …` 오류 로그 한 줄. 차단기는 끄는 스위치가 없다(60초 상수).
- **끄는 방법.** `CHATBOT_ANSWER_GATE=off`(관문), `CHATBOT_SECOND_CHANCE=off`(두 번째 검색), 전체 모델 사용은 `CHATBOT_FINAL_ANSWER_LLM=off`. 각 스위치를 끄면 어떻게 되는지는 [플레이북 05 §5](./playbook/05-chatbot.md).
- 챗봇 밖 Gemini 9곳 수정은 404 폴백을 단위 테스트(모의 응답)로만 확인했다.
