# KR Team과 Compass 월별 과정지표 연동

KR Team(`/admin/branch`)의 개요·파이프라인에서 Compass의 현재 팀 명부와 월별 과정지표를 읽는다.
시트 영업 KPI(LD·ACC·OPP·SOL·VST), 매출 장부, 월별 가중 평가표는 서로 다른 정본이다. 서로 합산하거나 이름만 바꿔 대체하지 않는다.

## 정본과 계약

- Compass의 버전 1 읽기 응답을 서버에서 검증한다. 월·버전·필수 필드·유한 숫자가 다르면 조회 실패로 처리한다.
- 지표·목표·가중치·실적·수동값·자동값·조정 사유·정성 평가·종합 점수·월말 전망은 Compass가 계산한다. 관리자가 다시 계산하지 않는다. 평가자·일자·메모·참고 수치도 원본에서 표시한다.
- 확정 월은 Compass의 확정 스냅샷을 표시한다. 스냅샷이 없으면 실패이며 라이브 값으로 대체하지 않는다.
- 명부는 Compass의 현재 KPI 설정과 BD 명단에서 읽는다. 현재 조직은 BD·MKT이며 CSM은 이전 조직 이력이다. CS·CSM 원본 역할의 새 부서를 추측하지 않고 팀 미분류로 표시한다. KPI 전용 대상은 로그인 계정을 만들지 않는다.
- 현재 팀 변경으로 과거 매출 귀속을 바꾸지 않는다. 한글 명부와 영문 장부 이름은 `lib/branch/member-names.ts`로 정규화한다.
- 문준혁·진소망의 MKT 편입, NEO·REV·Compass의 정본 경계와 노션 개정 목표 대조는 [KR 데이터 연결 기준](kr-data-source-contract.md)을 따른다. 현재 명부 밖 원본 평가표는 별도 보존하고 현재 인원·수동 조정 요약에서는 제외한다. 원본 평가표의 역할이 평가 당시 부서라는 보장은 없다.
- Compass 전체 팀 월매출은 CNY·동기화 시각·미수집을 함께 표시한다. KR 장부 금액에 더하지 않는다. 기존 매출 장부의 액티브 임포트 → DB 미러 → 라이브 폴백 순서는 유지한다.

## 설정과 갱신

관리자 서버의 `COMPASS_BRIDGE_URL`은 Compass의 HTTPS 오리진, `COMPASS_BRIDGE_TOKEN`은 Compass 서버의 전용 토큰과 같은 값이다. 토큰은 브라우저 응답·로그에 넣지 않는다.
로컬 개발에서만 loopback HTTP를 허용한다. 크론 토큰으로 브리지를 열거나 인증 우회를 켜지 않는다.

`GET /api/admin/branch/compass?month=YYYY-MM`은 Compass 요약과 같은 CRM 직원 읽기 권한을 확인한 뒤 원천을 조회한다. 평가표를 일반 VIEWER에게 새로 공개하지 않는다. 응답은 no-store이며 원천 요청에 시간 상한을 둔다.
개요·파이프라인이 활성화된 동안에만 조회하고, 보이는 화면에서 60초마다 갱신한다. 히트맵·AI 탭은 요청하지 않는다.
로딩·미설정·장애·이전 조회·목표 없음·평가 전·매출 미수집을 구분한다. 잘못된 응답을 정상 0으로 바꾸지 않는다.

## 리드·콜·데모 데이터 연결

리드·활동·데모는 같은 DB의 `compass_leads_v`·`compass_activities_v`·`compass_demos_v`를 직접 읽는다. 이 경로는 월별 KPI 평가 HTTP 브리지와 별개이며, 평가 브리지 장애를 활동 데이터의 단절로 해석하지 않는다. 원본 기록을 Admin에 복제하거나 콜·데모를 중복 생성하지 않는다.

홈페이지 리드의 처리 상태는 기존 `lead-contact-sync` 크론으로 조건부 반영한다. 전화 키 매칭·사람 활동 판정을 유지하고, 이미 바뀐 상태·담당자·이력을 보존한다. 실행 전 dry-run과 변경 전 사본, 실행 후 남은 반영 대상 및 감사 기록을 확인한다. 이 크론은 외부 메시지를 발송하지 않는다.

Compass DB 조회는 같은 담당자·기간의 동시 요청을 공유하며, 10초 무응답이면 실패를 반환하고 해당 진행 중 캐시를 폐기한다. 늦게 끝난 이전 요청이 재시도 결과를 덮지 않는다. 정상 결과는 60초, 명시적인 연결 실패 결과는 10초만 재사용한다. 200개 캐시 상한에서는 가장 오래된 항목 하나만 제거한다.
다음 액션 목록은 최대 500행이지만 전체 건수는 동일한 담당자·시간 조건의 DB exact count로 표시한다. 목록은 액션 시각·리드 ID로 정렬한다.

시트 동기화의 수동·Cron 후처리는 `lib/branch/sync/complete.ts`로 통일한다. REV 성공·하드웨어 실패에서도 매출 요약·매출 시트 캐시와 CRM 연결을 갱신한다. 링크 유지보수의 예외는 원본 반영 성공과 분리한 경고로 반환하며, 동기화가 건너뛰어진 경우 후처리를 실행하지 않는다.

로컬 Compass가 별도 테스트 DB를 사용한다면 월별 평가 응답은 개발 연결 검증용이다. 운영 공유 DB의 리드·활동 수치나 운영 KPI의 갱신 증거로 사용하지 않는다. 운영 월별 KPI는 배포된 전용 조회 라우트와 전용 토큰으로 따로 확인한다.

CRM 홈·인사이트의 오늘 데모와 CRM 업무 신호는 `lib/compass/demo.ts`의 판정으로 실제 `kind=demo` 중 `booked`·`done`만 사용한다. 미팅·취소·노쇼·미지정 상태는 제외하며, 원본 회차는 삭제하지 않는다. Overview의 예정(`booked`)·완료(`done`)·취소·노쇼 분리 집계는 유지한다.

## 요약과 시각화

개요는 매출 현황 → Compass 평가 요약 → 보조 운영 지표 → 추세·구성 차트 순서다. 매출 확정액을 중복 카드로 표시하지 않는다. 팀별 DSH 실적과 REV 확정액은 각각의 출처를 표시한다.
Compass 첫 화면은 평가 완료·대기·미배정·사유가 있는 조정 건수와 개인별 원본 달성률이다. 직무가 다른 개인 점수를 합쳐 새 팀 점수를 만들지 않는다. 평가 항목과 양의 가중치가 배정된 인원만 완료·대기의 분모에 포함하고 명부의 미배정 인원은 별도로 표시한다. 가중치가 0인 평가표도 상세에서 보존하고 가중치 확인 대상으로 표시한다.
막대는 공통 축과 100% 목표선을 사용하며 음수·초과 달성을 보존한다. 수치·등급·평가 반영 비중은 hover 없이 읽을 수 있다. 개인별 목표·가중치·조정 내역과 명부·원본 자료는 기본적으로 접혀 있다.
기존 팀별 원형 게이지·매출 로드맵·누적 추이·주차별 확도·매출 분해·하드웨어 차트를 보존하고 요약을 보강한다. 원형 게이지와 로드맵은 그릴 범위만 제한하며 음수·120% 초과 달성률의 실제 숫자는 유지한다. 목표가 없으면 게이지를 0%로 표시하지 않고 미설정으로 구분한다.
모바일에서도 차트를 유지한다. 캠페인·하드웨어 영역은 기본으로 펼쳐 보이고 사용자가 접을 수 있다. 접힌 영역과 비활성 탭은 해당 위젯을 마운트하지 않는다. 개요 매출 조회가 실패하더라도 Compass 평가와 그 실패 상태는 독립적으로 표시한다.
파이프라인 기본 보기는 확도 칸반이며 표로 전환할 수 있다. 하드웨어 상세는 비교 게이지로 시작한다. 동기화 실패는 상단 경고·원천 시각을 유지하고 긴 실패 원문은 펼쳐서 확인한다.
개요 위젯은 클라이언트의 API 상태로 렌더하는 하나의 지연 모듈이며 로딩·지연·실패 경계를 유지한다. 공유 차트 모듈의 잘못된 서버 preload를 피하도록 클라이언트에서 마운트한다.

## 검증과 배포

Compass의 전용 읽기 라우트를 먼저 배포하고 두 서버의 토큰을 연결한 뒤 관리자 소비 코드를 배포한다. 이 연결 자체에는 DB 마이그레이션이 없다.
운영 동기화·마감·임포트는 조회 검증에 필요하지 않다. 설정 값은 채팅·코드·문서에 남기지 않는다.

- `tests/compass/kr-team.test.ts`: 계약·버전·월·음수·실패 상태·토큰 비노출.
- `tests/api/admin-branch-compass.test.ts`: 인증·월 경계·no-store.
- `tests/branch/compass-team-section.test.tsx`: 명부·평가·조정·빈 상태·확정 상태.
- `tests/api/admin-branch-summary-breakdown.test.ts`: 기존 시트 KPI의 월·분기 집계 일치.
