# 고객 견적 작성 시 총판(파트너) 견적서 같이 만들기 — 기획(결정 대기)

기준 시점: 2026-11-20
상태: P0·P1 구현(2026-11-20). 결정 D1~D8 확정(§8), 데이터 질문 답변 반영(§4).
범위: `/admin/quotes` 하드웨어 견적 작성기(`QuickQuoteComposer`), 총판 정산(C방식) 초안, 총판 원가 템플릿.
선행 정본: [하드웨어 C방식/H방식 총판 정산](../hardware-ops/distributor-settlement.md) — 이 문서는 그 §3 순서의
**2단계(총판 정산 초안 만들기)를 1단계(고객 견적 작성)와 같은 순간으로 당기는 것**만 다룬다. 발행·입금·매출 규칙은 바꾸지 않는다.

## 1. 왜

- 지금은 고객 견적을 저장한 뒤 **견적 상세 › 총판 정산**을 따로 열어 원가를 넣어야 총판(퀴드러닝 · "배 대표님")용
  견적서가 생긴다. 안 해 두면 설치 완료(출고 확정) 때에야 초안이 자동으로 만들어지고, 원가 템플릿이 여러 개면 원가가 비어
  검토 요청으로 멈춘다(정본 §3-1).
- 영업은 고객 견적을 쓰는 순간 이미 수량을 안다. FY2026 채널 유통 가격 정책표(아래 §3)가 수량 구간별 공급가를 정해 두었으니
  **고객 견적을 쓰는 화면에서 총판 견적서까지 한 번에** 만들 수 있다.

## 2. 목표 동작(제안)

1. 작성기에서 HW 장(공급자 = 퀴드러닝)이 있으면, 장 아래에 **"총판 견적서 같이 만들기"** 토글이 보인다(기본 켬, D1).
2. 켜져 있으면 장 옆(또는 아래)에 **총판 견적서 미리보기**가 붙는다 — 같은 승인 양식(`QuoteDocumentPreview`),
   공급자 = 이이오클래스인코리아, 수신 = 퀴드러닝(배철웅), 참조 = 고객사, 금액 = §3 공급가. 고객 단가·합계는 싣지 않는다(정본 §4).
   - 작성자에게만 줄마다 **고객가 / 공급가 / 차액(총판 마진)** 을 작게 보여 준다(종이에는 안 찍힘, D6).
3. 고객 견적을 **저장/보내기** 하면, 고객 견적 저장이 끝난 뒤 같은 흐름에서 총판 정산 초안을 만든다
   (`PUT /api/admin/quotes/[id]/distributor-settlement`, 방식 C, 발행 시점 = 고객 동의 시 자동 `on_accept`).
   - **발행(배 대표님 이메일)은 하지 않는다.** 초안만 만든다. 발행은 기존대로 고객 동의 시 자동 / 설치 완료 검토 / 직접 발행(D2).
4. 원가가 다 채워지지 않은 줄이 있으면(벽걸이·설치 등 §3에 없는 품목) 초안은 만들되 저장 토스트에
   "총판 원가 N줄 비어 있음 — 견적 상세에서 채워야 발행됩니다"를 띄운다(기존 발행 차단 규칙 `getDistributorIssueBlocker` 그대로).
5. 고객 견적 저장은 성공했는데 총판 초안 저장이 실패하면 **고객 견적은 되돌리지 않는다**. 토스트로 알리고 견적 상세 › 총판 정산에서
   다시 저장하게 한다(정본 §3 "각자 실패를 삼킨다"와 같은 원칙).
6. 같은 견적을 작성기에서 다시 저장(v2, v3…)하면 발행 전 초안을 새 품목으로 갱신한다. 사람이 고친 원가·포함 여부는
   `buildDistributorLinesFromQuote`의 `previous` 규칙대로 이어받는다. 발행된 뒤라면 409 → 갱신하지 않고 "버전 바뀜" 경고만(기존 `versionChanged`).

SW 단독 장(공급자 = 클래스인 직접)에는 토글을 보이지 않는다. HW+SW 믹스면 HW 장에만 붙는다.

## 3. 가격 원천 — FY2026 채널 유통 가격 정책표

"채널공급가 = 수입원가 + 물류 + 통관 + 창고", 모두 **VAT 포함**. 기존 원가 템플릿 구조(품목 코드 × 최소 구매 대수 → 원가,
`distributor_price_templates`)에 그대로 들어가므로 **마이그레이션 없이** 템플릿 1개("FY2026 채널 공급가")로 넣는다.

| 정책표 | 품목 코드 | 1대 | 2~10 | 11~20 | 21~50 | 시장판매가(1 / 2~10 / 11~20 / 21~50) |
| --- | --- | --- | --- | --- | --- | --- |
| 86" | `board-86` | 4,870,000 | 4,870,000 | 4,670,000 | 4,500,000 | 6,300,000 / 5,800,000 / 5,500,000 / 5,300,000 |
| 75" | `board-75` | 4,200,000 | 4,200,000 | 4,000,000 | 3,850,000 | 5,400,000 / 4,900,000 / 4,600,000 / 4,400,000 |
| T1 | `camera-t1` | 840,000 | 840,000 | 800,000 | 800,000 | 1,200,000 / 1,200,000 / 1,000,000 / 1,000,000 |
| STD1 | `stand` | 270,000 | 270,000 | 250,000 | 250,000 | 500,000 (전 구간) |
| 86" OMO | `ai-studio-recording-set` | 6,210,000 | 6,210,000 | 5,970,000 | 5,800,000 | 8,300,000 / 7,800,000 / 7,500,000 / 7,300,000 |
| 75" OMO | `ai-studio-recording-set-75` | 5,540,000 | 5,540,000 | 5,300,000 | 5,150,000 | 7,400,000 / 6,900,000 / 6,600,000 / 6,400,000 |

템플릿 규칙(minQuantity): 각 품목에 `1`, `11`, `21` 세 구간이면 충분하다(2~10은 1대와 같은 값). 50대 초과 구간은 표에 없다 → D5.

- OMO(녹화 세트)는 "세트 판매 시 스탠드 가격 더하세요" — 세트 가격에 스탠드가 없으므로, 스탠드 줄이 있으면 STD1 공급가를 따로 더한다.
  지금 녹화 세트 장에 스탠드 행이 자동으로 생기는지는 구현 때 확인(없으면 작성자가 품목 "스탠드"를 눌러 추가).
- 구간 판정은 **줄 수량** 기준이다(기존 `pickTemplateUnitPrice`). 작성기는 같은 품목을 한 줄로 합치므로(누르면 수량 +1) 보통은 충분하다.
  86" 단품 줄과 번들의 86"을 합산할지는 D4.
- 표에 없는 품목: `wall-mount`(벽걸이), `install-training`(설치·교육), `camera-install`, AI Suite(판매 중단). 설치·교육은 정본대로
  기본 제외. 벽걸이 원가는 D3.

## 4. 표에서 확인이 필요한 값(데이터 질문)

1. **STD1 할인 폭 0원인데 할인 비율 −16.70%** — 비율 칸이 T1 행에서 복사된 것으로 보인다. 시장가 500,000 고정이 맞는지.
2. **86"·75"·T1·STD1 의 2~10대 공급가 = 1대 공급가** — 의도된 값인지(시장가만 내려가고 총판 공급가는 그대로면, 2~10대 구간에서
   퀴드러닝 마진이 줄어든다: 86" 1대 마진 1,430,000 → 2~10대 930,000).
3. 표 오른쪽의 **416,500 / 145,864** 메모 숫자의 의미(템플릿에 넣지 않는다).
4. **프로모션**: "단품 프로모션 2구매 T1 증정 / 1대 구매 스탠드 증정"(86"·75" 2~10 행 옆), "OMO 21~50 프로모션 추가 50만원 할인" —
   증정품·추가 할인이 고객 견적에 어떻게 찍히고(0원 증정 행? 견적 할인?), **총판 공급가에도 반영되는지**(증정 T1 원가를 누가 부담하는지) → D7.

## 5. 고객 견적 쪽 연동(같이 결정할 것)

정책표의 **시장판매가도 수량 구간별**이다(86" 2~10대 5,800,000). 지금 작성기는 수량과 상관없이 카탈로그 정가(6,300,000)를 쓰고,
작성자가 단가를 직접 고치면 "% 할인"으로 표시한다. 고객가도 구간에 맞춰 자동으로 바꿀지 D8. 바꾸면 할인 표시 기준(정가)도
구간가로 바뀌어야 한다 — 이 기획의 P1로 분리한다.

## 6. 구현 설계(P0)

**경계 원칙.** `QuickQuoteComposer`는 포털 경로(`components/portal/quotes`)에 있고, 어드민 클라이언트를 import 하지 않는다는
테스트가 있다(`tests/admin/quick-quote-composer.test.ts`). 원가는 파트너 포털에 새면 안 되는 값이므로 **원가 데이터와 저장 호출은
모두 주입한다**(템플릿 저장 `onSaveTemplate`과 같은 방식).

1. 작성기 props 추가(선택형, 안 주면 기능 숨김 — 포털은 그대로):
   - `distributorQuote?: { priceRules: DistributorPriceRule[]; defaults: {...배철웅 연락처}; onSave(quoteDocumentId, lines) }`
2. 작성기 안:
   - HW 장의 `composeSheetQuote` 결과 → `buildDistributorLinesFromQuote(lineItems, { rules })` → `buildDistributorQuoteDetails`로
     미리보기 본문을 만든다(순수 함수, `lib/distributor-settlements.ts` — 서버 전용 아님).
   - `executeSubmit`에서 HW 장 저장 성공 직후 `onSave` 호출. 실패는 `saveToast`/`errorToast`에 덧붙이고 흐름을 막지 않는다.
3. `HardwareQuotesPanel`:
   - 열 때 `GET /api/admin/distributor-price-templates`로 활성 템플릿(D4로 고른 기본 1개)을 받아 주입.
   - `onSave` = 기존 `PUT /api/admin/quotes/[id]/distributor-settlement` 호출(방식 C, `issueTrigger: "on_accept"`, `autoEmail: true`,
     `priceTemplateId`, 총판 기본값 = 최근 저장 총판 or `DEFAULT_HARDWARE_DISTRIBUTOR`). **새 API·마이그레이션 없음.**
4. 설치 완료 자동 준비(정본 §3-1)와의 관계: 발행 전 초안이 이미 있으면 사람이 정한 원가·포함 여부를 건드리지 않는다는 규칙이
   이미 있으므로 충돌하지 않는다. 출고 로트가 H면 기존 "방식 차이" 검토 사유가 남는다.
5. 권한: PUT 은 `CRM_STAFF_ADMIN_API_ROLES`. 작성기를 쓰는 역할이 이 권한이 없으면 토글을 숨긴다(D2와 같이 확인).

**테스트(추가)**
- `tests/lib/distributor-settlements.test.ts`: FY2026 규칙으로 86" 1/10/11/21대 → 4,870,000 / 4,870,000 / 4,670,000 / 4,500,000.
- `tests/lib/hardware-quote-flow.test.tsx`: 작성기 HW 장 → 총판 견적서 본문(공급자 = 회사, 수신 = 퀴드러닝 배철웅, 고객 단가 없음).
- `tests/admin/quick-quote-composer.test.ts`: 주입 없으면 토글·원가 없음(포털), 어드민 import 없음 유지.
- 저장 실패 시 고객 견적은 남고 토스트만 뜨는지.

### 7-1. P0 구현 메모(2026-11-20)

- 작성기 HW 장 아래 "총판 견적서" 영역: 같이 만들기 체크(기본 켬), 줄별 고객 단가·공급 단가·차액/대, 합계, 원가 빈 품목 경고.
  미리보기는 승인 양식 전체 대신 공급가 표로 둔다(총판 견적서 양식 미리보기는 견적 상세 › 총판 정산에 이미 있음).
- 저장 흐름: HW 견적 저장(또는 다음 버전 저장) 직후 `PUT /api/admin/quotes/[id]/distributor-settlement` — C방식, `on_accept`,
  총판 = `DEFAULT_HARDWARE_DISTRIBUTOR`, `priceTemplateId: null`, 메모 "고객 견적 작성 시 FY2026 채널공급가로 자동 생성".
  포함 품목이 없으면 호출하지 않는다. 실패(503·409 포함)는 오류 토스트만, 고객 견적은 그대로.
- 벽걸이 설치(`wall-mount`)는 `itemType: installation` 이라 기존 규칙대로 **기본 제외**된다(설치·교육과 같음) → D3 는 "제외가 맞는지" 확인으로 바뀜.
- 테스트: `tests/lib/distributor-fy2026-price-rules.test.ts`, `tests/admin/quick-quote-composer.test.ts`.

### 7-2. 2차 구현(2026-11-20, 결정 반영)

- **수신·참조**: 총판 견적서 수신 담당 칸 = 대표 조혜리, 참조 = 배철웅. 고객사는 본문 첫 문장
  ("고객사 ○○ 건으로 아래와 같이 견적서를 제출합니다.")으로 옮겼다(`buildDistributorQuoteDetails`). 등록 총판(퀴드러닝)이 아니면
  대표 이름을 모르므로 담당자가 수신 담당 칸에 들어가고 참조는 비운다. 자동 생성 시 `notes` 는 비운다(특약사항으로 찍히므로).
- **공급가 원천 = 어드민 원가 템플릿**: 작성기가 열릴 때 원가 템플릿을 읽어 최근 수정한 것을 기본으로 쓰고, 여러 개면 고를 수 있다.
  템플릿이 하나도 없을 때만 코드의 FY2026 값을 쓰며 "정책표를 원가 템플릿으로 저장" 버튼으로 템플릿을 만든다 — 그 뒤로는 화면에서 고친다
  (STD1 가격이 바뀌어도 코드 수정 없음). 저장할 때 고른 템플릿 id 를 정산 `priceTemplateId` 로 남긴다.
- **프로모션 증정 토글**(전자칠판 86"/75" 옵션, 기본 꺼짐): "T1 증정"(2대당 1대) · "스탠드 증정"(1대당 1대) — 0원 하드웨어 행,
  품목 코드 `camera-t1-gift` · `stand-gift`. 출고(오더 줄)는 T1 · STD1 재고로 센다. 총판 견적서에는 포함되지만 원가는 비어 있어
  사람이 넣는다(수동). 증정 원가를 템플릿에 넣고 싶으면 그 코드로 규칙을 추가하면 된다.
- **누적 대수 구간가 추천**: 수신 칸이 등록 고객과 정확히 매칭됐을 때만 그 고객의 **승인된 오더** 품목별 누적 수량을 읽고
  (`GET /api/admin/hardware/customer-units`), 이전 + 이번 수량의 시장 구간가가 지금 단가보다 낮으면 HW 장 위에 추천을 띄운다.
  단가는 작성자가 "추천가 적용"을 눌러야 바뀐다. 이전 구매가 없으면 추천하지 않는다(단일 견적 구간은 매니저 몫). 시장가 표는
  `lib/hardware-market-price-tiers.ts`(코드 상수).
- 테스트: `tests/lib/hardware-promo-and-tier-nudge.test.ts`, 수신·참조 변경은 `tests/lib/hardware-quote-flow.test.tsx`·`tests/lib/distributor-settlements.test.ts`.
