# Partner Portal Product Plan

기준 시점: 2026-04-04

이 문서는 파트너 포털의 실제 화면 설계, UI/UX 원칙, 기능 구조, 구현 순서를 정의한다.
운영 규칙 자체는 `partner-portal-guidelines.md`를 우선하고, 이 문서는 그 규칙을 제품 화면으로 풀어낸다.

문서 허브 재설계 세부 기준은 아래 문서를 함께 본다.

- `partner-portal-document-hub-guidelines.md`
- `partner-portal-document-hub-wireframes.md`

## 1. 제품 한 줄 정의

파트너 포털은 `기관별 거래 운영 보드 + 문서 허브 + 설치/수납 관제판`이다.

중요한 건 단순한 CRM 테이블이 아니라:

- 어떤 기관이 지금 어디 단계에 있는지
- 문서가 몇 번 수정됐고 무엇이 고객에게 나갔는지
- 설치가 언제 잡혔고 누가 움직여야 하는지
- 돈이 실제로 들어왔는지, 미수금이 남았는지

를 한눈에 보고, 한 번의 확인으로 다음 단계로 넘길 수 있어야 한다.

## 2. 제품 구조 핵심

### A. 고객 중심이 아니라 거래건 중심

기관은 여러 거래를 가질 수 있다.

따라서 상위 구조는:

- 기관 목록
- 기관 아래 거래건 목록
- 거래건 상세 운영

형태가 맞다.

### B. 화면 안에서 흐름이 이어져야 한다

탭마다 따로 들어가서 다시 입력하는 구조는 피한다.

좋은 구조:

- 견적서 발송 후 `다음 단계 진행`
- 계약서 서명 완료 후 `확정으로 이동`
- 설치 일정 생성 후 `캘린더 반영`
- 수납 등록 후 `미수금 자동 갱신`

즉, 탭은 보기용 분리일 뿐, 상태 전환은 전체 흐름에서 연결돼야 한다.

### C. 로드맵 + 칸반 + 타임라인을 섞는다

사용자가 원한 느낌은 전형적인 회계 ERP보다
`CRM 파이프라인`과 `로드맵 UI`에 가깝다.

권장 조합:

- 상단: 거래 단계 로드맵
- 중단: 거래건 카드/칸반 또는 기관별 스택
- 우측 또는 하단: 활동 타임라인

즉, 상태를 "표"가 아니라 "흐름"으로 보여준다.

## 4. 홈 화면 설계

`홈`은 요약 KPI 화면이면서, 오늘 해야 할 일을 보여주는 운영판이어야 한다.

### 추천 레이아웃

#### A. Top Summary Strip

- 진행 중 견적 수
- 진행 중 계약 수
- 설치 예정 건수
- 설치 중 건수
- 총 판매 대수
- 미수금
- 미수 기관 수

#### B. Main Board

좌측:

- `기관별 거래 스택`
- 기관 카드 안에 현재 활성 거래건 수 표시
- 가장 최근/가장 중요한 거래건이 위

중앙:

- `단계 로드맵 보드`
- 컨택 / 견적 / 계약 / 확정 / 설치 / 수납
- 각 단계에 거래건 카드가 들어감

우측:

- `오늘 일정`
- 설치/미팅/문서 후속 액션
- 서명 대기, 미수금 주의, 설치 일정 겹침 같은 alert

### 추천 시각 아이디어

미니멀하지만 게임 UI 같은 느낌을 주는 요소:

- 단계 노드와 연결선
- 거래 카드 우측 상단에 작은 상태 아이콘
- 카드 하단에 `문서 / 설치 / 수납` 미니 스탯 바
- 겹치는 추가 계약은 기관 카드 아래에 작은 서브 카드로 스택

너무 화려하게 가지 말고:

- 바탕은 화이트/웜그레이
- 상태는 블루/그린/옐로/레드 정도로만
- 카드 밀도는 높되 장난감 느낌은 피한다

## 5. 기관 화면 설계

기관은 운영의 입구다.
하지만 실제 액션은 거래건 단위에서 일어나므로, 기관 화면은 `개요 + 거래건 탐색기` 성격이 맞다.

### 기관 상세 구성

#### Header

- 기관명
- 담당자
- 연락처
- 주소
- 사업자번호
- 선택 메타: 관 / 캠퍼스 / 지역

#### Summary Row

- 진행 거래건 수
- 총 계약 금액
- 총 설치 완료 금액
- 실수납 누계
- 미수금

#### Main Panels

- `활성 거래건`
- `완료 거래건`
- `최근 문서`
- `최근 설치 일정`
- `최근 활동 로그`

### 기관에서 바로 가능한 액션

- 새 거래건 추가
- 고객 정보 수정
- CSV/Excel 고객 등록
- 미팅 로그 추가

## 6. 거래건 상세 설계

거래건은 포털의 핵심 화면이다.

### 상단 고정 영역

- 거래건 제목
- 현재 단계
- 거래 금액
- 기관명
- 최근 수정 시각
- 담당자 / 설치 담당

### 단계 로드맵

상단에 큰 로드맵 바를 둔다:

`컨택 -> 견적 -> 계약 -> 확정 -> 설치 -> 수납`

각 노드는:

- 현재 단계면 강조
- 완료 단계는 채워진 상태
- 다음 단계는 CTA 버튼 제공

예:

- 견적 발송 후: `계약으로 진행`
- 계약 서명 후: `확정 처리`
- 확정 후: `설치 일정 생성`
- 설치 완료 후: `수납 등록`

중요:

- 각 단계 전환 시 관련 탭 데이터를 다시 입력하게 하지 않는다
- 필요한 후속 객체를 자동 생성하거나 생성 모달을 바로 띄운다

### 거래건 탭 구조

권장 탭:

- `개요`
- `문서`
- `설치`
- `수납`
- `활동`

#### 1. 개요 탭

- 현재 상태 카드
- 금액 요약
- 판매 품목 요약
- 다음 액션 추천
- 최근 문서 / 최근 일정 / 최근 수납 미리보기

#### 2. 문서 탭

- 견적서 목록
- 계약서 목록
- 각 문서별 버전 이력
- 발송 링크 복사
- PDF 다운로드
- 고객용 링크는 `버전 고정`

UI 아이디어:

- 최신 버전은 굵게
- 이전 버전은 접기 가능한 아코디언
- 고객에게 공개된 버전은 `shared` 배지

#### 3. 설치 탭

- 설치 일정 리스트
- 타임라인 뷰
- 캘린더 미니뷰
- 여러 일정 허용

각 일정 카드:

- 시작/종료 시각
- 장소
- 설치 팀
- 상태
- 메모

액션:

- 일정 추가
- 일정 수정
- 일정 확정
- 설치 완료 처리

#### 4. 수납 탭

- 계약 금액
- 실수납 누계
- 미수금
- 수납 상태

하단:

- 입금 기록 리스트
- 영수증 발행 기록

상태값 추천:

- 미수
- 부분 수납
- 수납 완료

#### 5. 활동 탭

이 탭은 `운영 히스토리`를 한 번에 보는 곳이다.

포함:

- 미팅 로그
- 문서 로그
- 단계 변경 로그
- 설치 로그
- 수납 로그

UI는 단순 표보다 타임라인이 낫다.

## 7. 문서 UX 설계

### 견적서 / 계약서 공통 원칙

- 문서는 `본체`와 `버전`을 분리
- 공유 링크는 버전 단위
- 고객은 링크로 해당 버전만 열람
- 관리자는 최신/이전 버전 모두 열람

### 문서 리스트 카드에 필요한 정보

- 문서 종류
- 문서 번호
- 버전
- 상태
- 공유 여부
- 발송일
- 최종 수정일

### 문서 편집 UX

- 문서 편집은 전체 페이지보다 사이드 패널 + 프리뷰 분할 구성이 적절
- 왼쪽: 메타/품목/조건
- 오른쪽: 실시간 프리뷰

### 버전 관리 UX

- `저장`
- `새 버전 저장`
- `고객 발송 버전으로 지정`
- `PDF 생성`
- `링크 복사`

## 8. 설치 UX 설계

설치는 포털의 마지막 실물 단계라서 가장 명확하게 보여야 한다.

### 추천 3단 구조

- `보드 뷰`
- `리스트 뷰`
- `캘린더 뷰`

#### 보드 뷰

상태 기준:

- 예정
- 확정
- 진행 중
- 완료
- 보류

#### 리스트 뷰

시간/장소/기관/거래건/팀 기준으로 빠르게 필터링

#### 캘린더 뷰

- 설치 일정
- 미팅 일정
- 내부 캘린더 일정

를 함께 보여줄 수 있어야 한다

## 9. 캘린더 연동 설계

사용자 요구사항:

- 설치 일정과 미팅 날짜는 캘린더와 연동
- 이 캘린더는 관리자 캘린더와도 연결

권장 원칙:

- 캘린더는 별도 시스템이 아니라 `공용 이벤트 레이어`
- 이벤트 타입만 나눈다

추천 이벤트 타입:

- `meeting`
- `installation`
- `document_due`
- `internal`

동작:

- 거래건 설치 일정 생성 -> 관리자 캘린더에 자동 반영
- 파트너 포털에서 일정 수정 -> 공용 캘린더 동기화
- 관리자 캘린더에서 일정 수정 -> 거래건 설치 일정에도 반영

중요:

- 캘린더 원본은 하나만 둔다
- 설치 탭과 캘린더 탭은 같은 데이터의 다른 뷰여야 한다

## 10. 상태 전환 UX

사용자가 원한 부분을 제품적으로 풀면:

- 탭마다 따로 추가하지 않음
- 한 번의 확인으로 다음 단계 전환
- 필요한 부속 데이터는 바로 이어서 생성

예시:

### 견적 -> 계약

- 버튼: `계약 진행`
- 동작:
  - 최신 견적 버전 선택 확인
  - 계약서 초안 생성 모달 오픈
  - 상태 자동 전환

### 계약 -> 확정

- 버튼: `확정 처리`
- 동작:
  - 계약/서명 완료 여부 확인
  - 내부 판단으로 확정
  - 설치 일정 생성 CTA 노출

### 확정 -> 설치

- 버튼: `설치 일정 생성`
- 동작:
  - 일정 모달
  - 캘린더 반영
  - 상태 업데이트

### 설치 -> 수납

- 버튼: `설치 완료`
- 동작:
  - 설치 완료 금액 기록
  - 수납 등록 CTA 노출

## 11. 시각 언어 제안

방향:

- ERP처럼 무겁지 않게
- 게임 UI처럼 흐름은 명확하게
- 그러나 미니멀하고 사업 운영 툴처럼 믿음직하게

추천 톤:

- 배경: 웜 화이트 / 라이트 스톤
- 카드: 화이트
- 선: 연한 그레이
- 강조: 차콜
- 상태: 블루 / 그린 / 옐로 / 레드

추천 패턴:

- 단계 로드맵 바
- 카드 스택
- 작은 배지
- 숫자 카운터
- 접을 수 있는 타임라인

피해야 할 것:

- 과도한 그래프 남발
- 한 화면에 지나치게 많은 컬러
- 테이블만 가득한 ERP 느낌
