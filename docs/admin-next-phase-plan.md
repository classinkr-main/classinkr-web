# Admin Next Phase Plan

기준 시점: 2026-04-03  
문서 목적: 최근 손본 관리자 탭들의 다음 개발 요소와 사용성 증가 포인트를 총정리하고, 블로그 AI 기능 확장 방향을 함께 기획한다.

## 1. 이번 문서의 범위

이번 문서는 아래 두 축을 함께 다룬다.

- 최근 개발이 많이 진행된 관리자 탭의 다음 단계 기획
- 블로그 에디터의 AI 보조 기능 확장 기획

대상 탭:

- `Overview`
- `Campaigns`
- `Settings`
- `Analytics`
- `Blog Editor / 콘텐츠`

## 2. 지금 상태 한 줄 요약

현재 관리자 화면은 “뼈대가 있는 상태”를 넘어서,  
실제 운영자가 매일 열 수 있는 수준까지 올라왔다.

다만 아직 아래가 부족하다.

- 화면 간 연결성이 더 필요하다.
- 숫자를 행동으로 바꾸는 보조 UX가 더 필요하다.
- 블로그 작성은 강하지만 “AI로 더 빨라지는” 지점이 아직 없다.
- 계측은 일부만 연결되어 있어 Analytics가 완전히 차지 않는다.

즉, 다음 단계는 “새 화면 추가”보다  
`기존 탭의 사용성 강화 + 작성/운영 자동화 + 계측 연결`에 집중하는 것이 맞다.

## 3. 전체 우선순위

### P0

- 블로그 AI `다듬기` 기능
- 블로그 `템플릿 만들기 / 템플릿으로 시작`
- Overview 빠른 액션 강화
- Campaigns 발송 전 검수 UX 강화
- Analytics 계측 연결 포인트 정의

### P1

- Settings의 CTA 실제 데이터 모델 연결
- Analytics에 CTA / 다운로드 실제 수치 연결
- Campaigns 세그먼트 저장 기능
- Overview 개인화된 “오늘 해야 할 일”

### P2

- 블로그 AI 스타일 프리셋
- AI 발행 전 품질 점검
- 콘텐츠 성과 기반 추천 템플릿
- 관리자 개인별 워크스페이스/저장 뷰

## 4. 탭별 총정리

## 4-1. Overview

### 현재 상태

현재 `Overview`는 KPI 상단 유지 + 운영 허브 하단 확장까지 진행된 상태다.

이미 잘된 점:

- KPI는 빠르게 상태 파악 가능
- 오늘 처리할 일 / 일정 / 최근 콘텐츠 / 최근 캠페인 / 운영 알림이 한 화면에 있음
- 빈 상태가 단순 “데이터 없음”에서 끝나지 않음

### 지금 병목

- “많이 보이지만 무엇부터 할지”가 사용자마다 다를 수 있음
- 알림의 중요도 정렬이 더 강해질 수 있음
- 개인별/역할별 우선순위가 아직 없음

### 다음 개발 요소

#### A. 운영 시그널 고도화

- `긴급`, `오늘`, `이번 주`, `나중` 4단계 우선순위
- 알림 원인과 해결 액션을 1:1로 연결
- “이슈가 없는 상태”도 좋은 상태로 명확히 표현

#### B. 개인화된 작업 목록

- `admin`과 `branch`에 따라 다른 quick actions
- 최근 방문 탭 기반 추천 액션
- 예: “어제 멈춘 캠페인 초안 이어서 보기”

#### C. 스냅샷 블록 강화

- 최근 콘텐츠: 상태 + 수정자 + CTA 상태
- 최근 캠페인: 대상 태그 + 실패 여부 + 직전 결과
- 최근 리드: 미처리 시간 표시

### 사용성 증가 요소

- “오늘 가장 중요한 1개”를 상단 배너로 승격
- 카드 내 텍스트는 줄이고 액션 버튼은 더 명확히
- 0건 카드도 숨기지 말고 “지금 안정적”이라는 의미를 줌

## 4-2. Campaigns

### 현재 상태

`구독자 관리 / 이메일 발송 / 발송 이력` 흐름과 상단 요약, 워크플로우 스트립까지 갖춘 상태다.

이미 잘된 점:

- 운영 흐름이 `구독자 -> 발송 -> 이력`으로 읽힘
- 발송 전 판단 재료가 화면 안에 모여 있음
- 필터와 빈 상태가 이전보다 훨씬 설득력 있음

### 지금 병목

- 자주 쓰는 대상 세그먼트를 매번 다시 골라야 함
- 발송 전 “정말 이 문구가 맞는지” 검수 보조가 약함
- 캠페인과 콘텐츠/CTA가 아직 느슨하게 연결됨

### 다음 개발 요소

#### A. 저장된 세그먼트

- 자주 쓰는 태그 조합 저장
- 예: `데모신청 + 원장`, `뉴스레터 + 서울`, `VIP + 최근 참여자`

#### B. 발송 전 체크 패널 강화

- 대상 0명 여부
- 제목 길이 적정 여부
- 본문에 개인화 토큰 포함 여부
- 수신거부 링크 포함 여부
- 최근 동일 제목 캠페인과 중복 여부

#### C. 캠페인-콘텐츠 연결

- 특정 블로그 글과 연결된 캠페인 보기
- 특정 CTA와 연결된 캠페인 보기
- 나중에는 “이 캠페인이 어떤 글/CTA를 밀었는지”를 Analytics에서 같이 보기

### 사용성 증가 요소

- `테스트 발송`과 `실제 발송`을 더 분리
- 최근 캠페인 요약 카드에서 바로 재사용 복제 가능
- 이력 탭에서 실패 캠페인만 따로 필터

## 4-3. Settings

### 현재 상태

카테고리형 운영 패널 구조가 들어갔고, 실제 저장 가능한 영역과 준비중 영역이 구분되어 있다.

이미 잘된 점:

- 긴 폼에서 제어판 구조로 바뀜
- `일반 / 리드·폼 / CTA / 외부 연동 / 변경 이력` 흐름이 명확함
- 아직 구현되지 않은 영역도 허전하지 않게 의미 있게 보임

### 지금 병목

- CTA는 구조만 있고 실제 모델 연결이 없음
- 변경 이력은 아직 설명 수준
- 리드/폼 설정이 “설명 중심”이고 시뮬레이션은 부족

### 다음 개발 요소

#### A. CTA 실제 연결

- CTA 목록 조회
- CTA별 액션 타입 변경
- 링크 / 폼 / 다운로드 / 모달 연결
- 추적 이벤트명 관리

#### B. 라우팅 시뮬레이터

- “이 폼이 제출되면 어디로 가는지”를 시각적으로 보여주기
- 예: `demo_modal -> leads + subscribers + google sheet + channel talk`

#### C. 변경 이력 실제화

- 누가 변경했는지
- 저장 전/후 값
- 롤백 대상인지

### 사용성 증가 요소

- 민감 설정은 마지막 수정자와 마지막 테스트 시각 노출
- 외부 연동은 카드 내부에 상태 기록 유지
- CTA는 표 + 우측 상세 패널 구조 유지

## 4-4. Analytics

### 현재 상태

리드 중심 차트에서 `리드 / 소스 / 콘텐츠 / 캠페인 / 추적 현황` 구조로 확장되었다.

이미 잘된 점:

- 실제 숫자와 계측 준비 상태를 분리해서 보여줌
- 단순 그래프보다 해석 카드가 있음
- 운영자가 “다음에 뭘 붙이면 되는지”를 알 수 있음

### 지금 병목

- CTA 클릭, 다운로드, 페이지 체류는 아직 실제 숫자가 부족함
- 콘텐츠별 전환 기여는 추론 수준
- 공개 사이트 이벤트와 관리자 데이터가 아직 완전히 이어지지 않음

### 다음 개발 요소

#### A. 실제 계측 연결

- `click_cta`
- `download_materials`
- `page_view`
- `time_on_page`
- `submit_contact_request`

#### B. 콘텐츠 기여 모델

- 콘텐츠 상세 CTA 클릭 수
- 콘텐츠 -> 문의 전환 기여
- 다운로드 자료 -> 문의 전환 기여

#### C. 캠페인 성과 모델

- 발송 후 클릭
- 발송 후 방문
- 발송 후 문의

### 사용성 증가 요소

- 각 탭 상단에 “이번 기간 해석 한 줄” 유지
- `데이터 없음`과 `계측 미연결`을 엄격히 분리
- 가장 중요한 액션을 탭당 1개만 강조

## 5-2. 블로그 AI 방향 원칙

- 전체 글을 통째로 생성하는 버튼보다 선택 영역 보조가 더 중요하다.
- “잘 쓰게 돕는 AI”가 “대충 만들어주는 AI”보다 낫다.
- AI 결과는 덮어쓰기보다 `삽입 / 비교 / 대체 제안` 중심이어야 한다.
- 팀에서 반복하는 글 구조를 템플릿 자산으로 남겨야 한다.

## 5-3. AI 기능 우선순위

### P0

- 제목 / 요약 / CTA AI 제안
- 템플릿으로 시작
- 현재 글을 템플릿으로 저장

### P1

- 문단 확장 / 축약
- 톤 변환

- 발행 전 품질 점검

### P2

- 팀 스타일 프리셋
- 템플릿 성과 추천
- 콘텐츠 목표별 AI 워크플로우

## 5-4. AI `다듬기` 기능

### 목표

작성자가 이미 쓴 문장을 더 빠르게 개선하는 것.

### UX 권장안

본문 에디터에서 텍스트를 선택하면 우측에 작은 AI 액션 메뉴가 뜬다.

액션:

- `더 명확하게`
- `더 짧게`
- `더 설득력 있게`
- `원장 톤으로`
- `실무형 톤으로`
- `CTA 강하게`

### 결과 표시 방식

절대 바로 덮어쓰지 않는다.

옵션:

- 원문 유지
- 제안 보기
- 교체
- 아래에 삽입

### 실제 사용 예

- 서론이 길 때 -> `더 짧게`
- 문장이 밋밋할 때 -> `더 설득력 있게`
- 기능 소개가 어렵게 쓰였을 때 -> `더 명확하게`

## 5-5. AI `템플릿 만들기` 기능

### 목표

잘 쓴 글의 구조를 다음 글에도 재사용하게 만드는 것.

### 템플릿 개념

템플릿은 완성 글이 아니라 “구조 + 메타 기본값 + CTA 초안”이다.

포함 항목:

- 제목 구조 예시
- excerpt 구조
- 본문 블록 순서
- 권장 섹션 제목
- CTA 기본 문구
- SEO 기본 패턴

### 템플릿 생성 방법

#### A. 빈 템플릿으로 시작

- 인사이트형
- 제품 업데이트형
- 성공 사례형
- 이벤트 회고형
- 가이드형

#### B. 현재 글에서 템플릿 저장

- “이 글 구조를 템플릿으로 저장”
- 템플릿 이름
- 설명
- 포함 범위 선택
  - 본문 구조만
  - CTA 포함
  - SEO 포함
  - 작성자 정보 제외
