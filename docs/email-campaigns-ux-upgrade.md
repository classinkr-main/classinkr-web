# Email Campaigns UX Upgrade

문서 목적: 관리자 `캠페인` 탭의 사용성을 실제 운영 기준으로 끌어올리기 위한 상세 화면 설계와 구현 티켓을 정리한다.

관련 화면:
- `/admin/campaigns`
- `/admin/marketing`

기준 파일:
- `app/admin/marketing/page.tsx`

## 1. 현재 상태 요약

현재 캠페인 화면은 이미 아래 3단 구조를 갖고 있다.

- `구독자 관리`
- `이메일 발송`
- `발송 이력`

상단에는 KPI, 워크플로우 스트립, 탭 전환이 있고, 각 탭마다 핵심 패널이 분리되어 있다.  
즉, 구조 자체는 충분히 좋다. 다음 단계는 “기능을 더 많이 넣는 것”보다 “실수 줄이기 / 반복 작업 줄이기 / 발송 판단 더 쉽게 만들기”에 집중하는 편이 맞다.

## 2. UX 목표

이메일 운영 화면의 목표는 아래 4가지다.

- 발송 전 실수를 줄인다.
- 자주 쓰는 대상/포맷을 반복해서 재사용할 수 있게 한다.
- 발송 이후 “무슨 일이 있었는지”를 더 빨리 이해하게 한다.
- 모바일에서도 급한 운영 작업이 가능하게 한다.

## 3. 핵심 개선안

### 3-1. 발송 전 체크리스트 강화

현재 `발송 전 체크`는 정성적인 메모 중심이다.  
다음 단계에서는 실제 검수 체크리스트로 바꾼다.

체크 항목:
- 제목 입력됨
- 본문 최소 길이 충족
- 대상 수 0명 아님
- 수신거부 제외됨
- CTA 링크 존재
- 최근 동일 제목 캠페인 없음
- 테스트 발송 완료 여부

표현 방식:
- 각 항목을 `정상 / 주의 / 미완료` 배지로 표기
- `발송 가능` 상태일 때만 메인 발송 버튼 강조
- 주의 항목 클릭 시 관련 입력 영역으로 스크롤 이동

### 3-2. 테스트 발송

실운영 가치가 가장 큰 기능이다.

기능:
- `내 이메일로 테스트`
- `샘플 수신자 선택`
- `모바일 미리보기`
- `마지막 테스트 시각` 표시

UX:
- 작성 패널 우측 상단 또는 `발송 전 체크` 패널 최상단에 배치
- 테스트 발송 후 성공 토스트 + 최근 테스트 정보 남김
- 테스트 없이 실발송하려 하면 한 번 더 확인

### 3-3. 저장 세그먼트

현재는 필터링 후 바로 작성으로 넘어가는 구조다.  
반복 운영을 위해 세그먼트 저장이 필요하다.

예시 세그먼트:
- `전체 활성 구독자`
- `데모 신청 유입`
- `문의 유입`
- `뉴스레터 유입`
- `태그: webinar`

UX:
- 구독자 탭 상단 필터 아래 `저장된 세그먼트` 칩 영역 추가
- 칩 클릭 시 즉시 필터 적용
- `현재 조건 저장` 버튼으로 새 세그먼트 생성
- 세그먼트명 수정 / 삭제 가능

### 3-4. 캠페인 복제

실제로는 새 캠페인을 처음부터 만드는 경우보다, 이전 발송을 복제해 수정하는 경우가 많다.

기능:
- 발송 이력 행 액션 `복제`
- 복제 시 제목, 본문, 대상 태그, CTA, 내부 메모 복사
- 새 초안으로 `compose` 탭 열기

UX:
- 이력 화면에서 가장 많이 눌릴 액션이므로 `상세 보기`보다 `복제`를 더 눈에 띄게 둔다.

### 3-5. 예약 발송

즉시 발송만 있는 구조는 운영 리듬을 만들기 어렵다.

기능:
- `즉시 발송 / 예약 발송`
- 발송 예정 일시
- 예약 상태 캠페인 목록
- 예약 취소 / 수정

UX:
- 발송 버튼 옆에 옵션으로 두기보다, 작성 폼 하단 `발송 방식` 블록으로 분리
- 예약 캠페인은 이력 탭에서 `예약됨` 상태로 구분

### 3-6. 결과 해석 카드

지금 이력은 상태 확인 위주다. 다음 단계에서는 해석을 붙인다.

각 캠페인 카드/행에 추가:
- 대상 수
- 발송 상태
- 연결된 태그
- 연결된 콘텐츠 또는 CTA
- 다음 액션 추천

예시 문장:
- `발송 성공 · 대상 214명 · CTA 연결 필요`
- `초안 상태 · 테스트 발송 없음`
- `실패 · 웹훅 설정 점검 필요`

## 4. 상세 화면 설계

### 4-1. 전체 헤더

```text
[좌]
캠페인
설명 문구

[우]
새로고침 | 테스트 발송 | 새 캠페인 | 예약 발송
```

헤더 행동 원칙:
- 급한 액션은 `새 캠페인`, `테스트 발송`
- 부가 액션은 `새로고침`, `예약 발송`
- 모바일에서는 2줄로 자연스럽게 래핑

### 4-2. 구독자 탭

```text
[상단]
검색
상태 필터
유입 경로 필터

[중단]
저장된 세그먼트 칩
+ 현재 조건 저장

[본문]
좌: 구독자 테이블
우: 채널 믹스 / 최근 등록 / 추천 다음 액션
```

추가 인터랙션:
- 세그먼트 칩 클릭 시 필터 즉시 반영
- 세그먼트 hover 또는 클릭 시 수정/삭제
- 테이블 상단에 `현재 예상 발송 인원` 표시

빈 상태:
- `아직 구독자가 없습니다`
- 액션: `첫 구독자 추가`
- 보조 액션: `이메일 먼저 작성`

### 4-3. 이메일 발송 탭

```text
[좌]
제목
본문
대상 태그
발송 방식 (즉시 / 예약)

[우]
대상 요약
발송 전 체크리스트
테스트 발송
최근 발송 정보
```

우측 패널 우선순위:
1. 대상 수
2. 발송 가능 여부
3. 테스트 발송
4. 중복/위험 경고
5. 최근 유사 캠페인

권장 행동 흐름:
1. 제목/본문 입력
2. 대상 태그 선택
3. 테스트 발송
4. 체크리스트 확인
5. 즉시 또는 예약 발송

### 4-4. 발송 이력 탭

```text
[상단]
상태 필터

[본문]
좌: 발송 이력 리스트
우: 최근 상태 요약 / 추천 다음 액션
```

이력 행 구조:
- 제목
- 발송 시각
- 상태 배지
- 대상 수
- 태그
- 액션: `복제`, `상세`, `실패 원인`

권장 추가 상태:
- `draft`
- `scheduled`
- `sent`
- `failed`

## 5. 마이크로 UX 규칙

- `실발송` 버튼은 가장 마지막에만 강하게 강조한다.
- 위험 배지는 빨간색을 아껴 쓴다. 진짜 실패/차단에만 사용한다.
- 테스트 발송 완료 전에는 발송 버튼 옆에 작은 `권장` 힌트 표시.
- 상태가 많은 화면은 표보다 카드형 요약을 같이 써서 빠른 판단을 돕는다.
- 모바일에서는 필터를 한 줄에 억지로 넣지 말고 가로 스크롤 칩 또는 줄바꿈으로 처리한다.

## 6. 구현 우선순위

### P0

- 테스트 발송
- 발송 전 체크리스트 실제화
- 발송 대상 수 즉시 계산
- 중복 제목 / CTA 누락 경고

### P1

- 저장 세그먼트
- 캠페인 복제
- 예약 발송
- 예약 상태 표시

### P2

- 최근 유사 캠페인 추천
- 콘텐츠/CTA 연결 표시
- 성과 해석 문장 자동 생성
- 세그먼트 사용 이력

## 7. 구현 티켓

### T1. 발송 전 체크리스트 실제화

목표:
- 현재 정성 메모형 패널을 실제 검수 패널로 바꾼다.

작업:
- 제목, 본문, 대상 수, CTA 링크, 테스트 발송 여부 계산
- `정상 / 주의 / 미완료` 상태 표시
- 발송 버튼 비활성 조건 연결

파일:
- `app/admin/marketing/page.tsx`
- `components/admin/...` 분리 필요 시 신규 컴포넌트

### T2. 테스트 발송 UI + 액션

목표:
- 실발송 전에 샘플 발송 가능하게 만든다.

작업:
- 테스트 이메일 입력 또는 기본 관리자 이메일 사용
- `테스트 발송` 버튼
- 마지막 테스트 시각 표시
- 성공/실패 토스트

파일:
- `app/admin/marketing/page.tsx`
- 관련 API route 필요 시 추가

### T3. 저장 세그먼트

목표:
- 반복 대상 선택 작업을 줄인다.

작업:
- 세그먼트 스키마 정의
- 필터 조건 저장/불러오기
- 세그먼트 칩 리스트 UI

파일:
- `app/admin/marketing/page.tsx`
- 저장 위치 정의용 데이터 파일 또는 API

### T4. 캠페인 복제

목표:
- 이력 기반 재사용 흐름 만든다.

작업:
- `복제` 액션 추가
- 기존 캠페인 데이터를 compose 초안으로 복사
- 복제 후 토스트 + compose 탭 포커스

파일:
- `app/admin/marketing/page.tsx`

### T5. 예약 발송

목표:
- 즉시 발송 외 시간 예약 운영 가능하게 한다.

작업:
- 즉시/예약 선택
- 예약 일시 입력
- 예약 상태 저장
- 이력 탭 상태 표시

파일:
- `app/admin/marketing/page.tsx`
- 관련 데이터 저장 로직

### T6. 이력 해석 카드

목표:
- 숫자 확인을 넘어서 다음 액션까지 보이게 만든다.

작업:
- 상태 요약 문장 추가
- 실패 원인 또는 다음 액션 라벨
- 콘텐츠/CTA 연결 필드 자리 마련

파일:
- `app/admin/marketing/page.tsx`

## 8. 추천 실행 순서

1. `T1 발송 전 체크리스트`
2. `T2 테스트 발송`
3. `T4 캠페인 복제`
4. `T3 저장 세그먼트`
5. `T5 예약 발송`
6. `T6 이력 해석 카드`

## 9. 결론

캠페인 탭은 새 구조를 갈아엎을 필요가 없다.  
지금 구조 위에 아래 3가지만 먼저 얹으면 체감 사용성이 크게 오른다.

- 테스트 발송
- 발송 전 체크리스트
- 캠페인 복제

이 3개만 먼저 들어가도 “보여주는 화면”에서 “실제로 매일 쓰는 운영 도구”로 올라간다.
