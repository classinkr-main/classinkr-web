# 총판 정산 — 총판용 견적서와 미수금

기준 시점: 2026-10-23
범위: `/admin/quotes` 견적 상세의 총판 정산 영역, `총판 미수금` 탭, `/share/distributor-quote/[token]`

## 1. 돈의 흐름 (C1 물량)

- 회사가 하드웨어를 원가(구입가)로 미리 사 둔다.
- 고객은 총액을 하드웨어 총판에게 낸다.
- 총판은 그중 원가를 회사로 입금한다. 예: 고객 견적 630만원 → 총판이 회사로 530~550만원 입금.
- 그래서 회사 입장에서는 "총판에게서 받을 원가"가 미수금이고, **매출은 총판 입금이 확인된 시점**에 잡는다.
- 이전 방식(총판이 먼저 사 두고 회사는 받을 돈만 챙기며 설치 즉시 매출)과 번갈아 쓰여 왔지만,
  앞으로는 C1 방식을 기본으로 본다. 이 화면은 C1 방식만 다룬다.

## 2. 총판용 견적서

- 고객 견적서와 같은 양식(`QuoteDocumentPreview`)이고 금액만 다르다. 수신처는 총판, 참조란은 고객사다.
- 기본 대상 품목: `itemType=hardware` + AI Suite(`online-suite-monthly`). 설치·교육 등은 기본 제외이고 줄마다 포함 여부를 바꿀 수 있다.
- 원가는 견적마다 직접 입력하거나 **원가 템플릿**(품목 코드 × 최소 구매 대수 → 단가)으로 채운 뒤 고객별로 덮어쓴다.
- 고객 단가·고객 합계는 총판 문서에 싣지 않는다.

## 3. 발행 시점

| 설정 | 동작 |
| --- | --- |
| 고객 동의 시 자동 발행 | 고객이 공유 링크에서 "이 견적으로 진행"을 누르면 자동 발행·발송 |
| 설치 완료 시 발행 | 직원이 견적 상세에서 "설치 완료 → 총판 견적서 발행"을 직접 누르면 발행·발송 |
| 직접 발행 | "지금 발행"을 누를 때만 |

- 발행 = 공유 토큰 생성 + 총판 이메일 발송(이메일이 있고 자동 발송이 켜져 있을 때) + 운영 알림.
- 원가을 저장한 뒤 고객 견적 버전이 바뀌었거나 원가가 비어 있으면 자동 발행하지 않고
  `review_required_reason`과 재확인 알림을 남긴다. 금액을 다시 저장하면 해소된다.
- 이메일 실패는 발행을 되돌리지 않는다. 화면에서 링크를 복사해 전달하거나 메일을 다시 보낸다.
- 발행 후에는 금액을 고치지 않는다. 바꾸려면 정산을 취소(입금 기록이 없을 때만)하고 다시 설정한다.

## 4. 미수금과 매출

- 상태: 발행 전 → 입금 대기 → 일부 입금 → 입금 완료(또는 취소).
- 입금은 견적 상세의 총판 정산 영역에서 금액·입금일로 기록한다. 부분 입금은 누적된다.
- 입금 1건을 기록할 때마다 그 입금일이 속한 달로 **매출 원장 입력 큐에 초안**(확도 확정)을 올린다.
  원장은 CNY 이고 자동 환산을 하지 않으므로 금액은 0으로 두고, 원화 입금액은 메모·메타데이터에 남긴다.
  검수자가 CNY 금액을 넣고 체크·적용한다(계약 서명 자동 제안과 같은 방식).
- 입금 기록을 지우면 아직 검수 전인 초안도 함께 지운다. 이미 체크·적용된 초안은 원장에서 직접 정정한다.
- `총판 미수금` 탭은 받을 금액, 기한 경과 금액, 건별 남은 금액을 보여 주고 행을 누르면 해당 견적으로 이동한다.
