# 하드웨어 C방식/H방식 — 총판 정산과 매출 순서

기준 시점: 2026-10-23
범위: `/admin/quotes` 견적 상세의 총판 정산 영역, `총판 미수금` 탭, `/share/distributor-quote/[token]`,
하드웨어 매출 원장 초안. 입고·출고 물량에의 적용은 §6(다음 단계).

## 1. 왜 두 방식인가

하드웨어 물량은 **누가 먼저 사 두었는지**에 따라 돈과 매출의 순서가 달라진다. 두 방식이 시기마다 번갈아 쓰여
왔고, 2026-10 기준으로는 **C방식을 기본**으로 간다. 방식 이름은 재고 로트 이름의 첫 글자와 같다
(C1 로트 = C방식, H1~H8 로트 = H방식 — `lib/repositories/hardware-inventory.ts`의 로트 해석 참고).

하드웨어 총판은 **퀴드러닝**이다. 하드웨어 고객 견적의 표준 공급자(`STANDARD_QUOTE_SUPPLIER`)와 같은 회사이고,
총판 정산의 기본값(`DEFAULT_HARDWARE_DISTRIBUTOR`)이다. 내부에서 "배 대표님"이라고 부르면 이 총판을 뜻한다.
견적서에는 등록 정보를 그대로 쓴다 — 대표 **조혜리**, 담당자 **배철웅**. 호칭을 붙이거나 이름을 바꾸지 않는다.

## 2. 두 방식 비교

| | C방식 · 회사 선매입 | H방식 · 총판 선매입 |
| --- | --- | --- |
| 하드웨어 구입 | 회사가 원가(구입가)로 미리 사 둔다 | 총판이 먼저 사 둔다(수입) |
| 고객 결제 | 고객이 총액을 총판에게 낸다 | 기존 방식대로 |
| 총판 ↔ 회사 | 총판이 원가를 회사로 입금한다(예: 고객 630만원 → 회사로 530~550만원) | 원가 미수 없음 |
| 총판용 견적서 | 있음 — 고객 견적서와 같은 양식, 금액만 원가 | 없음 |
| 회사 매출 인식 | **총판 입금 확인 시점**(입금 1건 = 매출 초안 1건) | **설치 완료 시점**(직원이 누름) |
| 미수금 추적 | 총판 미수금 탭 | 해당 없음 |

## 3. 진행 순서

**C방식**

1. 고객 견적 작성(공급자 = 퀴드러닝).
2. 견적 상세 › 총판 정산에서 방식 = C, 품목별 원가 입력(직접 또는 원가 템플릿), 발행 시점 선택.
3. 발행: 고객 동의 시 자동 / 설치 완료(직원 버튼) / 직접 발행 — 총판용 견적서 링크 + 총판 이메일 + 사내 알림.
4. 총판 입금 기록(부분 입금 누적) → 입금일이 속한 달로 매출 원장 입력 큐에 초안(확도 확정).
5. 매출 원장에서 검수자가 CNY 금액을 넣고 체크·적용 → 매출 반영.

**H방식**

1. 고객 견적 작성.
2. 견적 상세 › 총판 정산에서 방식 = H 저장.
3. 설치가 끝나면 직원이 "설치 완료 → 매출 잡기"를 누른다 → 설치일이 속한 달(KST)로 매출 원장 초안.
4. 매출 원장에서 검수자가 CNY 금액을 넣고 체크·적용.

설치 완료는 자동으로 감지하지 않는다. **항상 직원이 직접 누른다.**

## 4. 총판용 견적서(C방식)

- 고객 견적서와 같은 승인 양식(2026-10-21 성남여고 승인 디자인, `QuoteDocumentPreview` — 웹·PDF 공용)이다.
  견적 상세에서 발행 전에 미리보기로 확인할 수 있다.
- 공급자 = 회사(이이오클래스인코리아), 수신처 = 총판(퀴드러닝, 담당자 배철웅), 참조 = 고객사. 고객 견적의
  공급자(퀴드러닝)를 그대로 쓰지 않는다 — 그러면 "총판 → 총판" 문서가 된다.
- 기본 대상 품목: 하드웨어 + AI Suite(`online-suite-monthly`). 설치·교육은 기본 제외, 줄마다 포함 여부 변경 가능.
- 원가는 구매 대수·고객마다 다르므로 견적마다 직접 입력하거나 원가 템플릿(품목 × 최소 구매 대수)으로 채운 뒤 덮어쓴다.
- 고객 단가·고객 합계는 싣지 않는다.
- 자동 발행 보류: 원가 저장 뒤 고객 견적 버전이 바뀌었거나 원가가 비어 있으면 발행하지 않고 재확인 알림을 남긴다.
- 이메일 실패는 발행을 되돌리지 않는다(링크 복사·메일 재발송). 발행 후 금액 변경은 취소(입금 없을 때) 후 재설정.

## 5. 매출 원장 초안 규칙(두 방식 공통)

- 매출 원장(`branch_sales_ledger_drafts`)은 CNY 이고 자동 환산을 하지 않는다. 초안 금액은 0, 원화 금액은
  메모·메타데이터에 참고로 남긴다. 검수·적용은 사람이 한다(계약 서명 자동 제안과 같은 방식).
- C방식: 입금 1건 = 초안 1건(`operation = distributor-payment-confirmed`). 입금 기록을 지우면 검수 전 초안만 함께
  지우고, 체크·적용된 초안은 원장에서 직접 정정한다.
- H방식: 정산 1건 = 초안 1건(`operation = hmode-installation-confirmed`).

## 6. 다음 단계 — 입고·출고 물량

하드웨어 재고(입고·출고)도 같은 C/H 구분으로 움직인다. 아직 연결하지 않았고, 붙일 때의 기준은 다음과 같다.

- 입고: 로트 이름이 방식을 나타낸다(C1 = 회사 선매입 물량, H1~H8 = 총판 선매입 물량).
- 출고: 출고 로트의 방식이 그 고객 건의 총판 정산 방식과 같아야 한다. C 로트 출고 건은 C방식 정산(원가 미수·입금 시 매출),
  H 로트 출고 건은 H방식(설치 완료 시 매출)으로 이어진다.
- 매출을 찍는 순서가 방식마다 다르므로, 재고 화면에서 매출을 따로 찍지 않고 이 문서의 §3 순서를 따른다.
