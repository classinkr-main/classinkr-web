# Admin Tab Wireframes

기준 시점: 2026-04-03  
문서 목적: 현재 관리자 탭 중 운영 가치가 얕은 영역을 실제 사용 가능한 수준으로 확장하기 위한 상세 화면 설계를 정의한다.

## 1. 범위

이번 문서는 아래 4개 탭을 우선 대상으로 한다.

- `Overview`
- `Campaigns`
- `Settings`
- `Analytics`

아래 탭은 이번 단계에서 구조 유지가 기본이다.

- `CRM / 리드`
- `캘린더`
- `콘텐츠`
- `Dev Mode`

`지사 관리`, `회원 관리`는 다음 단계 확장 후보로 남기되, 이번 문서에서는 직접 구현 대상에서 제외한다.

## 2. 목표

이번 개편의 목표는 “예쁜 관리자”가 아니라 “매일 여는 운영 도구”를 만드는 것이다.

핵심 원칙:

- 첫 화면 5초 안에 오늘 할 일을 알 수 있어야 한다.
- 데이터 조회와 작업 실행이 같은 화면 안에서 자연스럽게 이어져야 한다.
- 저장 실수보다 보수적인 UX를 선택한다.
- 빈 상태에서도 다음 액션이 바로 보여야 한다.
- 지표는 단순 숫자보다 해석과 액션이 함께 보여야 한다.

## 3. 개편 후 권장 IA

```text
/admin/overview
/admin/crm
/admin/calendar
/admin/blog
/admin/campaigns      -> 기존 /admin/marketing 승격
/admin/settings
/admin/analytics
/admin/branch         -> 유지
/admin/users          -> 유지
/admin/dev
```

사이드바 명칭 권장:

- `Overview`
- `CRM / 리드`
- `캘린더`
- `콘텐츠`
- `캠페인`
- `Settings`
- `Analytics`
- `지사 관리`
- `회원 관리`
- `Dev Mode`

## 4. 공통 UX 규칙

### 4-1. 레이아웃

- 좌측 사이드바는 유지한다.
- 본문은 최대 `1200 ~ 1320px` 폭 기준으로 설계한다.
- 주요 화면은 `상단 요약 + 본문 2~3개 블록` 구조로 통일한다.
- 표가 긴 화면은 헤더를 sticky 처리한다.

### 4-2. 상호작용

- 조회는 카드와 테이블 중심으로 구성한다.
- 수정은 가능하면 우측 드로어에서 처리한다.
- 모달은 삭제 확인, 발송 확인, 연결 테스트처럼 짧고 위험한 작업에만 쓴다.
- 저장은 자동저장보다 `명시 저장`을 기본으로 한다.
- 미저장 상태가 있으면 저장 버튼에 점 배지를 노출한다.

### 4-3. 필터

- 기간 필터 위치는 각 탭 우측 상단으로 통일한다.
- 자주 쓰는 필터만 상단에 노출하고, 나머지는 `고급 필터` 드롭다운으로 숨긴다.
- 필터 상태는 탭 이동 후에도 유지한다.

### 4-4. 상태 표시

- 파란색: 신규/정보성
- 초록색: 정상/완료
- 노란색: 주의/확인 필요
- 빨간색: 실패/위험

빨간색은 정말 위험한 항목에만 사용한다.

### 4-5. 빈 상태

모든 빈 상태에는 아래 3가지가 들어가야 한다.

- 왜 비어 있는지 한 줄 설명
- 지금 할 수 있는 첫 액션
- 필요하면 연결된 탭으로 가는 바로가기

예:

- “아직 캠페인이 없습니다.”
- “첫 캠페인을 만들어 구독자에게 테스트 메일을 보내보세요.”
- `새 캠페인 만들기`

## 5. Overview 상세 설계

### 5-1. 역할

`Overview`는 KPI 대시보드가 아니라 “운영 시작 화면”이다.  
현재 상단 KPI 6개는 유지하고, 하단에서 오늘 처리해야 할 일과 최근 활동을 바로 보여준다.

### 5-2. 화면 구조

```text
[Header]
Admin / Overview
우측: 기간 요약, 새로고침

[KPI Row]
현재 구조 유지

[Section A - 2열]
좌: 오늘 처리할 일
우: 이번 주 일정

[Section B - 2열]
좌: 최근 리드
우: 최근 콘텐츠

[Section C - 2열]
좌: 최근 캠페인
우: 운영 알림 / 연동 상태
```

### 5-3. 블록별 상세

#### A. 오늘 처리할 일

카드 리스트 형태.

항목 예시:

- 미처리 신규 리드 `N건`
- 24시간 이상 미처리 리드 `N건`
- 오늘 일정 `N개`
- 실패 캠페인 `N건`
- 테스트 안 된 외부 연동 `N개`

각 행 구성:

- 좌측: 상태 아이콘
- 중앙: 제목 + 보조 설명
- 우측: `바로가기`

실사용 포인트:

- 숫자보다 “당장 해야 하는 일” 문장형 라벨이 중요하다.
- `0건`인 항목은 흐리게 처리하거나 숨긴다.

#### B. 이번 주 일정

캘린더 전체를 복붙하지 않는다.  
이번 주 일정 5~7개만 노출한다.

항목:

- 일정명
- 날짜/시간
- 일정 타입 배지
- 담당자

우측 상단 액션:

- `캘린더 열기`
- `새 일정 추가`

#### C. 최근 리드

현재 Overview 하단 리스트를 유지하되 아래만 보강한다.

- 소스 배지
- 상태 배지
- 접수 시간
- 기관명
- `CRM에서 보기`

#### D. 최근 콘텐츠

블로그 포스트 최근 4개.

노출 정보:

- 제목
- 상태: `공개 / 비공개 / 초안`
- 수정 시각
- 작성자

액션:

- `수정`
- `콘텐츠 전체 보기`

#### E. 최근 캠페인

기존 `/admin/marketing` 데이터 재활용.

노출 정보:

- 캠페인 제목
- 발송 상태
- 발송 일시
- 대상 수신자 수
- 태그 요약

액션:

- `상세 보기`
- `새 캠페인`

#### F. 운영 알림 / 연동 상태

이 블록은 Overview의 핵심이다.

우선순위 높은 경고:

- 웹훅 URL 미설정
- 최근 테스트 실패
- 이메일 발송 webhook 미설정
- 이번 주 리드 급감
- CTA 설정 누락

각 행 구성:

- 심각도 아이콘
- 제목
- 짧은 설명
- 관련 탭 이동 버튼

### 5-4. UX 메모

- Overview는 스크롤이 너무 길어지면 안 된다.
- 각 블록은 최대 4~7개만 보여주고 `더 보기`로 넘긴다.
- 카드 전체 클릭 대신 명시적인 액션 버튼을 둔다.
- 첫 진입 시 가장 중요한 경고 한 건은 상단 배너로 승격 가능하다.

## 6. Campaigns 상세 설계

### 6-1. 역할

`Campaigns`는 단순 이메일 발송 화면이 아니라  
“구독자 관리 + 발송 + 성과 확인”까지 묶는 운영 탭이다.

기존 `/admin/marketing`을 승격하는 구조로 가는 것이 가장 효율적이다.

### 6-2. 화면 구조

```text
[Header]
캠페인
우측: 기간 필터, 새로고침, 새 캠페인

[Summary Cards]
전체 구독자 / 활성 구독자 / 최근 30일 신규 / 총 캠페인 수

[Inner Tabs]
구독자
이메일 발송
발송 이력
성과 요약
```

### 6-3. 탭별 상세

#### A. 구독자

```text
[Top Controls]
검색 | 태그 필터 | 소스 필터 | 상태 필터 | 구독자 추가

[Body]
좌: 구독자 테이블
우: 선택 시 구독자 상세 드로어
```

테이블 컬럼:

- 이름
- 이메일
- 기관명
- 태그
- 유입 소스
- 상태
- 등록일

드로어 구성:

- 기본 프로필
- 유입 경로
- 현재 태그
- 최근 수신 이력
- 수신거부 여부

액션:

- 태그 수정
- 수신거부 처리
- 삭제

UX 포인트:

- 태그는 칩 형태로 다루고, 필터 선택과 같은 컴포넌트를 재사용한다.
- 행 액션 버튼을 많이 두기보다 상세 드로어에서 처리한다.

#### B. 이메일 발송

```text
[2열 레이아웃]
좌: 작성 폼
우: 발송 미리보기 / 대상 요약 / 체크리스트
```

좌측 작성 폼:

- 제목
- 본문
- 대상 태그
- 발송 대상 예상 수

우측 요약 패널:

- 샘플 미리보기
- 예상 수신자 수
- 제외 대상 수
- 발송 전 체크리스트
  - 제목 입력됨
  - 본문 입력됨
  - 대상 0명 아님
  - 발송 webhook 설정됨

하단 고정 액션:

- `임시 저장`
- `테스트 발송`
- `실제 발송`

실사용 UX:

- 발송은 확인 모달 1회를 둔다.
- `실제 발송`은 빨간색 금지. 기본 강조색 유지.
- `대상 0명`이면 발송 버튼 비활성화.

#### C. 발송 이력

카드보다 테이블이 좋다.

컬럼:

- 제목
- 대상 태그
- 발송 수
- 상태
- 발송 시각
- 작성자

행 클릭 시 드로어:

- 본문 미리보기
- 대상 필터
- 발송 결과
- 실패 원인

#### D. 성과 요약

초기에는 계측 한계가 있으므로 아래까지만 제공한다.

- 기간별 발송 수
- 태그별 발송 수
- 성공/실패 비율
- 최근 10개 캠페인 추이

후속 확장:

- 오픈율
- 클릭률
- 전환 기여

## 7. Settings 상세 설계

### 7-1. 역할

`Settings`는 긴 폼이 아니라 “운영 규칙 제어판”이어야 한다.

이번 단계에서는 아래 5개 카테고리만 구현한다.

- `일반`
- `리드/폼`
- `CTA`
- `외부 연동`
- `변경 이력`

### 7-2. 화면 구조

```text
[Header]
Settings
우측: 저장 / 변경 취소

[2열]
좌: 카테고리 네비
우: 상세 설정 패널
```

좌측 카테고리 항목에는 다음 상태를 붙일 수 있다.

- 미저장 변경 있음
- 경고 있음
- 최근 수정됨

### 7-3. 카테고리별 상세

#### A. 일반

섹션:

- 사이트 기능
- 배너 문구
- 공통 운영 문구

필드:

- 데모 신청 폼 on/off
- 블로그 섹션 on/off
- 데모 배너 on/off
- 공지 배너 on/off
- 배너 문구 입력

우측 보조 패널:

- 현재 공개 사이트에 어떤 영향이 있는지 한 줄 요약

예:

- “데모 신청 폼을 끄면 Hero와 Final CTA 모달이 비활성화됩니다.”

#### B. 리드/폼

섹션:

- 폼별 동작 규칙
- 성공/실패 메시지
- 라우팅 규칙

노출 항목:

- 데모 신청 폼
- 문의 폼
- 뉴스레터 구독

각 행에서 보여줄 것:

- source 키
- 저장 대상
- 외부 전달 대상
- 추적 이벤트명

예:

- `demo_modal -> leads + subscribers + google sheet + channel talk`

여기서는 문장형 설명이 중요하다.

#### C. CTA

문서 [admin-cta-tab-spec.md] 기반으로 설계한다.

```text
[상단]
검색 | 페이지 필터 | 액션 타입 필터 | 활성화 필터 | 새 CTA

[본문 2열]
좌: CTA 목록
우: CTA 상세 편집
```

목록 컬럼:

- 페이지
- 위치
- 라벨
- 액션 타입
- 대상 요약
- 활성화 여부

상세 패널 섹션:

- 기본 정보
- 액션 설정
- 폼 설정
- 추적 설정
- 노출 설정
- 미리보기

지원 액션 타입:

- `link`
- `form`
- `download`
- `modal`

실사용 UX:

- 폼 타입이 아니면 폼 설정 섹션은 숨긴다.
- 다운로드 타입이면 파일 연결과 다운로드 이벤트를 같이 보여준다.
- 우측 하단에 `저장`, `복제`, `비활성화`를 둔다.

#### D. 외부 연동

현재 페이지 구조를 확장한다.

각 연동 카드:

- 이름
- 설명
- URL 입력
- 연결 상태
- 마지막 테스트 시각
- `테스트` 버튼

연동 목록:

- Google Sheet
- Lead Webhook
- ChannelTalk
- Email Webhook

실사용 UX:

- 테스트 성공/실패는 토스트만 쓰지 말고 카드 내부에도 마지막 상태를 남긴다.
- 민감 URL은 일부 마스킹 옵션 제공 가능.

#### E. 변경 이력

이번 단계에 완전한 revision 시스템이 없어도 UI는 먼저 열 수 있다.

표시 형태:

- 타임라인
- 수정자
- 수정 시각
- 카테고리
- 변경 요약

각 이력 클릭 시:

- 이전 값
- 이후 값
- 관련 설정으로 이동

## 8. Analytics 상세 설계

### 8-1. 역할

`Analytics` 이름은 유지하되, 리드 수 차트만 보여주는 탭이 아니라  
“유입 → 클릭 → 다운로드 → 문의 → 전환”을 보는 분석 허브로 확장한다.

### 8-2. 화면 구조

```text
[Header]
Analytics
우측: 기간 필터 | 비교 기간 | 내보내기

[Summary Row]
방문 / CTA 클릭 / 다운로드 / 리드 / 전환

[Inner Tabs]
리드
CTA
다운로드
체류
콘텐츠
소스
```

### 8-3. 탭별 상세

#### A. 리드

블록:

- 일별 리드 추이
- 상태 퍼널
- 소스별 전환율
- 최근 변화 해석 카드

해석 카드 예:

- “문의 수는 늘었지만 전환율은 지난주 대비 8% 하락”

#### B. CTA

블록:

- CTA 총 클릭 수
- 페이지별 CTA 성과
- 버튼별 클릭 순위
- CTA별 문의 전환 기여

권장 차트:

- 상단 카드
- 막대 차트
- 순위 테이블

#### C. 다운로드

블록:

- 전체 다운로드 수
- 자료별 다운로드 순위
- 다운로드 후 문의 전환
- 페이지별 다운로드 클릭

이 탭은 특히 `download_asset` 이벤트가 필요하다.

#### D. 체류

블록:

- 페이지별 평균 체류 시간
- 이탈 높은 페이지
- 랜딩 페이지별 성과

주의:

- 체류 데이터는 샘플 수가 적으면 오해가 크므로, 표본 수를 함께 보여준다.

#### E. 콘텐츠

블록:

- 블로그 유입 순위
- 글별 CTA 클릭률
- 글별 문의 전환 기여
- 최근 30일 성장 글

표 중심이 적합하다.

컬럼 예:

- 제목
- 조회
- CTA 클릭
- 문의 전환
- 최근 7일 변화

#### F. 소스

블록:

- demo_modal / contact_page / newsletter / 기타 CTA
- 첫 유입 페이지
- 소스별 품질 비교

“품질”은 단순 유입 수가 아니라 아래를 함께 본다.

- 평균 체류
- CTA 클릭률
- 리드 전환율

### 8-4. UX 포인트

- 차트만 두면 읽기 힘들다. 각 섹션 상단에 `이번 기간 해석 한 줄`을 둔다.
- 비교값은 `지난 기간 대비`로 통일한다.
- 데이터가 없는 영역은 “계측 미연결”인지 “실제 0건”인지 분리해서 보여준다.
- 내보내기는 모든 탭에 두기보다 상단 공통 액션 하나로 통합한다.

## 9. 계측 이벤트 정의

Analytics 확장을 위해 최소한 아래 이벤트가 필요하다.

- `view_page`
- `click_cta`
- `open_demo_modal`
- `submit_demo_request`
- `submit_contact_request`
- `download_asset`
- `subscribe_newsletter`

권장 파라미터:

- `page`
- `section`
- `cta_id`
- `asset_id`
- `source`
- `content_id`

## 10. 빈 상태 설계 예시

### Overview

- “오늘 처리할 일이 없습니다.”
- 보조 문구: “이번 주 일정과 최근 캠페인을 먼저 확인해보세요.”

- “아직 구독자가 없습니다.”
- 액션: `구독자 추가`, `구독 폼 확인`

### Settings / CTA

- “등록된 CTA가 없습니다.”
- 액션: `첫 CTA 만들기`

### Analytics

- “이 영역은 아직 계측 데이터가 없습니다.”
- 보조 문구: “CTA 클릭과 다운로드 이벤트 연결 후 그래프가 채워집니다.”

## 11. 단계별 구현 권장 순서

### Phase 1

- 사이드바에 `캠페인` 노출
- Overview 하단 블록 추가
- Settings를 카테고리형으로 개편

### Phase 2

- Analytics 내부 탭 구조 추가
- CTA 설정 화면 추가
- 외부 연동 상태 기록 표시

### Phase 3

- 다운로드/체류 분석 고도화
- 변경 이력 실제 저장
- CTA별 전환 기여 분석
