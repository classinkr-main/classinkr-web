적합한 학원

지점이 늘며 수업 기준이 흔들리기 시작한 본사

프랜차이즈·다지점 학원에서 교안 배포, 수업 품질, 녹화·복습 제공, 권한 관리, 신규 지점 온보딩이 지점마다 달라진다면 먼저 맞습니다.

  • 지점마다 수업 자료와 진도 기준이 달라지는 본사

  • 강사 교체 때 교안, 녹화, 학생 기록이 끊기는 학원

  • 지점 수업 품질과 복습 제공 상태를 보고서로만 확인하는 운영팀

  • 원장, 지점장, 강사, 보조의 접근 권한을 분리해야 하는 조직

Enterprise Story

작을 때는 넘어가던 문제가, 지점이 늘면 본사 리스크가 됩니다.

한두 지점일 때는 전화와 메신저, 엑셀 보고로도 버틸 수 있습니다. 하지만 지점이 늘고 강사가 바뀌고 커리큘럼이 세분화되면, 본사는 더 이상 현장을 감으로 관리할 수 없습니다.

그래서 ClassIn은 본사 교안, 권한, 녹화·복습, 관리자 확인을 한 흐름으로 묶어 지점 확장 속도보다 먼저 수업 기준을 고정합니다.

월요일 오전의 운영팀

본사 운영팀은 오늘도 세 가지 질문을 동시에 받습니다.

A지점은 녹화 링크가 늦었고, B지점은 신규 강사가 다른 교안으로 수업했고, C지점은 학부모가 지난 진도 기준을 묻습니다. 문제는 각각 달라 보이지만 뿌리는 같습니다. 본사 기준이 지점 수업 안으로 내려가지 못한 것입니다.

  1. Before

    지점마다 다른 방식

    교안은 본사에 있지만 실제 수업 자료는 강사 개인 저장소, 지점 메신저, 별도 드라이브로 흩어집니다.

  2. Turning Point

    수업 기준을 시스템으로 고정

    EDB 교안, 권한, 녹화·복습 제공 흐름을 먼저 잡으면 본사의 기준이 실제 수업 장면으로 내려갑니다.

  3. After

    확장은 복제가 됩니다

    신규 지점과 신규 강사는 처음부터 같은 수업 구조에서 출발하고, 본사는 예외와 리스크를 더 빨리 확인합니다.

매주 반복되는 장면

본사 운영회의

지점별 진도와 복습 제공 상태를 같은 기준으로 봅니다.

회의 때마다 지점장에게 다시 묻는 대신, EDB 배포 여부와 녹화·복습 제공 흐름을 한 기준으로 확인합니다.

권한 설계

대표, 지점장, 강사가 보는 화면이 달라집니다.

본사는 전체 운영 리스크를 보고, 지점장은 자기 지점의 실행을 보고, 강사는 수업에 필요한 범위에 집중하도록 나눕니다.

신규 지점 오픈

잘하던 지점의 수업 흐름을 복제합니다.

우수 강사의 판서와 진행 순서를 신규 지점 온보딩 자료로 옮겨, 확장이 매번 새로 만드는 일이 되지 않게 합니다.

The Standard

본사가 정한 기준은, 지점 교실에서 그대로 실행될 때만 기준입니다.

프랜차이즈와 다지점 학원은 이미 커리큘럼 문서와 강사 매뉴얼을 갖고 있습니다. 차이는 본사 기준이 파일함에 남느냐, 실제 수업 장면으로 내려가느냐입니다. ClassIn은 EDB 교안·판서·녹화·복습·LMS·관리자 데이터를 하나의 흐름으로 묶어, 기준이 지점 교실까지 같은 모양으로 도착하게 만듭니다.

PREP

수업 전 준비

본사가 이번 주 단원의 EDB 교안과 반 구성, 권한을 배포하면 모든 지점 강사가 같은 자료로 시작합니다.

LIVE

EDB·판서 수업

강사는 배포된 교안 위에 판서·이미지·풀이를 더하고, 그 흐름이 재사용 가능한 칠판 파일로 남습니다.

AFTER

녹화·복습

수업이 끝나면 녹화본이 결석 학생 보강과 복습 링크로 자동 이어져, 강사가 따로 편집하지 않습니다.

LMS

과제·시험

과제 제출, 시험, 피드백이 같은 반 단위로 묶여 수업 밖 학습 관리까지 한 줄로 연결됩니다.

ADMIN

관리자 데이터

권한 있는 관리자는 어느 지점이 교안을 썼고 복습을 제공했는지 같은 기준으로 확인합니다.

신규 지점 오픈 2주 차

강사 한 명이 본사 EDB 교안 대신 예전 학원에서 쓰던 자기 PDF로 수업을 시작합니다. 본사 기준이 파일함에만 있었다면 이 이탈은 한 달 뒤 학부모가 “옆 지점이랑 진도가 다르다”고 물을 때 드러납니다. ClassIn에서는 배포된 교안이 그 반에서 열렸는지, 녹화·복습이 제공됐는지가 관리자 화면에 비어 있는 칸으로 먼저 보이고, 운영팀은 2주 차에 강사를 따로 코칭합니다. 기준이 ‘공지’가 아니라 ‘수업 흐름’으로 내려가면, 이탈은 사고가 되기 전에 운영 항목이 됩니다.

HQ Control

본사 기준을 수업 현장까지 전달

표준 교안과 수업 흐름을 지점별 재해석에 맡기지 않고, 수업 전 준비부터 복습 제공까지 같은 구조로 유지합니다.

Brand Asset

우수 강사의 노하우를 기관 자산화

판서, 이미지 배치, 문제 풀이 순서를 EDB와 녹화로 남겨 강사 교체와 신규 지점 온보딩에 재사용합니다.

Visibility

늦은 보고가 아니라 운영 가시성

수업 진행, 녹화·복습 제공, 특이사항을 권한 있는 관리자가 같은 기준으로 확인하게 만듭니다. 늦게 알면 커지는 문제를 먼저 발견합니다.

Pilot

90일 파일럿은 확장 전 리허설

대표 지점·과목·강사군으로 30일 수업 흐름, 60일 권한·복습, 90일 본사 리포트 기준을 검증해 전면 도입 리스크를 줄입니다.

Visibility & Control

본사는 전체를 보고, 지점장은 자기 지점을, 강사는 자기 수업을 봅니다.

같은 시스템을 쓰더라도 보는 정보와 실행 권한은 역할마다 달라야 합니다. 권한이 흐릿하면 데이터도 리스크가 됩니다. ClassIn은 본사·운영팀·지점장·강사·보조의 가시 범위와 권한을 한 장의 매트릭스로 분리합니다.

지점장이 보는 것

분당 지점장은 분당 캠퍼스의 반·강사·복습 제공 상태까지 봅니다. 옆 지점의 매출이나 다른 지점 강사의 수업 기록은 화면에 아예 나타나지 않습니다. 자기 지점을 책임지는 데 필요한 범위만 열려 있어, 권한을 ‘믿고 맡기는’ 대신 ‘구조로 닫습니다’.

강사가 못 보는 것

강사는 자기 반 수업과 자기 녹화·복습만 다루고, 다른 강사의 학생 명단이나 본사 교안 ‘편집’ 권한은 갖지 못합니다. 좋은 판서를 남길 수는 있어도 본사 기준을 바꿀 수는 없습니다. 그래서 강사가 바뀌어도 학부모가 보던 개인정보와 운영 책임은 흐릿해지지 않습니다.

본사만 할 수 있는 것

EDB 교안 편집과 권한 부여는 본사·운영팀에만 열립니다. 신규 지점 계정을 만들고, 어느 역할이 무엇을 보는지 정하는 일은 위에서 한 번 설계하면 모든 지점에 같은 모양으로 적용됩니다. 권한이 곧 운영 기준이 되는 지점입니다.

Boardroom Evidence

늦게 아는 대신, 회의에서 바로 확인합니다.

같은 본사 기준도 지점에서 실행되는 방식은 달라집니다. 임원 회의와 운영 회의에서 바로 꺼낼 수 있도록, 자료가 지점 운영으로 남는지 아니면 파일과 공지로 끝나는지 같은 장면에서 대비합니다.

본사가 실제로 보는 화면

월간 운영회의 하루 전, 본사는 이 한 화면에서 지점을 봅니다.

본사 대시보드는 지점별로 EDB 교안 배포와 녹화·복습 제공이 정상인지 한 줄씩 보여줍니다. 목동 본원과 대치 캠퍼스는 정상 상태로 표시되고, 분당 캠퍼스만 복습 영상 제공이 지연돼 노란 예외로 올라옵니다.

예전 같으면 학부모 문의가 들어오고 나서야 알았을 한 건이, 월간 회의 자료를 만들기 전에 먼저 눈에 띕니다. 운영팀은 회의에서 “분당, 지난주 복습 왜 늦었나요”를 따로 묻지 않고, 같은 화면을 보며 바로 처리 상태를 확인합니다.

지금 — 흩어짐

  • 본사 기준은 있지만 실제 수업 자료는 지점·강사마다 흩어짐
  • 강사 교체 때 수업 노하우와 판서 흐름이 사라짐
  • 권한이 섞여 개인정보와 운영 책임이 흐릿해짐
  • 지점 리스크를 주간 보고나 학부모 문의 뒤에 알게 됨

ClassIn — 한 화면

  • 대표 수업 기록과 교안 흐름을 신규 강사가 이어받음
  • 역할별 접근 범위와 확인 책임을 나눠 설계함

각자의 관점

같은 시스템이어도 본사는 기준과 데이터를, 운영팀은 예외를, 지점장은 실행 부담 완화를, 강사는 재사용 가능한 수업 흐름을 봅니다.

본사 대표·임원

확장 속도보다 브랜드 편차를 줄이는 구조

지점이 늘어도 수업 기준과 학부모 경험이 본사 언어로 남도록, 지점 수업을 본사 운영 기준 안으로 다시 모읍니다.

교육운영팀

보고 전에 예외를 찾는 운영 가시성

지점장

강사 온보딩, 자료 전달, 보강 안내가 지점장의 기억과 메신저에만 남지 않도록 흐름을 시스템화합니다.

강사

좋은 판서와 활동 순서가 다음 반, 다음 강사, 다음 지점으로 이어지는 수업 자산이 됩니다.

FAQ

다지점 도입 전에 가장 많이 걸리는 질문

기존 자료 전환, 권한 설계, 지점별 단계 도입, 데이터 확인 범위처럼 본사 회의에서 막히는 질문을 먼저 답합니다.

본사는 지점별 수업을 어디까지 확인할 수 있나요?

관리자 콘솔과 권한 기준 안에서 수업 진행, 녹화·복습 제공, 과제·시험 흐름, 특이사항을 확인하는 방향으로 설계합니다. 실제 권한 범위는 계정과 계약 조건을 기준으로 상담에서 확인합니다.

기존 CRM, 결제, 출입 출석 시스템도 모두 대체하나요?

대체한다고 말하지 않습니다. ClassIn은 수업 운영 데이터와 학습 흐름을 중심으로 보고, 결제·정산·오프라인 출입 출석은 외부 시스템 또는 연동 검토 범위로 분리합니다.

다지점 전체 도입은 얼마나 걸리나요?

기본 수업은 빠르게 시작할 수 있지만, 대형 조직은 대표 지점 파일럿, 권한 설계, 강사 온보딩을 거쳐 30/60/90일 기준으로 확장 판단을 권장합니다.

본사와 지점장의 권한을 다르게 나눌 수 있나요?

도입 상담에서는 본사, 지역 관리자, 지점장, 강사, 보조가 어떤 정보를 봐야 하는지 역할별로 분리합니다. 실제 범위는 계정 구조와 계약 조건에 맞춰 확인합니다.

지점별 운영 편차를 어떻게 발견하나요?

녹화 제공, 복습 안내, 과제·시험 흐름, 수업 특이사항처럼 반복적으로 확인할 항목을 먼저 정합니다. 이후 대표 지점 파일럿에서 어떤 예외를 볼지 기준을 잡습니다.

보안과 개인정보는 어떻게 다루나요?

수업 기록, 녹화, 계정 권한, 관리자 접근 범위를 먼저 확인합니다. 서버·스토리지·개인정보 처리 세부는 공개 페이지에서 단정하지 않고 계약과 운영 조건에 맞춰 검토합니다.
