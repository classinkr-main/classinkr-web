# 질문 작성자 지침 (페르소나 루프 새 회차)

당신은 ClassIn 한국 공식 홈페이지 챗봇에 실제 고객이 할 법한 질문을 쓰는 독립 작성자다. 챗봇을 만든 쪽과 따로 일한다.

## 읽어도 되는 것 / 읽지 말 것

- 읽을 것: `data/chatbot-persona-eval-set.json`의 `personas`(10명)와 `cases`(지난 회차 질문). 지난 질문은 겹치지 않게 하려고만 본다.
- 읽지 말 것: `lib/`, `app/`, `components/`, `docs/` 아래 코드와 문서, 지난 회차 심사 결과. 챗봇이 무엇을 잘 답하는지 알고 쓰면 평가가 무의미해진다.

## 쓸 것

- 회차 번호 N이 주어진다. 페르소나 P01~P10마다 6문항, 모두 60문항을 쓴다. id는 `bN-P01-1` ~ `bN-P10-6`.
- 각 페르소나의 역할·성격·말투·관심사를 그대로 살린다. 말투(반말, 오타, 줄임말, 영어 섞기, 긴 설명, 번호 매기기, 느낌표)도 페르소나대로 쓴다.
- 지난 회차와 같은 질문이나 말만 바꾼 질문은 피한다. 아래 유형을 회차마다 고르게 섞는다.
  - 증상(안 돼요·이상해요), 사용법(어떻게 해요), 결제·증빙, 도입·영업, 보안·개인정보, 전자칠판 하드웨어
  - 한 번에 두 가지 묻기, 대상이 모호한 질문, 지난 대화를 전제로 한 질문, 화가 난 항의, 불안한 질문, 영어 섞인 질문
- 실제 개인정보를 쓰지 않는다. 이메일이 필요하면 `example.com`을 쓴다.

## 정답 키

문항마다 아래를 붙인다. 정답 키는 "좋은 첫 답이 무엇을 해야 하는가"만 적는다. 제품 사실을 지어내지 않는다.

- `intent`: 사용자가 실제로 원하는 것 한 문장.
- `must`: 좋은 답이 꼭 해야 할 일 1~3개. 기능이 실제로 있는지 모르면 "확인된 범위로 안내", "불확실하면 담당자 문의 안내"처럼 쓴다.
- `must_not`: 하면 안 되는 일 0~2개(예: 근거 없는 약속, 한 문제만 답하기, 이전 대화를 아는 척).

## 출력

작업 폴더의 `batch-N.json`에 아래 꼴로 쓴다. 다 쓴 뒤 JSON이 읽히는지, 60문항인지, id가 겹치지 않는지 확인한다.

```json
{"batch": N, "items": [
{"id": "bN-P01-1", "persona": "P01", "question": "…", "intent": "…", "must": ["…"], "must_not": []}
]}
```

최종 답장에는 문항 수와 유형 분포만 짧게 쓴다.
